26.04.1 LTS 的隔离桌面客机验收。24.04 分别运行 GNOME 46 的 Xorg 与 Wayland
会话，26.04 运行 GNOME 50.1 Wayland。本文记录受控接收窗口和合成服务的结果。

## 启动、页面与包加载

- Ubuntu 24.04 的 Xorg 客机缺少 `libfuse2t64`，实际 AppImage 通过
  `APPIMAGE_EXTRACT_AND_RUN=1` 启动，平台为 Qt XCB。后端夹具从同 SHA 的解包
  运行时导入，记录模块来源及哈希。`provider-ui.json` 同时核对 94 个冻结应用文件、
  3,707 个普通文件、1,048 个符号链接及两份 WebSocket 授权文本。该客机的 Wayland
  补验也使用此包的解包运行时。
- Ubuntu 26.04 实际 AppImage 使用 FUSE 和 Qt Wayland。客机 `package-audit.json`
  从 FUSE 挂载复核 94 个源码文件、3,707 个普通文件和 1,048 个链接，确认没有
  源码覆盖。主窗口及输入、协议夹具的挂载信息均绑定同一 AppImage 和清单摘要。
- 两个系统均用独立配置打开实际主窗口。主 Agent 目视检查概览、模型配置、润色
  风格、设置和帮助共五页，核对版本与导航。两套 `gui/result.json` 记录正常退出
  为 0、通过进程间请求显示与退出、退出后的录音切换／取消／退出命令未重新启动
  应用且配置不变。隔离的损坏配置保留原字节，应用报告错误并退出 1。
  私有桌面总线的 Portal 告警保留在原日志中，此项覆盖应用生命周期。
- 宿主独立以同 SHA 执行 FUSE 挂载，`AppRun --help` 退出 0，核对 0.17.0 和挂载
  内模块来源。第一次立即检查卸载的断言失败，确认挂载已清理后重跑，轮询在 51 ms
  内观察到卸载。宿主记录见 `/tmp/inkecho-v0170-fuse-review-a5z5e830/result.json`。

## Ubuntu 24.04 GNOME 46 Xorg

`stock-ibus-active-auto.json` 使用真实系统 IBus 的 libpinyin 和聚焦的 GTK3
输入框，加载系统 `im-ibus.so`。默认 `auto` 选择 XTest 模拟键盘。单字「测」和混合
文本 `甲A🙂乙Ω` 均精确接收。GTK 对混合文本分别记录 `甲`、`甲A`、`甲A🙂`、`甲A🙂乙`、
`甲A🙂乙Ω` 五次 `changed`，没有合并为一次变更。取消样本只收到「甲」。三个样本
的既有预编辑「你」均保留，之后用空格正常提交为「你」。另一个样本在「甲」已进入
窗口 A 后实际切到 B，B 收到 `A🙂乙Ω`，映射前后摘要一致，输出作用域完成清理。
此结果覆盖该 libpinyin 和 GTK 组合；免扩展 stock IBus 直接提交仍未交付。

`fcitx-package.json` 使用隔离的系统 Fcitx5 5.1.7。实际 XTest 点击一次
「配置 Fcitx5 输入桥」，成功发布并刷新，服务 owner、PID 和启动时间不变。
聚焦从 A 移至 B 后开始发送，A 为空，B 精确收到 `甲A🙂乙Ω`。第二次发送接受一个
码点「丙」后取消，观察期没有迟到文本，能力标记与桥接会话已清理。接收窗口绘制提示
等待上限默认 40 ms，在真实设置控件改为 80 ms 后重新加载仍为 80 ms。此上限仅在
支持绘制提示的 X11 接收目标生效，不提供目标文字已显示的确认。

## Ubuntu 24.04 与 26.04 GNOME Wayland IBus

两个真实会话均由 `loginctl` 确认原生 Wayland。实际显示 Qt Wayland 设置页，默认
`auto`，打开页面不安装扩展或改变设置。发送一组 Qt 鼠标按下与释放事件点击可见的
「配置 IBus 输入桥」。首次各安装七份经校验的内置文件。当前 Shell 尚未识别新扩展，
界面提示重新登录后再点同一按钮。重新登录后再次点击，真实状态为 `enabled`，Shell
探针返回 `owner-loss-focus-recheck-v2`。扩展目录及七份文件的 inode、修改时间、
权限与摘要保持一致，系统输入源也保持原值。两次操作通过 `configure-initial.json`
与 `configure-retry.json` 记录。

两个系统均以原生 Wayland GTK 接收窗口验证默认 `auto`。虽然任务准备阶段建立键盘
候选，发送阶段真实选择 `inkecho.platform.ibus_owned`。A 先收到 `甲A🙂`，随后 B
实际获得焦点，收到 `乙Ω`。GTK 分别记录三个与两个文字变化。路由记录
`ibus_delivery_unknown` 和五次已确认派发，实际文字由接收窗口独立观察。接着在 B
收到一个码点「丙」后取消，状态为 `ibus_cancelled`，确认派发次数为 1，B 的最终
文字为 `乙Ω丙`。会话关闭，路由解除绑定，接收进程退出。此样本在两段发送之间切焦，
覆盖同一任务中后续文字跟随焦点，切焦时没有同时测试活动的 Wayland IBus 组词。

26.04 另用相同 FUSE 运行时显示 Siri 样式悬浮层和合成实时文字。悬浮层确认显示
并暴露，独立原生 GTK 接收窗口的 12 次新鲜观测均为激活且聚焦。取消后悬浮层内容
清空并隐藏，悬浮层宿主退出 0，接收进程退出。见 `overlay-native.json`。24.04
此次未执行对应悬浮层焦点检查。

## Ubuntu 26.04 GNOME Wayland Fcitx5

`fcitx-native.json` 记录独立系统 Fcitx5 5.1.19，实际 Qt Wayland 设置页点击一次
「配置 Fcitx5 输入桥」。配置前检查报告运行未确认，刷新后确认真实服务接口可用，
服务 owner、PID 和启动时间一致，私有总线上没有 IBus owner。真实激活、聚焦的原生
Wayland GTK 窗口加载 `im-fcitx5.so`，通过协议 4 精确接收 `甲A🙂乙Ω`，对应两次
`changed`。取消样本再收到一个码点「丙」，返回 `cancelled` 和接受次数 1，最终
`甲A🙂乙Ω丙`。第一个运行因夹具作用域检查退出 1，发生于桥接操作前，原始
`first-fcitx.log` 保留。修正私有会话继承的临时路径后原包复验退出 0。
两套 Fcitx5 检查均显式选择该方式。

## 双系统本地协议检查

两个系统均使用打包的 Python 和应用模块连接回环 TLS 服务，配置、凭据、输入数据均
为隔离合成样本。真实模型配置控件通过固定模型列表及过滤检查，云端请求数为零。

| 协议 | 实际结果 |
| --- | --- |
| HTTPS ASR | 合成 WAV 在请求中的字节完全一致，返回预期转写，无剩余服务处理任务。 |
| Qwen WSS，手动切段 | 正常请求按 `session.update`、三次 append、显式 commit、finish 的顺序发送，PCM 分块为 3,200、3,200、14 字节。停止前有预览，finish 确认前无输出，最终文本仅输出一次。停止前取消的另一次连接无 commit、finish 或输出，两次资源均清理。 |
| Qwen WSS，服务端 VAD | 正常与取消共两次连接，无手动 commit，停止前有预览、无提前输出，正常结果仅提交一次，取消无输出，资源已清理。 |
| HTTPS SSE 润色 | 恰好一次请求，校验完整请求内容。`[DONE]` 前分两次收到 `本地甲` 和 `A🙂Ω。`，完成前保持等待，合并结果精确，token 用量为 7、4、11，无剩余服务处理任务。 |

## 复现和范围

两套原始客机目录是 `/tmp/inkecho-v017-noble.VoNvWl/` 和
`/tmp/inkecho-release-v0170-wayland26.S6UidB/`。其 `input/` 保留运行夹具，
`output/` 保留 JSON、截图、退出记录及失败日志，两套目录各有 `REPORT.md`。
它们是临时审计材料。

- 24.04 在一次性客机将输入挂载到 `/work`，证据写入 `/mnt/output`。
  按 `guest-setup.sh` 和 `INKECHO_PACKAGE_GATE=1` 的守卫启动夹具。在 Xorg 通过
  `dbus-run-session` 分别运行 `run-desktop.sh`、`run-protocols.sh`、
  `run-fcitx.sh`。先执行 `prepare-preedit.sh`、重新登录并确认实际 libpinyin，
  再运行 `run-preedit.sh`。手动 Session 和 SSE 运行 `run-manual-session.sh`、
  `run-sse.sh`。用 `restore-xorg.sh` 恢复 Xorg 输入源后，执行 `setup-wayland.sh`
  并在 Wayland 会话运行 `wayland-desktop-state.py stage`。运行 `launch-wayland.py`
  的 `initial`，重新登录，再运行 `retry` 和 `output`。
- 26.04 在一次性客机挂载 `/mnt/input` 与 `/mnt/output`。使用
  `desktop-state.py stage` 隔离桌面状态，重新登录。以测试用户运行
  `run-gate.py initial`、`desktop`，重新登录后运行 `retry`、`protocols`、
  `fcitx`、`supplemental` 和 `overlay`。对应记录核对成品摘要和 FUSE 来源。
- 两套协议复验使用相同的手动 Qwen 与 SSE 夹具，SHA-256 分别为
  `fcb935e2123df34d9d3fe877e2a96b91742aff077290dae04ef33258593281f1` 和
  `9bbb6de10aaeaf38b57f51ccc49c7194fbf16035490ea87fcff67e6a43e608a1`。
  24.04 结果为 `qwen-manual-session.json`、`polish-sse.json`，26.04 为
  `qwen-manual-shared.json`、`sse-polish.json`。HTTP 与 VAD 同名文件在两套
