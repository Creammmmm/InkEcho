# 故障排查

凭据文件说明针对当前源码修订；已发布版本的行为以对应验收报告为准。以下输入兼容性细节保留自 [a14 历史验证](a14-dual-ubuntu-validation.md)，新版本实际环境见 [v0.3.0 双系统报告](v0.3.0-dual-ubuntu-validation.md)。不得据历史记录推断当前用户的快捷键或配置。

## 可以打开设置，但无法输入文字

先查看「输入与兼容性」。a14 已实测 Ubuntu 24.04.5 GNOME 46 Xorg，以及 Ubuntu 26.04.1 GNOME 50.1 Wayland 中的自有 Chrome XWayland 和原生 Wayland 字段。原生路线只接受 BMP 文本，emoji 等非 BMP 字符会提前报 `unsupported_text`；X11/XWayland 样本另含 emoji。GNOME 46 安装缺少当前原生后端所需接口，Xorg 通过不能推定其原生 Wayland 可用。桌面会话名称不能代替目标应用协议；其他应用仍需分别验证。历史 GTK/VTE 检查也不能外推任意终端或 Codex 编辑器。

录音开始时不需要先选择文本框。输出时请把光标放在希望接收文字的兼容应用中；若该应用不接受模拟按键，换模型无法解决。出现「按键已发送」只确认发送完成，不证明目标应用已经接收。失败不会回退到剪贴板或系统输入法。

## 显示「正在聆听」但没有文字

「正在聆听」表示仍在录音，需要再按一次已配置的快捷键结束录音并提交转写；说完停顿不会自动提交，达到最长录音时限则丢弃本次录音并提示超时。出现「正在转写」或「正在润色」后仍可切换窗口，文字输出时会进入当时的光标位置；输出中切换窗口也会改变后续字符的接收位置。失败或主动取消后，在「概览」查看具体错误，再按提示处理麦克风、服务或输入兼容性问题。

## 快捷键没有反应

保存快捷键文本与向桌面注册快捷键是两个操作。GNOME 用户在录音设置中主动启用，根据冲突提示调整组合键。F13/F14 的设置可保存，但实际键盘是否发送对应按键仍需检查；不要把合成按键实验理解成所有物理键盘已验证。其他桌面可手动绑定应用的 `--toggle` 命令，见[快捷键说明](hotkeys.md)。应用不会自动改变其他软件的绑定。

## 麦克风不可用、录音为空

先在系统声音设置中确认输入设备，再用应用的三秒麦克风测试。检查静音、设备拔出、权限、PipeWire/PulseAudio 服务和采样率。更换设备或选择默认设备后重新测试。录音只保留在内存；达到时长限制、取消或退出会结束采集。

## 密钥无法保存或读取

当前源码按用户要求将全部认证字段明文保存到当前配置目录的credentials.json，不再依赖系统密钥环。旧引用不会读取或迁移旧密钥，需要重新填写并保存。检查专用目录/文件权限0700/0600、owner与JSON格式，不用符号链接；错误不会自动覆盖坏文件。不要把密钥写入provider参数、日志或源码。删除供应商记录不会自动删除凭据，请使用明确的密钥删除操作。历史AppImage仍按其当时方式运行，需核对实际版本。

## 服务测试失败、模型列表为空

检查供应商区域、HTTPS 地址、账户权限、密钥以及所选模型实际支持的接口。模型列表包含某个 ID 不代表它支持音频转写或文本润色；分别执行能力测试。支持手动填写模型。转录和润色配置彼此独立；网络超时可分别调整。真实云端调用可能收费。

若 `qwen3-asr-flash-realtime` 显示不支持，先确认新包有「转写方式」选择器。旧 a9 没有实时接入，启动新文件也可能只唤起旧实例；先正常退出旧进程再启动 a14。明确选择「边录边识别 · Qwen 实时 WebSocket」、实时模型和 16 kHz 并保存；普通 `qwen3-asr-flash` 与 `{}` 仍是 HTTP。红色表示与当前方式不匹配，不是 Ubuntu 26.04 禁用该模型。a14 已在本机完成一次官方实时公开音频能力请求，详见[报告](a14-dual-ubuntu-validation.md)，不代表任意账号、区域或网关均可用。

自定义实时服务必须提供实际 `wss://` 地址；实时参数仅接受 `asr_protocol` 和可选 `realtime_url`。切换方式保留原 JSON，需手动移除 HTTP 专用字段；损坏 JSON、缺地址和错误参数应按配置提示修复，不要清空全部配置或重设密钥。切换供应商/URL 后旧模型列表或成功提示可能保留，这是已知存量显示问题；重新发现，不把旧列表当新服务验证。

尚未尝试键盘投递时，润色失败可按保存的偏好回退识别原文；已进入投递后失败会停止剩余文字，不会整段回放。空结果、鉴权失败、限流及错误响应应分别提示，取消后的迟到响应不会重新触发输入。

## 配置损坏或升级后无法启动

错误提示会给出配置目录。先备份目录，再检查指出的 JSON；不要直接删除整个目录。未知版本和损坏文件不会被默认配置覆盖。旧版迁移会保留原始备份。配置布局与恢复边界见[配置说明](configuration.md)。

## 关闭窗口后找不到程序

有托盘时可通过托盘打开设置或退出。快捷键用于开始录音、再次按下结束并提交，不用于取消。主动取消可使用系统通知的「取消」、托盘菜单或概览的「取消任务」；没有托盘时，重新执行应用命令会通知已有实例打开设置。`--cancel` 取消当前任务，`--quit` 正常退出。同一配置目录只允许一个实例；另一个实例不会重复注册快捷键。

## AppImage、启动器或图标失效

确认 AppImage 有执行权限。宿主机没有可用 FUSE 时，可参照[打包说明](packaging.md)使用提取运行方式。移动 AppImage 后在「关于与桌面集成」点击「修复路径」。桌面集成与自启动需主动开启；清理集成只移除应用拥有的入口，不删除配置或密钥。

## 报告问题

提供应用版本、发行版、桌面环境、X11/Wayland、目标应用版本、操作步骤与可见错误。诊断页可查看固定错误代码并清除日志。不要附上 API Key、私人录音或转写正文。目前兼容性与已知缺口见[验收清单](acceptance-checklist.md)；Ubuntu 24.04 容器启动证明不能替代真实桌面输入、音频与快捷键测试。
