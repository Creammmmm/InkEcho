# 接收窗口绘制提示等待上限：隔离候选设计

2026-10-29。此改动仅为隔离源码候选；未构建 AppImage、未替换稳定入口、
未进行新的真实桌面或双系统实际包验收。它实现有能力窗口的可配置等待，
不宣称跨应用帧确认、目标已处理字符或已显示文字。

## 可配置的 40 毫秒行为

新增 `receiver_feedback_wait_ms`，默认 40，允许 20–250 毫秒。它是等待
接收窗口**绘制提示**的上限：在当前 X11 DRAW 调度窗口已满时，等待新的
合格提示或该上限；有提示可提前继续，超时只结束调度等待，不代表收到、
处理或显示。有限窗口仍为现有自适应的 1–4 个字符；不是每字固定休眠。

此上限从调度器开始等待时计算，受任务截止限制；线程调度抖动可能令实际
墙钟耗时略超设定，不能作为实时系统保证。键盘映射、按下和释放的协议
安全等待独立保留，不在该预算中，整次输入不会被限制为 40 毫秒。

保留原有配置及取值：`x11_mapping_wait_ms` 仍只保护实际映射变更；
`x11_feedback_timeout_ms` 仍是动态估算的基准。现有动态值最终受新上限
约束，因此设置页将旧“绘制反馈超时下限”准确改称“自适应反馈基准”。
旧字段不删除、不改写，也不把旧映射值迁移为接收窗口等待。旧配置缺少
新字段时读默认 40，读取不重写文件。保存有界整数，任务开始形成快照，
本任务期间修改设置仅影响下一任务；Hybrid 后端切换沿用任务快照。

## 实际能力与提示

只有原生 X11 目标检测到现有 XSync/Damage 绘制提示时使用此预算。它们
是窗口活动的弱提示，动画也可能产生；没有字符序号或目标呈现收据。
保持现有去重、窗口代际与焦点失效逻辑，不读取接收文字、不修改其计数器。

设置页运行时显示以下状态；不在输出前捕获目标，不因查看设置而探测目标：

- 未输出或尚未检测：输出时检测当前接收窗口。
- 实际 DRAW 观察可用：可观察窗口绘制提示，不确认接收或显示。
- 当前键盘目标无反馈：明确等待设置不生效，保留已有安全调度。
- 原生 Wayland / Fcitx5 / IBus：明确当前方式无绘制反馈，该预算不生效。

XWayland 的现有观察器默认拒绝启用 DRAW，候选不放开该限制。输入法提交
回执、Wayland 输入请求回复、自身窗口帧回调和全局绘制 tick 均不会伪装为
接收窗口帧信号。NONE 的既有 20ms 复用等待、INPUT 的 RTT 调度不变。

切焦只使旧提示失效；后续未发送字符仍跟随当前光标，不锁定录音开始位置。
等待前后及实际发送前继续检查取消、替代与截止。取消唤醒已有等待；不延长
任务、不补发或重放已发送/状态不明字符，正常清理仍释放资源。

这些是离线/Qt offscreen 检查；不是实际显示流畅度或桌面帧时序证明。

后续必须在自有目标记录 input/changed、draw/after-paint 与实际观察器
事件，区分无提示、提示提前、目标暂停、无关动画、切焦/取消与40/80配置。
只有实际测得的系统/会话/目标可声称有该能力；不能把此窄实现写成所有
输出方式都恢复了帧同步。真正逐字呈现确认还需目标自愿配合或可信桌面
协议，当前不存在。集成、版本提交和新 AppImage 须单独审核；同一新 SHA
在 Ubuntu24 与26通过必需实际包验收前，仍只能称候选，不得发布或部署。
