# Ubuntu 24 Xorg：活动拼音下 XSendEvent 对照实验

2026-10-31，在隔离 Ubuntu 24.04 GNOME 客机中，logind 确认 seat0 用户会话 active/x11，Xorg 存在；实际旧 0.15.0 AppImage SHA-256 `94a73232871abaca8c91fb5f58e52059be404f10605955562d39bf31ec64354a` 的 `keyboard.py` SHA-256 `67000fe0de6592017796ebd07cb47dc0e187a1d24457ade68cfe4243cde5920e` 与当前源码相同。本测试直接实例化 `KeyboardInput()`，使用默认 `_XDriver` 的 XSendEvent，不经过自动路由或 Session；产品 Xorg 工厂实际使用 `_XTestDriver`，因此本样本不代表产品自动回退。

自建 GTK3 X11 输入框明确选择 IBus；在活动窗口和控件焦点均为 true 时，用合成键输入 ni，等待 0.8 秒后记录真实 libpinyin 预编辑“你”、正文为空。默认 XSendEvent 驱动的 `KeyboardInput` 在单个输出会话发送“测”并返回 1；0.8 秒后目标仍有焦点、正文“测”、预编辑仍为“你”。再合成空格后正文为“测你”、预编辑为空。一个 GTK 控件上的这个受控单字样本表明该次映射与按键没有丢失或提交原有拼音；不能外推到其他引擎、应用、Unicode 字符、焦点切换、取消或其他系统，不证明插件协议或自动回退安全。

首次容器启动因挂载源路径错误、QEMU 尚未启动而失败；修正后重试。客机第一次探针因未安装 libpinyin 而失败；在隔离客机安装六个已有离线包并重启 IBus 后，第二次由于引擎选择命令返回 1 而失败。实际 `ibus engine libpinyin` 返回 1 时查询可显示已切换，因此后续根据查询结果判断。下一次样本在输入 ni 后过早取样，观察到预编辑从“年”变为“你”，不可归因于键盘输出；最终增加 0.8 秒等待后得到上述稳定样本。各失败和早期样本均保留在本地。

恢复过程记录六个新安装包移除，IBus 重新启动，活动引擎和源分别恢复为 `xkb:us::eng` 与 `[('xkb', 'us')]`；自建客户端退出并卸载 AppImage/共享目录。QEMU 与容器退出 0、无 OOM，停止快照完整解压校验通过。本实验不触碰宿主桌面、不读取剪贴板；原始日志和快照仅留本地，结果不构成双系统正式包验收。

测试结束时探针向自建 GTK 客户端发送 SIGTERM，客户端等待结果为 -15；这不是客户端自然退出 0。
