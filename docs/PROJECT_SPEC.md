# 桌面后台语音输入软件需求与实施文档

> 文档用途：作为 Codex 或其他开发 Agent 的项目总需求、架构约束和分阶段实施依据。
>
> 首期平台：Ubuntu 24.04 / 26.04（分别测试 Wayland 与 X11）。
>
> 技术栈：Python、PySide6、JSON、pytest；首期以 AppImage 分发。

## 2026-10-14 用户修订：输出到当前光标

用户明确修改了输入语义：开始录音与当前位置、窗口和焦点无关；录音、转写、润色期间允许自由切换窗口或光标，不因此取消任务。结果像模拟键盘输入一样发送到**输出当时**的光标位置。输出进行中切换窗口，后续字符可以进入新的焦点，不绑定录音开始时或输出开始时的控件。

本修订替代此前“开始时捕获目标、失焦即取消”的要求。不使用剪贴板或系统输入法；主动取消、过期或被替代的任务仍必须停止未发送的文字。焦点变化本身不表示任务过期。已发送的输入无法撤回，取消后不得发送剩余正文，也不得自动重放投递状态不明确的正文。

历史验收报告保留其当时的行为和结果，不能作为新语义已支持的证明。新行为须按第 12、21、24 节重新验证，记录在[当前光标输入验收](current-cursor-input-validation.md)。

## 1. 项目概述

开发一款**后台常驻的桌面语音输入工具**，而不是系统输入法。用户在任意应用中按下可配置的全局快捷键开始录音，再按一次结束录音。程序调用云端语音识别服务获得文字，可选调用云端大语言模型按照用户选择的 Prompt 模板润色，最后按模拟键盘语义将文字输入到输出当时的光标位置。

核心原则：**不使用剪贴板或系统输入法**，不修改剪贴板内容，也不在直接输入失败时回退为剪贴板粘贴或输入法提交。

## 2. 第一阶段范围与非目标

### 2.1 必须实现

- Linux 后台常驻程序、系统托盘及替代入口。
- 全局快捷键，支持普通组合键及 F13/F14 等扩展键。
- 麦克风录音、云端语音转录、可选云端文字润色。
- 按模拟键盘语义向输出当时的光标位置输入 Unicode 文本（包括中文），不依赖剪贴板或系统输入法。
- 供应商、模型、Prompt、快捷键及提示样式的图形化配置。
- 使用统计、错误提示、日志、基础安全与配置迁移。
- AppImage 打包及桌面集成。

### 2.2 首期不实现

- Windows/macOS 正式支持，但架构必须预留适配接口。
- 本地 AI 模型推理。
- 多人协作、云端账户同步、音频长期存档。
- 将应用实现为系统级输入法。

## 3. 核心技术架构

建议使用 Python + PySide6，模块之间通过清晰接口、信号或事件通信，UI 不直接耦合具体供应商协议。

主要模块：

1. `app`：应用启动、生命周期、依赖注入。
2. `hotkeys`：全局快捷键注册、冲突检测、后端适配。
3. `audio`：设备选择、录音、音频编码与临时文件清理。
4. `transcription`：云端语音识别统一接口及供应商适配器。
5. `polishing`：云端语言模型润色统一接口。
6. `providers`：供应商配置、模型发现、能力验证。
7. `prompts`：内置及用户自定义 Prompt 管理。
8. `injection`：当前光标的键盘输入传输、Unicode 兼容性、取消及过期任务检查，不使用剪贴板或系统输入法。
9. `overlay`：不抢焦点的悬浮状态动画。
10. `statistics`：本地统计、Token 计量及估算标记。
11. `config`：JSON 配置、版本迁移、系统凭据存储。
12. `packaging`：AppImage、桌面入口、图标、自启动集成。

## 4. 全局快捷键

- 用户可配置启动/停止录音的快捷键。
- 支持 Ctrl/Alt/Shift/Super 组合键以及 F13、F14 等扩展功能键。
- 首期需分别验证 Ubuntu 24.04/26.04 的 Wayland 与 X11 环境。
- 检测注册失败、冲突、权限不足及桌面环境限制，并显示明确错误。
- 快捷键事件应去抖动，避免重复触发；同一时刻只允许一个活动录音任务。
- Wayland 下不得假定 X11 的全局键盘钩子可用；按实际桌面环境选择可行后端。

## 5. 音频采集

- 支持选择系统可用的输入设备及默认麦克风。
- 快捷键第一次触发开始录音，第二次触发结束并提交识别。开始录音不要求当前位置存在可编辑控件，也不预先捕获输入目标。
- 显示录音状态、时长及基础音量波形。
- 检查设备不可用、无权限、录音中断、空录音、超时等情况。
- 按供应商需要转换采样率、声道、格式及编码。
- 默认不永久保存原始音频；临时数据用完后清理。

## 6. 云端语音转录

- 使用可扩展的转录接口，优先适配阿里云通义千问相关语音识别服务。
- 允许配置 API Key、Base URL、模型和供应商专有参数。
- 支持合理的超时、取消、重试与错误分类；避免无界重试。
- 转录结果为空时按失败处理，不向目标窗口注入空内容。
- 不将模型 ID 写死在业务逻辑中。
- 注意供应商的实际语音接口可能与普通文本 Chat Completions 接口不同，必须逐个验证。

## 7. 云端文本润色

- 识别完成后，可选将原文交给云端语言模型进行润色。
- 优先接入 DeepSeek；供应商配置与转录服务完全独立。
- 用户可选择 Prompt 模板，并按模板要求保留语义、纠正口语及标点。
- 可设置关闭润色、超时和失败回退策略。
- **默认润色失败时回退原始识别文本**；用户可以关闭该回退。
- 润色返回空内容视为失败。
- 避免不必要地上传敏感内容；界面应说明云端处理事实。

## 8. 供应商与模型管理

- 转录供应商与润色供应商分别管理和选择。
- 每个供应商可配置显示名称、类型、Base URL、凭据引用、模型及请求参数。
- 尽量通过供应商 API 动态获取模型列表；不支持列表接口时允许手动输入。
- **模型列表存在不等于模型具备所需能力**：需对转录/润色能力分别校验或做测试请求。
- 供应商适配器独立实现认证、请求格式、响应解析、错误处理和使用量解析。
- UI 仅调用统一接口，不包含某家供应商的特殊 HTTP 逻辑。
- 提供连接测试与明确的失败信息。

## 9. JSON 配置管理

- 使用版本化 JSON 配置，支持默认值、校验、原子写入和迁移。
- 普通应用配置与供应商配置、Prompt 模板分离。
- `providers/` 目录：每个供应商一个独立 JSON 文件。
- `prompts/` 目录：每个用户 Prompt 一个独立 JSON 文件。
- 不在普通 JSON 中保存明文 API Key；仅保存系统凭据服务中的引用标识。
- 用户配置放在符合 Linux XDG 规范的位置，不写入 AppImage 只读安装内容。
- 对损坏或版本不兼容配置给出可恢复的错误提示，避免直接覆盖用户数据。

## 10. API 凭据安全

- 优先通过系统密钥环或 Secret Service 等凭据服务保存 API Key。
- 不在日志、异常消息、界面调试输出中泄漏凭据。
- 允许用户更新、删除、测试凭据。
- 如系统凭据服务不可用，明确告知限制，不静默退化为明文保存。
- 对网络请求配置合理的 TLS 验证和超时。

## 11. Prompt 模板

- 提供至少一个内置的“忠实转写、适度润色”模板。
- 用户可选择、创建、复制、编辑和删除自定义模板。
- 内置模板资源不可被用户修改直接覆盖；编辑内置模板时自动另存为用户副本。
- 模板包含名称、说明、正文、版本/标识等必要字段。
- 支持预览或测试润色效果（在服务可用时）。
- 模板文件逐个保存为 JSON，便于备份和手动管理。

## 12. 无剪贴板文本直接输入（最高风险）

这是项目的**关键可行性门槛**，必须在阶段 0 优先验证。

- 不读取、覆盖或修改剪贴板；不得使用复制粘贴模拟实现，也不得使用系统输入法提交文字。
- 必须能向常见目标应用输入中文及其他 Unicode 字符。
- 至少验证浏览器文本框、终端、文本编辑器；分别测试 X11 和 Wayland。
- 不得将 `uinput` 视为天然支持直接输入 Unicode：它模拟按键事件，并不自动解决中文字符映射问题。
- 调查并实测桌面键盘输入协议或其他符合当前光标语义的传输路径、权限与 Unicode 兼容性；不得以系统输入法实现。向固定辅助功能对象投递的旧路径不能冒充当前光标语义。
- 若某种桌面环境或目标应用无法满足无剪贴板直接输入，应明确报告“不支持”及原因，**不得偷偷回退为剪贴板方案**。
- 开始录音不检查或绑定窗口、控件、光标；录音、转写和润色期间的焦点、光标或选择区变化不得取消任务。
- 输出按模拟键盘语义交给当时拥有焦点的接收方，不锁定旧窗口或辅助功能对象；输出期间切换窗口，后续字符允许进入新焦点。
- 每次异步恢复及发送步骤前核对活动任务 ID、epoch 和取消状态。主动取消、超时过期或被替代的任务即使响应晚到，也不得再发送正文；焦点变化不使任务过期。
- 取消时停止未发送文字并释放自身占用的按键与资源。已交给桌面的事件无法撤回；部分输出状态不明确时不得自动整段重试。
- 对传输不可用、权限拒绝或输出失败提供清晰提示及可恢复流程；不要把焦点切换本身报告为错误，也不得将无法确认的投递报告为成功。

## 13. 悬浮状态提示

- 在录音、转录、润色、注入、成功和失败状态提供视觉反馈。
- 默认使用简约波形风格，图标清晰美观。
- 尽量采用**无文字提示动画**，通过颜色、动效和图形表达状态。
- 动画样式、位置、透明度、显示时间等可配置。
- 悬浮窗不得抢占目标应用焦点，不应妨碍正常输入。
- 在 Wayland 和 X11 上分别验证置顶、透明、点击穿透与焦点行为。

## 14. 主窗口与配置界面

使用 PySide6 提供简洁的桌面管理界面，建议包含：

- 首页：当前状态、快捷键、启用的转录与润色模型。
- 录音设置：麦克风、音频参数及测试。
- 快捷键设置：录入、验证、冲突与权限提示。
- 转录服务：供应商、模型、API 配置与连接测试。
- 润色服务：独立供应商、模型、启停及失败回退策略。
- Prompt 管理：模板列表、编辑、复制、删除、预览。
- 输入与兼容性：当前光标输入后端、实测支持范围、权限与诊断。
- 外观与悬浮提示：动画样式及位置。
- 统计与日志：本地使用数据、错误诊断、隐私选项。
- 关于与桌面集成：版本、AppImage 集成、自启动与修复入口。

## 15. 使用统计与 Token

至少记录：

- 今日识别次数、成功次数与失败次数。
- 今日识别字符数或词数（标明计数口径）。
- 今日累计录音时长。
- 转录与润色服务调用次数、耗时。
- 润色输入/输出 Token、总 Token（供应商有返回时）。
- 无准确 Token 数据时可以估算，但必须标记为**估算**，不得冒充精确值。

默认不保存完整音频和转录/润色正文。统计持久化应考虑数据损坏恢复、隐私和清除功能。

## 16. 系统托盘与生命周期

- 默认在后台常驻，提供托盘菜单：打开设置、开始/停止录音、退出等。
- 关闭主窗口默认最小化或隐藏到托盘，行为可配置。
- 对不支持系统托盘的桌面环境提供替代入口，不让用户失去退出或打开设置的方法。
- 防止重复启动多个实例导致快捷键冲突。
- 正常退出时停止录音、取消网络任务、释放快捷键和清理临时资源。

## 17. 日志与错误处理

- 使用分级日志与适当轮转；默认不记录原始音频、完整识别正文、Prompt 中的用户敏感内容或 API Key。
- 区分麦克风、快捷键、网络、鉴权、模型能力、润色、输入权限、文本输出和桌面集成错误；正常焦点切换不构成错误。
- UI 显示用户可理解的简短信息，诊断日志保留技术细节但必须脱敏。
- 异步任务需正确处理取消、超时、重试与过期响应。

## 18. AppImage 打包与交付

- 首期优先交付 AppImage，不要求先提供 `.deb`。
- 处理 Python/PySide6、Qt 插件、图标和运行时依赖。
- 在目标 Ubuntu 版本的相对干净环境中验证，而非仅在开发机启动。
- 明确记录对桌面环境、系统服务、输入权限和音频服务的依赖。
- 具备可复现的构建脚本、版本信息及基础发布说明。

## 19. AppImage 桌面图标、启动器与自启动

重点避免“AppImage 可以运行，但应用菜单没有图标/入口”的常见问题。

- 随包提供规范的 `.desktop` 文件与多尺寸图标资源。
- 提供用户主动执行的桌面集成入口或首次运行引导。
- AppImage 路径变化后可检测并修复失效的启动器。
- 用户可主动开启/关闭开机自启动，默认不擅自开启。
- 卸载/清理桌面集成时不得误删用户配置和凭据。
- 对无法自动集成的环境提供明确的手动步骤。

## 20. 配置迁移与兼容

- 配置带有 `schema_version`。
- 新版本启动时先校验并按需迁移，保留备份或可恢复路径。
- 迁移逻辑需要自动化测试，避免升级后丢失供应商、Prompt 或快捷键设置。
- 平台相关设置不得污染跨平台的核心配置。

## 21. 任务状态机与并发约束

推荐状态：

`IDLE → RECORDING → TRANSCRIBING → [POLISHING] → INJECTING → SUCCEEDED`

异常路径：`FAILED` 或 `CANCELLED`，结束后回到 `IDLE`。

必须满足：

- 同一时刻最多一个活动录音任务。
- 每个任务拥有唯一 ID，所有异步回调必须核对当前任务 ID。
- 用户取消后，不论转录/润色服务何时返回，都不能继续注入。
- 录音、等待转写及润色期间的窗口或光标变化不取消任务；输出到当时的光标，输出中的焦点变化也不取消。
- 每个发送步骤仍检查任务 ID、epoch 和主动取消状态；不允许旧任务在新任务开始后继续输出。
- 润色失败按配置决定回退原文或失败终止。
- 任何阶段失败都应释放资源并恢复可再次录音的状态。

## 23. 跨平台设计原则

- 首期只实现 Linux，但通过接口抽象隔离全局快捷键、音频设备、当前光标键盘传输、凭据服务、系统托盘与自启动。
- Windows/macOS 适配器可以保留接口和空实现，不需要首期通过完整测试。
- 核心业务（任务状态机、供应商、Prompt、配置、统计）尽量不依赖 Linux 专有实现。

- 连续多次开始/结束录音，不发生重复触发或资源泄漏。
- 断网、超时、错误 Key、无权限、空结果、供应商异常均有可理解的反馈。
- 润色成功、润色失败回退和禁用回退三种路径正确。
- 没有可编辑目标也能开始录音；录音、转写、润色期间切换窗口或光标不取消，结果送到输出当时的光标而非旧目标。
- 输出中切换焦点，后续字符可进入新焦点；不得锁定此前捕获的控件。
- 主动取消、超时过期、旧任务被替代以及取消后的迟到响应均不再发送正文；覆盖部分输出取消、资源释放和歧义输出不重放。
- 中文、英文、标点、换行、混合 Unicode 文本的输入行为符合预期。
- Prompt 创建、编辑、复制、删除与内置模板保护有效。
- JSON 配置迁移、凭据读取、统计保存和数据清除可靠。
- AppImage 桌面图标、启动器、路径修复、自启动开关及清理行为正确。

## 28. 最终验收原则

软件的价值在于：用户按快捷键说话，云端识别并可选润色后，**不使用剪贴板或系统输入法地**将文字按键盘语义输入输出当时的光标位置，并在主动取消或任务过期后停止。

验收优先级依次为：

1. **文本输入的真实性与任务隔离**：不使用剪贴板或系统输入法，中文可输入，遵循输出当时的光标而不绑定旧窗口；取消或过期后不再发送正文。
2. **核心流程可靠性**：快捷键、录音、转录、润色、取消与错误恢复。
3. **Linux 兼容性可验证**：如实标明不同 Ubuntu、Wayland/X11 环境的支持范围。
4. **可配置与可扩展**：供应商、模型、Prompt、凭据和跨平台适配接口。
5. **桌面体验与交付**：悬浮动画、托盘、统计、AppImage 和桌面图标集成。
