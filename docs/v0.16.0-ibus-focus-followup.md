# v0.16.0 owned IBus focus follow-up

## Scope and artifact

These follow-up checks used the released 0.16.0 AppImage, SHA-256 `fa1bbfffc6480534b790bdf00e29ea45977f529ef398ceb94fa7f2830223c6bf`, in isolated Ubuntu 24.04.5 GNOME 46 and Ubuntu 26.04.1 GNOME 50 Wayland guests. They exercised actual mounted package modules with a synthetic producer and controlled Chrome receivers, not a physical microphone, physical shortcut or real cloud service. Read-only dispatch instrumentation identified `inkecho.platform.ibus_owned` as the actual selected backend. The final route field was null after session close and is not route evidence. No clipboard was used.

## Results

- On both Ubuntu versions, a native Wayland Chrome page with two controlled input fields moved focus from A to B after A observed the first character. The receivers independently observed 1 and 21 codepoints, concatenating to the complete 22-codepoint sample. A separate cancellation sample observed one codepoint in A, none in B, and no later text. These are same-page field checks, not cross-window acceptance.
- On Ubuntu 26.04, two separately launched native Wayland Chrome windows were tested in one output session. The controlled receiver observed the first character in A before focus moved to B; B received the next character, and A received the last after focus returned. The three observed characters matched the requested sequence, with no later text. The fixture explicitly paused at dispatch boundaries to establish focus; it does not demonstrate arbitrary focus switching under load. The output session ended with `ibus_delivery_unknown` after three attempts, so the receiver observation is not a protocol acknowledgement of delivery.
- On Ubuntu 26.04, a separate native Wayland-to-XWayland window case did not pass: A observed two codepoints, but B observed none after the switch. The following dispatch stopped with `ibus_delivery_unknown` and two attempts. No late text was observed and the uncertain input was not replayed. Do not infer native-to-XWayland delivery from the same-page or native-window samples.

Ubuntu 24.04 cross-window behavior, other target applications, physical devices and real cloud providers remain unverified. The tests do not prove delivery in arbitrary applications or guarantee a target processed or displayed text. Already attempted output cannot be safely replayed merely because acknowledgement is unavailable.

## Procedure, failures and cleanup

In disposable guests, verify the AppImage SHA and mount it, confirm GNOME Wayland and enable the matching owned-context extension, then run controlled native Chrome receivers with focus evidence and a synthetic streaming producer. Record actual dispatch backend, each observed receiver value, cancellation and delayed follow-up, and the session outcome. For the separate-window case, focus changes were made only at explicit dispatch boundaries after checking the owned receiver. Verify cleanup and restore extension settings after each guest. The private harness and raw VM records contain environment-specific data and are not part of this public summary; this document alone is not a standalone test suite.

The initial Ubuntu 26 same-page attempt loaded an older extension protocol and failed with `ibus_upgrade_required` before any dispatch: A had focus and both fields remained empty. The matching extension was installed after saving the old assets and the desktop was reloaded; the tests above then ran. The initial 26 VM launch also failed because a temporary harness had an incorrect read-only snapshot path; it succeeded after correction. Ubuntu 24 startup initially timed out on SSH while the same VM initialized its network and later connected without rebooting. All failures are retained as such; they are not counted as passing samples.

Both guests reported resource cleanup and exited with code 0 without OOM; original extension assets and settings were restored. The prior v0.16.0 dual-system package report remains the release artifact record. This document does not modify or replace the published AppImage, tag, or release.
