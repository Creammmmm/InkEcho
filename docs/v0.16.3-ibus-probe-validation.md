# IBus 单次探测 owner 变化验证（0.16.3）

日期：2026-10-31。变更仅在一次 owned IBus 探测中监听服务名称变化；任意名称变化使该次探测保守失败。它不保证多次探测之间或整次输入任务的服务身份连续性，也不提供接收端回执。

```sh
.venv/bin/pytest -q -p no:cacheprovider tests/test_ibus_probe_owner_epoch.py
.venv/bin/ruff check --no-cache src/inkecho/platform/ibus_owned_auto.py tests/test_ibus_probe_owner_epoch.py
.venv/bin/ruff format --check --no-cache src/inkecho/platform/ibus_owned_auto.py tests/test_ibus_probe_owner_epoch.py
```

结果：10 项通过，Ruff 检查和格式检查通过。测试使用模拟总线，覆盖 ABA 信号拒绝、无关信号、正常和受阻状态、无目标、注册失败与超时、连接失败、取消、并发以及连接清理。更广的 13 组原有 IBus/Fcitx 和路由相关测试共 191 项通过（含新增测试）。

## 独立私有总线实验

在本机临时私有 D-Bus 中运行的受控服务于 Probe 期间释放服务名称并由同一进程重新取得；独立观察者记录两次名称变化。原生产 probe 误接受该情况；隔离修复副本拒绝该情况，同一名称一直保持的对照通过。为运行该测试，测试身份验证器设为恒真，服务模拟 IBus；测试脚本位于本轮临时目录 `/tmp/inkecho-probe-aba/`，不是持久的发布验收资产。

本次没有在真实 GNOME/IBus、Ubuntu 24.04 或 26.04 实测输出，也没有验证两系统 AppImage。此证据不表明任何应用兼容性、接收成功、跨焦点完整性或可发布状态。
