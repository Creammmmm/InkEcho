# IBus 输出中切换焦点验收

旧版在每次发送前检查 GNOME 当前输入上下文。若在异步查询期间换窗，即使两个目标均可接收，也会停止整个输出任务。新版只对尚未派发的当前片段，在确实观察到焦点或上下文变化时，等待一次桌面事件处理边界并重新完整检查。连续变化、无法验证的目标、活动或未知组词、取消、过期及服务所有者变化仍会停止当前片段。已经尝试派发的文字不会重放。

## 复现步骤

1. 在隔离的 GNOME Wayland 客机中，用 `cc3afa8` 和本修复分别运行真实 InkEcho IBus 客户端及对应扩展。每次换扩展后重新登录桌面，核对 D-Bus 运行标记及资产校验。两个客机均使用同一个历史 0.15.0 AppImage 提供 Python 运行环境，其 SHA-256 为 `94a73232871abaca8c91fb5f58e52059be404f10605955562d39bf31ec64354a`。测试时覆盖源码，未构建本修复的 AppImage。
2. 用两个独立进程打开原生 Wayland GTK 可编辑窗口 A 和 B，记录真实窗口、控件焦点与各自的正文变化。两个输入框均从空白开始。让 A 获焦，开始一个输出会话，发送固定样本「甲乙丙」。
3. 为稳定命中竞态，仅在客机扩展副本的 `current` 回调加测试探针。第二次调用在取初始快照后、发出真实 IBus 查询前暂停。此时确认 A 已收到「甲」，让 B 获焦，再释放查询。两个客机均使用生产 `OwnedGate`、真实查询和提交路径。24.04 直接使用已验证服务身份的 IBus 桥，26.04 走自动路由并为探针文件替换单个资产校验值。26.04 另用完整未修改的扩展在片段边界换窗作对照。
4. 分别检查两个接收方的全文、逐次变化、短时间内是否有迟到文字，以及发送端的后端、派发次数和会话释放。不能用发送端的次数代替接收端观察。退出并恢复客机原有设置。

测试逻辑的 `owned_gate.js` SHA-256 为 `e64c700e3a039b94de094d964efc0bc63c3655aabed2d9194299de7a55efc3dd`，未加探针的 `extension.js` 为 `7e0165c9e562ac5af79808f29affdec6a18d012979da99f5b896996fef05a75b`。新版运行标记为 `owner-loss-focus-recheck-v2`。旧版完整资产仍可识别，旧运行标记会提示升级扩展。旧扩展需按界面指引更换并重新登录桌面。

## 实测结果

### Ubuntu 24.04.5，GNOME Shell 46.0，原生 Wayland

- 使用 IBus 1.5.29-2、GTK 3.24.41 和一次 `IBusBridge.insert("甲乙丙")`。探针记录第二次查询前后 Shell 窗口 ID 变化和焦点代际递增；GTK 同时观察到 A 失焦、B 获焦且组词为空。
- 旧版只尝试派发一次，A 收到「甲」，B 为空，桥返回 `delivery_unknown`。新版同样切换时返回 3，A 的全文只发生「甲」一次变化，B 的全文依次变为「乙」「乙丙」，随后 450 毫秒没有迟到输入。
- 新版取消对照在第二次查询暂停时关闭桥，再释放查询。A 保留「甲」，B 为空，桥报告 `delivery_unknown` 并记录此前的一次尝试，未派发剩余文字。这里直接调用了桥的取消清理，未使用物理 Escape。
- 已恢复客机扩展、输入源和登录设置，客机正常关机，QEMU 返回 0。临时原始证据位于 `/tmp/inkecho-focus24.I2hnfH/output/`。首轮启动及 GTK 夹具导入失败后重新运行，失败日志保留，结论只使用有效样本。

### Ubuntu 26.04.1，GNOME Shell 50.1，原生 Wayland

- 旧版在第二个字的查询中切窗，A 收到「甲」，B 为空，任务在一次派发后中止。
- 新版在相同位置切窗，释放查询前确认 A 已失焦且 B 已获焦。A 保留「甲」，B 的两次变更为「乙」和「乙丙」。同一输出会话使用两次 `insert`，第二次完整派发。未调用键盘路径，尾部 0.5 秒内无迟到或重复输入。
- 使用无探针扩展，在 A 已收到首字后切窗再发送剩余片段，得到同样的 A「甲」、B「乙丙」。两个新版测试均由发送端记录 `dispatch_complete=true` 和 3 次派发。IBus 没有目标应用收件回执，实际文字由 GTK 接收方独立确认。应用对这一状态显示发送完成、接收未确认的提示。
- 测试窗口已退出，GNOME 输入源和扩展设置已恢复，客机正常关机，QEMU 返回 0。临时原始证据为 `/tmp/inkecho-owned-focus26/REPORT.md` 和其 `output/` 目录。早期候选样本的 A 失焦取样仍滞后，结论使用等待 A 确实失焦后的复测。

## 自动化与范围

`tests/test_owned_focus_recheck.py` 直接运行生产 JavaScript，覆盖 A→B、A→B→A、片段间切换、取消、过期、所有者变化、活动或未知组词、目标不兼容、重复变焦、查询或事件边界失败及派发后的不重放。新增用例在旧 gate 上重现失败。协议与资产用例覆盖旧运行标记升级提示、旧版完整资产及混合资产拒绝。

本次桌面测试范围是已启用匹配扩展的 GNOME 原生 Wayland 和自有可编辑目标。Xorg 原生 IBus、XWayland、任意应用、真实麦克风、物理快捷键和云服务均未在本轮验证。源码覆盖测试不构成最终 AppImage 验收。
