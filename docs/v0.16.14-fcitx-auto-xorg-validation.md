## Ubuntu 24.04：保留失败，再核验真实登录环境

首次执行 im-config 并重启 GDM 后，旧用户 manager 仍保留 `QT_IM_MODULE=ibus`、`XMODIFIERS=@im=ibus`。应用 shell 与 manager 一致。夹具在发送前的环境断言处停止。不能把 im-config 保存选择等同于会话已经切换，也没有将这个失败算作输出成功。

随后在隔离客机停止 GDM、结束旧用户会话并重新登录，用户 manager PID 从 1180 变为 4204。没有人为注入探测器环境。真实 manager 与应用 shell 均为 `GTK_IM_MODULE=fcitx`、`QT_IM_MODULE=fcitx`、`XMODIFIERS=@im=fcitx`，真实活动 seat 为 GNOME Xorg。

真实桌面总线上分别存在 stock Fcitx `/usr/bin/fcitx5` 与 stock IBus `/usr/bin/ibus-daemon`，不冒充对方。Fcitx 的 clipboard、ibusfrontend 插件运行状态已核查为禁用。配置前 InkEcho endpoint 为 UnknownObject、可用桥探测为空。包内可见“配置 Fcitx5 输入桥”按钮实际点击一次，配置前后设置均为 auto。热载前后 Fcitx owner `:1.15`、PID 4336、start tick 34242 不变，RuntimeVersion 为 5.1.7，发布桥摘要为 `f67c6b5f2cb7ecd7c915c8062efd3b70284c74b97ced4a597d942c4b39594e44`。

真实包内 Session 在输出阶段选择 `inkecho.platform.fcitx5`，owner `:1.15`、协议 4。独立 GTK 进程 5194 映射系统 im-fcitx5.so，真实 X11、控件有焦点、空 preedit，收到且仅收到 `甲A🙂乙Ω`。准备阶段字段仍为 keyboard，不能用这个提前状态代替实际输出路由。记录的 normal_route 和 cancel_route 均在真实输出中确认 Fcitx。

第二任务尝试 `丙丁戊`，首字发送后使任务失效。返回 `fcitx_cancelled`、计数 1，独立控件最终为 `甲A🙂乙Ω丙`，没有丁戊。输入桥已关闭、能力已删除、actor 已退出。最终恢复客机原 im-config 与 Fcitx 配置，GNOME 输入源未变，移除暂存桥并确认无测试进程。正常关机的 `qemu-exit-r2.json` 返回 0，Docker/QEMU 均正常退出，容器已删除。

## Ubuntu 26.04：显式配置的 XFCE 登录

此镜像未安装 im-config。客机 `.xsessionrc` 导出上述三项 Fcitx 环境。XDG autostart 运行 `/usr/bin/fcitx5 -D --keep --disable=clipboard,ibusfrontend,xim,waylandim`，选择 XFCE/Xorg 并真实重新登录。实际 systemd 用户环境确认 XFCE、x11 和三项 Fcitx 值。使用真实 `/run/user/1000/bus`，不是私有总线代替桌面。

包内可见配置按钮程序点击一次，设置始终 auto。打开页面及负向状态检查不安装桥。配置后正向检查成功。同一个 stock Fcitx 5.1.19-1 保持 owner `:1.24`、PID 2803、start tick 3681，RuntimeVersion 5.1.19。没有 IBus 服务 owner。

实际 DefaultAutoOutputRouter 在 output_session 内选择 fcitx。独立 GTK actor 3393 映射系统 im-fcitx5.so（GTK frontend 5.1.6-1），真实 GdkX11Display、active/focused、空 preedit。`xdotool getwindowfocus -f` 原始 X 焦点等于自有 XID 27262979。精确收到 `甲A🙂乙Ω`。另一次默认 auto 任务的首字取消只追加丙，0.8 秒后仍为 `甲A🙂乙Ω丙`。取消夹具退出时出现 Qt timer 清理警告，原日志保留。发生在断言通过后，不隐藏该警告。

客机正常 poweroff，QEMU 返回 0，容器删除，临时磁盘与所有登录配置丢弃。父盘只读，宿主未修改。

## 复现和证据

1. 从一次性镜像启动相应真实桌面，核对 AppImage SHA。使用包内模块，不增加源码 PYTHONPATH。
2. 配置客机输入法并真正重登。独立记录实际 manager/shell 环境、总线 owner 与进程身份。环境不一致时在发送前停止。
3. 设置保持 auto，真实包内按钮配置桥。记录配置前不可用、配置后 RuntimeVersion 与同一 owner/PID。
4. 用独立 GTK 控件记录实际焦点、模块映射与文本事件，观察 Session 输出中的真实路由，再验证 Unicode 与首字取消。
5. 退出 actor/应用，清理一次性客机。只把实测组合计为通过。
