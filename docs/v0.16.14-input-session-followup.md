24 GNOME Wayland 的真实包内 Session/router 显式调用
`prepare_task('ibus-owned')`，核对选中模块 `inkecho.platform.ibus_owned`。
包内扩展首次安装后无法在当前会话启用，经客机重新登录后启用。一次状态
查询暂为 unknown，随后实际核验 enabled 与版本标记。没有把暂态当作成功。
同一 scope 先向真实 native GTK A 输出 `甲A🙂`，焦点切到 B 后输出 `乙Ω`。
独立事件与最终内容一致，派发共 5 次，delivery_unknown 与真实接收分别记录。
新任务取消后 B 只追加 `丙`，状态 input_cancelled、attempts=1。Session 关闭、
router 解除与 actor 退出均确认。原始证据为该 24 目录 `output/ibus-output.json`。
这不证明首次安装无需重新登录，也不证明 24 自动路由已选择该后端。

26 使用真实包内 `DefaultAutoOutputRouter.prepare_task('auto')`，在同一个
output_session 中先向 native GTK A 输出 `甲`，再打开不同进程的 B。
B 实际 active/focused，A 已 inactive/unfocused，随后输出 `乙丙`。
最终 A 精确为 `甲`，B 的 changed 序列为 `乙`、`乙丙`。没有重复、回放或
迟到文字。切换发生于两个完成的 insert 之间，不是强制异步保护竞态。

服务真实 owner 为 `:1.8`，OwnerGuardVersion 为
`owner-loss-focus-recheck-v2`。`provenance.json` 核对全部安装扩展文件与包内

`7e0165c9e562ac5af79808f29affdec6a18d012979da99f5b896996fef05a75b`。
owned_gate.js SHA-256 为
`e64c700e3a039b94de094d964efc0bc63c3655aabed2d9194299de7a55efc3dd`。

## 复现与限制

仅在隔离客机中挂载各实验目录的只读 input 和可写 output。先核对同一镜像
哈希。新增 Fcitx 实验的 `package-probe.py` 经真实配置页面调用，GTK actor
独立记录模块、焦点与文字。具体启动参数与原始失败保存在各实验目录。26 XFCE 使用 `launch-package.py`、
`package-session.py`，ownerless 回退为 `auto.py`。24 Wayland 的扩展流程为
`ibus-install.py`、`ibus-enable.py`、`run-ibus.sh`，实际双目标与取消断言在
`ibus-output.py`，目标进程为 `ibus-actor.py`。

26 owned 将原样包内扩展安装到客机用户目录，备份原设置后仅重启客机 GDM。
运行 `launch-probe.py`、`launch-cancel.py`、`launch-provenance.py`，最后运行
`restore.py` 并关机。模块仅从解包后的 packages 加载。未使用剪贴板、真实
用户文本、云服务或麦克风。未覆盖密码框、任意应用或活动组词切换。

本补充不是 release，也不扩展未经实测的桌面支持声明。临时原始目录可能被
清理，本文保留必要合成观察和边界。各新增客机与容器均已完成清理。
