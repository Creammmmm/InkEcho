## Causes and changes

1. Input authorization preceded audio capture, and the UI could say listening
   before any sample arrived. Recording now starts before desktop input consent,
   and a capture-ready signal changes the display from microphone startup to
   listening. During this repair experiment, a forced 20 ms Qt capture buffer
   truncated the synthetic start marker on Ubuntu 24.04. That setting was an
   undelivered tuning experiment, not a cause established for the user's original
   0.5.0 image; the final repair does not adopt it and uses the platform default.
2. The old Qwen realtime path explicitly used manual detection. It uploaded audio
   during recording but waited for stop before committing it; an artificial
   server that emitted early text did not prove live-cloud previews. Standard
   official endpoints, derived or explicitly saved, now use server VAD with a
   400 ms silence boundary. Explicit manual selection and custom/nonstandard
   endpoints retain manual behavior. Preview is replaceable RAM text; final
   keyboard output still requires stop, finished recognition and the same task's
   authorization. Cancellation stops all remaining output.
3. The host retained the `waveform` display preference, but the Wayland window
   branch explicitly hid every style except Siri. All three styles now show
   status and supported realtime drafts through the existing display-only XCB
   host on native Wayland. The settings window remains native Wayland.
4. GNOME's persisted shortcut invoked `--toggle`, which previously cold-started
   an exited application. Control commands now address an existing instance only;
   no instance means successful no-op without configuration, GUI or recording
   startup. Deliberate launch and `--show` still start the app. The control path
   avoids loading GUI, audio and provider modules. Closing settings still hides
   to the tray; complete tray exit / `--quit` ends shortcut availability.

Neither clipboard nor system input methods are used. Recording does not capture
an input target, and final keyboard delivery follows the cursor at output time.
Credentials stay in their existing dedicated plaintext configuration file; no
real configuration was rewritten or restored by acceptance tools.

### Synthetic capture onset and complete-exit controls

All audio tests route generated PCM into uniquely owned temporary virtual audio
nodes. They never record a physical microphone or change default devices. Each
run sends a 100 ms marker at the start, then silence; the acceptance threshold
is at least 1200 marker samples. Owned modules are unloaded and default-device
hashes are compared afterward.

| Actual package system | First-frame times, three runs | Marker samples | Playback to first signal | Complete-exit control timing |
| --- | --- | --- | --- | --- |
| Ubuntu 26.04 | 5.001 / 17.275 / 18.151 ms | 1601 / 1601 / 1601 | 70.159 / 83.111 / 64.112 ms | Five extracted-package no-instance toggles, median 195.94 ms |
| Ubuntu 24.04 | 5.869 / 27.485 / 25.653 ms | 1600 / 1601 / 1601 | 93.549 / 80.501 / 84.320 ms | Five extracted-package no-instance toggles, median 198.44 ms |

These are three synthetic captures and five command invocations in each measured

## Reproducing and remaining scope

Use the exact artifact and verify its sidecar first. Private package acceptance
inputs and metadata are preserved under `build/v0.5.8-repair-preparation` and
`build/v0.5.8-repair-acceptance`; guest inputs are a fresh 454-file stage. Run
fixed reviewed modes serially and stop on the first failure. Never replay an
ambiguous partial keyboard delivery.

The tracked `scripts/validation/qwen_vad_package_probe.py` takes the package's
interpreter, `--package-root APPDIR/packages` and a new `--output` JSON. The
tracked `scripts/validation/audio_onset_probe.py` is a source tool; package
acceptance uses an explicit wrapper that preloads and verifies the package's
Recorder, restores import paths after loading the frozen tool, and records its
actual package origin/hash. Invoking that source tool directly from a frozen
checkout would not establish actual-package capture behavior.

Ubuntu 24.04 GNOME 46 native Wayland keyboard delivery remains outside the
supported scope; its Xorg result cannot be relabelled native Wayland support.
Windows/macOS are not validated. Real microphone accuracy, physical hotkeys,
provider billing and broad application compatibility are not established by
these synthetic package tests. HTTP/manual-only services cannot promise live
recording drafts. A 400 ms VAD silence boundary, network time, device startup,
optional polishing and final keyboard delivery still contribute latency.
