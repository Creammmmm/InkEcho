# Ubuntu 24.04 Xorg：旧 IBus panel 焦点与预编辑实验

2026-10-31 在无外网的隔离 Ubuntu 24.04 GNOME Xorg 虚拟机上，使用自建 Chrome 页面和 GTK 输入框，测试现有实验性 V2 扩展通过 GNOME Shell 已有 IBus panel 的 `commit_text` 方法提交合成字符。该方法不占用或替换 IBus panel 服务身份。旧 0.15.0 AppImage 的 SHA-256 为 `94a73232871abaca8c91fb5f58e52059be404f10605955562d39bf31ec64354a`；其中的 Python 运行环境叠加了先前桌面测试相同的 94 个源码文件（清单摘要 `c6774a4e8d4d7f93b27037ed3ef615b7ade7f0c6e6b376237e47b2ca56729508`），因此这不是当前最终包验收。所有内容为合成数据，没有读取用户正文或使用剪贴板。

- 同一 Chrome 输入框的普通样本收到完整 `甲乙丙丁abc123`。在网页首次输入事件后将焦点从 a 转到 b 的样本中，a 收到 `甲`，b 收到 `乙丁abc123`，`丙`未出现在两个输入框中。发送结果是未确认，不代表客户端确认收到。取消样本收到 `甲`。
- 为测试跨窗口切换，专门的实验钩子在自有 Chrome 页面实际看到 `甲`后，才将窗口焦点切至自有 GTK X11 控件，然后继续提交。Chrome 保持 `甲`，GTK 当时报告 active/focus 均为 true，正文为空；发送端记录十字提交尝试，未确认交付。该样本没有独立证明 GTK 控件输入法模块准备就绪，不能据此确定丢失原因。原普通脚本的 `window-switch` 情形只对键盘驱动设置切换钩子，此处运行的是 IBus，钩子未触发，不能作为跨窗口证据。
- 在 libpinyin 已输入 `ni`，Chrome 报告候选 `你`的状态下，旧桥首字 `甲`使页面收到 `compositionupdate(甲)` 和 `compositionend(甲)`；之后空格提交候选，最终为 `甲乙丙丁abc123你`。取消样本同样发生提前 `compositionend`，空格后为 `甲你`。本样本中原候选最终仍提交，但应用感知的组词生命周期已经改变；不得推断其他应用或输入法也能保留候选。

因此这些样本不能支持将旧桥自动用于 Xorg：切换焦点期间提交未获交付确认，活动组词也无法安全保护。仅监听 IBus 预编辑变化不能证明监听前的状态为空，异步查询和后续提交也不能消除竞态；不得在提交结果未知后回退并重放。GNOME `Main.inputMethod.hasPreedit()` 保护的是其原生输入上下文，不能据此证明任意 Xorg 客户端的状态。AT-SPI 可编辑文本接口存在应用支持、焦点竞态与语义差异，本次未测试、未纳入产品。

[实验脚本和合成结果](../experiments/ibus-xorg-panel-20261031/)保留了三个测试；其启动脚本还依赖先前验证的隔离测试共享目录、旧 AppImage、Python 依赖、Chrome、GNOME 扩展及 `session_product_r2.py` 等夹具，并非独立测试套件。测试不是 Ubuntu 26、真实网站或编码 CLI 的兼容证明，也不是双系统同包验收。

客机先禁用扩展；首次卸载命令误用了扩展标识，失败后使用实际标识成功卸载，用户扩展列表为空。临时安装的六个拼音依赖的 `dpkg -l` 均报告未找到，IBus 引擎恢复 `xkb:us::eng`，测试 AppImage 挂载移除，客户机正常关机。原始启动配置和详细清理日志保留在 `/var/tmp/inkecho-xorg-panel/vm24/`；未操作宿主用户桌面。
