# 0.16.0 Fcitx 原生 Wayland 受控补测

2026-10-31，在无外网隔离虚拟机分别运行 Ubuntu 24.04.5/GNOME 46 与 Ubuntu 26.04.1/GNOME 50.1，均为 Wayland 会话。测试使用正式 0.16.0 AppImage（SHA-256 `fa1bbfffc6480534b790bdf00e29ea45977f529ef398ceb94fa7f2830223c6bf`）中的模块、隔离 Fcitx 实例、自建 GTK3 原生 Wayland 控件及合成文本；没有真实用户内容或剪贴板。测试不代表 0.16.7 或任何其他版本的 AppImage 验收。

## 双窗口与取消

在同一输出会话中，夹具只在每次派发边界暂停并切换自有窗口，按 A→B→A 输入“己”“Ψ”“辛”。24 与 26 的正常样本均由 A 收到“己辛”、B 收到“Ψ”，所选后端为 Fcitx。取消样本在第二次已尝试输入后取消，两个系统分别报告 `fcitx_cancelled`、累计尝试 2；即时及后续采样均为 A“己”、B“Ψ”，第三字符没有出现。已尝试发送不能撤回；这些样本不证明任意时刻切焦或取消都不会出现迟到字符。

## 活动组词

两个系统各自在单个自有原生 GTK 控件上，使用 Fcitx Pinyin 构造长度为 2 的真实预编辑；尝试输出时返回 `fcitx_composition_active`，尝试次数 0，原有预编辑长度保持。之后由夹具发送空格提交，目标显示“你”；独立首字取消样本报告 `fcitx_cancelled`、尝试次数 1。这不是跨窗口组词测试，也不证明其他应用或输入法均有相同表现。

## 失败与复现线索

两系统独立的完整 pipeline 尝试均未完成：原 X11 夹具使用 `xdotool` 查找原生 Wayland 目标，查找失败，测试进程均退出 1；不得将其作为 pipeline 通过或应用功能失败的证明。26 双窗口正常测试的前两次因 `fcitx_unavailable` 未完成，修复测试环境后第三次才得到上述正常样本；首次取消记录的外层错误被 `output_failed` 掩盖，修正记录后第二次才得到上述取消结果。不得忽略这些失败。

本轮临时原始记录分别位于 `/tmp/inkecho-fcitx-native24/output/` 和 `/tmp/inkecho-fcitx-native26/output/`：双窗口正常为 `native-cross-normal/result.json`（24）及 `native-cross-normal-r3/result.json`（26），取消为 `native-cross-cancel/result.json`（24）及 `native-cross-cancel-r2/result.json`（26）；组词为各自 `fcitx-raw-wayland-r2/results.json`；失败 pipeline 的诊断为各自 `wayland-r2/fcitx-package.log` 和 `coordinator.log`。对应本轮临时 `input/` 中夹具及 `coordinator.py`、`launch.json` 提供复现线索；完整复现还需要隔离虚拟机镜像、同一 AppImage、测试依赖及 GNOME/Fcitx 环境。临时目录不是永久发布资产。

本次没有验证 0.16.7 包、真实云服务、物理麦克风或快捷键、Chrome/Codex、任意目标和自由切焦，也没有验证完整 Session pipeline。不能以此扩展现有版本的兼容性或发布声明。
