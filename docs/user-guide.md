# InkEcho 使用指南

本指南描述 a14 开发预览版的配置与当前光标输入行为。同一 AppImage 已通过 Ubuntu 24.04.5 GNOME 46 Xorg 和 Ubuntu 26.04.1 GNOME 50.1 Wayland 主机的限定实际包验收；具体会话、字段与未测范围见[a14 双系统报告](a14-dual-ubuntu-validation.md)。实时转写、流式润色选项以实际启动版本为准，旧下载包可能没有这些选项；本机稳定入口现已更新 a14。开始录音不用先选文本框，录音、识别与润色期间可自由切换窗口；结果送到输出当时的光标位置。输出途中切换窗口，后续字符也可进入新焦点。主动取消、过期或被替代的任务停止未发送文字，已经发送的按键无法撤回；不使用剪贴板或系统输入法。

X11 / XWayland 与原生 Wayland 的支持范围分别验证。a14 在上述两系统的自有 Chrome X11/XWayland 字段完成 31 字符精确读回、取消 8 字符及当前光标 [5,26] 切窗；本机原生 Chrome 两字段各完成 29 个 BMP 字符、取消 8 字符和三段 native/XWayland 混合路由，emoji 等非 BMP 字符明确拒绝。Noble 的这些新结果来自 Xorg，不证明 GNOME 46 原生 Wayland 输入。历史 a9 在实际 GNOME Wayland 桌面的自有原生 Chrome 与 XWayland 测试窗口通过当前光标输入及双向切窗验收，原生路线暂不支持 emoji；这些结果不能推定所有应用或 Ubuntu 24.04 已兼容。详见[a9 原生 Wayland 验收](native-wayland-parent-validation.md)及[历史 a8 验收](focus-tracking-removal-release.md)。设置、麦克风测试与云服务能力测试不依赖自动输入可用性。

Ubuntu 24.04.5 的实际 KVM Xorg 测试须按版本区分：a11 的 R2 长流文字和取消正确，但新 GTK 就绪仍需 6.0944 秒，这份历史结果保留。[R7 新源码](ubuntu24-source-r7-validation.md)验证后，[实际 a12 包](performance-a12-package-validation.md)独立通过首轮八种模式，包括四目标、取消、本地模拟服务、快速长流、首字不等待后续片段、切窗和提取后九页界面；单次快流清理后新 GTK/VTE 为 0.1747/0.3388 秒。

a12 的 R2 夹具改为每片段配置 70 ms 等待后，文字和取消仍正确，但 GTK 就绪用 5.8435 秒，**延迟验收未通过**。这份 a12 反例保留，不因后续源码修复而改写；不能将快流结果推广到任意节奏或立即响应。以上没有验证 VM 麦克风、云端识别、物理快捷键、FUSE、安装或自启动。该 VM 的 GNOME 46 原生 Wayland 还缺少当前输入后端所需接口，授权失败；界面启动不表示可向原生窗口输入。详见[a12 慢流反例](performance-a12-paced-validation.md)、[历史 a11 记录](performance-a11-package-validation.md)和[兼容性矩阵](compatibility-matrix.md)。

[R8 源码检查](ubuntu24-source-r8-validation.md)已在真实 Noble Xorg 虚拟机通过相同慢流/快流，正常任务均只恢复一次映射，并通过首字不等待后续片段及 [12,44] 切窗。源码测试使用旧 a12 的解释器与依赖，不替代包验证。随后[a13 实际包](performance-a13-package-validation.md)独立通过 Noble 七项检查，包含默认四目标、取消、普通及两种长流本地链路、首字/切窗及提取后九页界面；包内慢流清理后 GTK/VTE 为 0.1753/0.2983 秒。这不是末字当刻响应或可靠性分布，也没有新增云端语音或 VM 麦克风验证。

同一 a13 包的[主机验收](performance-a13-host-validation.md)在 Ubuntu 26.04.1、GNOME 50.1 Wayland 会话完成：四个自有 XWayland 目标、取消、真实麦克风到本地固定文本服务的输入链路，以及原生 Wayland 九页界面、IPC 与损坏配置保留均通过。这次界面检查未测试原生 Wayland 输入；本地固定识别结果也不能证明云端语音准确率。

本机稳定入口已部署 a14，Qwen 已明确切换实时模型/协议；保留现有 F4、16 kHz、密钥引用与其他设置，稳定入口的正常 FUSE 挂载启动已核验，现保留运行。公开 v0.1 下载包仍为 a8。启动独立版本文件前先正常退出旧实例，否则单实例通信可能只唤起旧进程；本次部署未改桌面入口、图标或自启动，修改前文件已备份。a10/a11/a12 旧包均保留原样，不包含后来的 R8 映射生命周期修复。

alpha6 的[原生 AT-SPI 记录](native-voice-workflow-validation.md)描述旧版目标绑定策略；不要按旧版失焦取消要求操作当前版本。

## 第一次使用

1. 确认关于页和启动路径为所需版本；若旧实例仍在，先正常退出，再启动新包。打开「录音与快捷键」，选择麦克风，点击「测试麦克风 · 3 秒」。音量条应随声音变化；测试不上传也不保存音频。
2. 打开「语音转写」，选择「录音结束后上传 · HTTP」或「边录边识别 · Qwen 实时 WebSocket」，填写对应服务地址、模型 ID 和 API 密钥，保存。密钥进入系统 Secret Service 密钥环；系统密钥环不可用时会明确失败，不落入普通配置文件。切换方式不会自动修改模型、采样率或已保存配置。
3. 可用「发现模型 / 测试连接」检查模型列表。模型列表返回成功不代表模型具备转写能力；「测试模型能力」会录制三秒并调用云端，可能计费。
4. 需要润色时，单独配置「文字润色」页面中的 OpenAI 兼容服务、模型和密钥，开启润色并保存。「边润色边输入」默认开启，可提前输出已生成的文字；关闭后等待完整润色结果。可单独设置转写、润色超时。尚未尝试输入时，润色失败是否使用识别原文由复选框控制；已经开始输入后若失败，会停止剩余文字，不会整段回退或重复输入。
5. 在「Prompt 模板」选择模板。修改内置模板会保存为用户副本；内置原件不能删除。示例预览只在点击云端测试后上传，结果仅在本页显示。
6. 在「录音与快捷键」显式启用快捷键。应用检查 GNOME 绑定冲突，不覆盖其他应用设置。当前会话实际按键触发仍须实测。

使用 `qwen3-asr-flash-realtime` 时，请明确选择实时方式，并在录音设置中手动选择 **16 kHz**。受支持的阿里云官方地址可以留空「实时服务地址」，由应用派生；自定义服务必须填写其实际提供的 `wss://` 实时地址，普通 HTTP 地址或仅改模型名称不能代替实时接口。实时方式需要模型及账户实际提供对应能力；a14 已在本机 Ubuntu 26.04 完成一次官方公开 WAV 能力请求（202 字符、954.919 ms），详见[a14 实测](a14-dual-ubuntu-validation.md)；这是完整音频的能力请求耗时，不是停止录音到首字或真实麦克风实时延迟，也未评估准确率。此前生成静音与 a13 公开音频 A/B 各有独立记录，不能替代当前包的实测。

模型列表中的红色表示与**当前转写方式**不匹配，切换方式会重新标注；不意味着操作系统或模型在所有协议下均不支持。仅把模型名改为 realtime 不会自动切换协议；旧 `qwen3-asr-flash` 与 `{}` 仍使用 HTTP。

「请求参数 · JSON」仍可编辑高级字段；切换方式会保留其他字段，损坏的 JSON 不会被静默替换。实时方式仅接受 `asr_protocol` 和可选的 `realtime_url`，切换后需手动移除 `asr_options` 等 HTTP 专用参数。未知或不适用的参数会在保存、测试或使用时明确报错；实时地址不能含账号密码或密钥查询参数。能力测试会使用当前表单的模型及协议，润色测试按**已保存的**「边润色边输入」设置选择流式或完整响应；先保存偏好再测试。切换表单内容后，旧测试的迟到结果不会覆盖新表单。

## 录音与输入

按快捷键开始录音，再按一次结束并提交识别；开始时不需要存在可编辑文本框。也可从概览点击开始。录音和识别期间可以切换窗口，输出时将光标放在希望接收文字的兼容应用中。输出途中切换窗口，后续字符可以进入新位置，文字不会被固定送回录音开始时的窗口。

实时方式在录音期间分段发送音频，结束后等待最终转写；HTTP 方式在结束后上传完整录音。两者都只把最终识别结果交给后续润色或输入。能力测试为了单独验证协议，会先录制三秒再将样本通过所选接口发送，结果仅显示字符数，不输入其他窗口；它不等同于完整的边录边传验收。

录音期间可查看音量和时长；GNOME Wayland 使用系统通知显示状态，再次按快捷键结束录音并提交转写；主动取消请使用通知中的「取消」、托盘菜单或概览的「取消任务」。窗口、光标或选择区变化本身不取消任务。主动取消或任务过期后，迟到结果不会继续发送；若取消发生在输出中，已发送部分会保留。处理失败不回退到剪贴板或系统输入法。「按键已发送」表示发送已完成，不能保证每个应用都会接受这些按键。

服务、密钥引用、模型和 Prompt 在任务开始时固定，本次录音期间修改设置只影响后续任务。主窗口关闭行为可在外观页设置；没有托盘时不会因关闭而失去入口，左侧「退出 InkEcho」明确结束应用。

## 页面说明

| 页面 | 可用操作 |
| --- | --- |
| 概览 | 录音、取消、音量与时长、当前服务摘要 |
| 录音与快捷键 | 输入设备、16/24/48 kHz 单声道、最长 300 秒、设备测试、GNOME 快捷键启停 |
| 语音转写 / 文字润色 | 独立供应商文件、HTTP / Qwen 实时选择、可选实时地址、可编辑模型与参数、边润色边输入、超时、密钥保存与删除、连接与能力测试 |
| Prompt 模板 | 创建、复制、编辑、选择、删除、明确触发的云端预览 |
| 输入与兼容性 | 当前环境、直接输入限制与诊断 |
| 外观与悬浮提示 | 波形或呼吸圆点、位置、透明度、结果显示时间、关闭窗口行为 |
| 统计与日志 | 今日计数、录音与请求耗时、精确可用的润色 Token、查看与清空 |
| 关于与桌面集成 | 安装入口、修复入口、显式启停登录自启动、删除桌面入口 |

X11 悬浮提示以颜色和形状表示进度：波形/圆点代表处理，箭头代表输入，勾号代表完成，叉号代表失败，短横代表取消。悬浮窗不接收鼠标，不主动获取输入焦点；Wayland 使用系统通知，避免应用提示窗抢走当前输入位置。

## 数据与故障恢复

普通配置位于 `$XDG_CONFIG_HOME/inkecho`，未设置时为 `~/.config/inkecho`。各供应商与 Prompt 独立保存；API 密钥仅在系统密钥环。统计与诊断位于 XDG 数据目录。诊断记录固定事件和错误代码，不记录音频、识别正文、润色正文或密钥。统计只记录元数据；服务未返回精确 Token 时显示未知。

配置损坏、字段不兼容或版本来自未来时，应用保留原文件并报告问题，不覆盖成默认值。备份后修正相关文件再启动。云服务鉴权、额度/限流、模型、网络和超时错误分别显示；请在服务页面单独测试，避免把输入目标不受支持误判成云端失败。

删除桌面入口不删除配置或密钥。若要清理供应商密钥，请先在该供应商页面点击删除密钥。应用不会默认启用开机自启动。

开发运行方式和验证命令见 [开发指引](DEVELOPMENT.md) 与 [应用验证记录](application-validation.md)。
