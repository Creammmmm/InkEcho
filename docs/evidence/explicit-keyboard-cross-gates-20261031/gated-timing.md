# Ubuntu 26 隔离焦点切换门闩实验（本地摘要）

该实验使用旧版 0.15.0 AppImage 依赖及 9ecc378 源码复制；launcher 在改动前比较 94 个常规文件，随后仅在复制后的 Wayland worker 插入 B/C 门闩，A 门闩包装应用端请求。音频、转写、润色为模拟；Session 和键盘路径真实。三个案例均为全新 GTK 控件和独立结果目录。插桩测试不是未修改包验收。

A：应用已选原生路径、尚未向 worker 写首字请求；B：worker 已接请求、尚未派发首字按键；C：首字按键已派发且释放完成，但回执尚未发送。每次等待 XWayland B 窗口焦点状态成立后释放门闩；事件按目标应用记录的 focus 和 key 信号与工作进程单调时钟关联，应用信号处理时间不是 compositor 决策的精确时刻，也不代表通用客户端确认。

A/B 两次结果为原生 A 空、XWayland B 收到“甲乙丙丁”；C 原生 A 收到“甲”，XWayland B 收到“乙丙丁”。三次 Session 均报告成功和 4 字；结束后约 1.3 秒与之后约 1.3 秒两次观察的文字相同。A/B/C 均仅各 1 次，首字请求只有一次，后续字符使用正常切换后的路径，没有自动重放。

首次包准备的审计因缺少 artifact_scope 而失败，但调用命令用分号继续进行测试；AppImage SHA 与挂载在审计之前完成。补齐部分夹具重试仍因缺少 frozen/assets/licenses 失败。两次失败保留，不可宣称本轮包审计通过。run.log 记录 worker 原始与插桩哈希、94 文件数和包 SHA。首轮缺字仍未解释；本文结果不能保证切焦期间无丢字、证明任意应用兼容或取代 Ubuntu 双系统正式包验收。

私有原始日志、控件状态和客机归档仅本地保存，不应直接上传。清理完成后关机；恢复 XFCE/X11 是恢复配置的操作，未独立验证恢复后的活动图形会话。

环境恢复证据限制：最终清理、恢复 XFCE/X11 配置以及卸载共享目录为当时工具输出中的操作记录，没有单独保存可独立复核的最终命令日志；无法仅凭本地归档核验这些操作或恢复后的活动图形会话。归档和退出状态以各自的归档记录为准。
