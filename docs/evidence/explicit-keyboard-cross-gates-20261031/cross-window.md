# Ubuntu 26 GNOME Wayland 显式 keyboard 跨窗口实验（本地去敏摘要）

被测为旧版 0.15.0 AppImage 运行依赖加从 input/current-src/src/inkecho 复制的 9ecc378 源码覆盖（input/frozen 为较旧副本，不是运行时来源），不是新包验收；音频、转写和润色为夹具，使用真实 Session、混合键盘后端、真实 GTK 控件及桌面会话。首次与复测均恢复输入源和 IBus engine。实时文字是合成样本，每次使用新的两个窗口；从不重放未确认的字符。

首次：simple 原生 Wayland 到 XWayland，Session 返回成功且派发计数 40，两个窗口在结束后约 1.3 秒和再过 1.3 秒分别为 4 与 35 字，缺少第五个字“戊”。不能将派发回执解释为目标收到，也无法凭此确定具体丢失环节；首次无逐键时序。首次反向、活动 libpinyin 双向均为合计 40 字；libpinyin 两个取消案例各报告取消、派发 1 字，窗口收到 1 字，两个观察点无后续新增。这些均为有限样本。

独立复测十次：simple 原生到 XWayland 四次、反向两次；活动 libpinyin 两方向各两次；均按 A+B 顺序得到完整的 40 字，两个观察点内容稳定。焦点状态由被测窗口约每 30ms 更新，外部采样约 5ms，不能当作精确焦点时间。举例 simple 第一例，原生“戊”请求 245.7266 至 245.7862，A 失焦被采样在 245.7619，B 获焦被采样在 245.8022；该字最终出现在 B。记录是请求区间而非客户端真实消费时间。不能从复测推断首轮丢字原因或保证所有切换安全；不应重放未知前缀。

首轮原始 cross-session JSON 和夹具已保留，但首轮控制器日志与守护按键日志位于实验根目录，复测前误以为它们在 output 内，因而被复测覆盖；不可称首轮主控日志完整留存。复测逐事件 JSON、守护按键与日志在本地，可能含私人环境数据，不应直接上传。

客机清除了覆盖目录并执行恢复 XFCE/X11 设置和显示管理器重启后关闭。恢复后 XFCE 实际活动会话未独立核实。客机容器退出 0，磁盘归档 full_stream_verified 为 true。故该实验不构成 Ubuntu 24/26 双系统包验收，不证明任意应用、任意切换时都无丢失，也未形成安全可证实的产品修复。

环境恢复证据限制：最终清理、恢复 XFCE/X11 配置以及卸载共享目录为当时工具输出中的操作记录，没有单独保存可独立复核的最终命令日志；无法仅凭本地归档核验这些操作或恢复后的活动图形会话。归档和退出状态以各自的归档记录为准。
