# Ubuntu 26 XWayland 滚动双槽候选对照（本地摘要）

本研究不是修复或包验收。隔离 Ubuntu 26 GNOME Wayland 客机中，同一 0.15.0 AppImage 运行依赖（SHA-256 94a73232871abaca8c91fb5f58e52059be404f10605955562d39bf31ec64354a），顺序运行基线 9ecc378 源码覆盖及仅在复制源码中更改 keyboard.py/hybrid_keyboard.py 的滚动双槽候选。各轮复制前后对比94个常规文件，随后在复制的 Wayland worker 中添加逐键/映射记录；测试还包装 X11 方法，自有 GTK 控件记录焦点、按键和 keymap 通知。音频、识别与润色使用固定夹具，真实 Session。插桩本身可能改变时序。完整原始日志和客机素材仅保留本地，不提交。

两轮各1次固定原生焦点、3次原生切到 XWayland、2次约50ms暂停目标、3次暂停目标至输出结束；每次固定合成40字，新建窗口，不重放。输出完成后约1.3秒和再1.3秒读取正文。基线稳定对照完整；正常切换3例中2例完整、1例共39字；短暂停两例完整；长暂停3例目标B分别0、0、1字。候选稳定对照、正常切换3例及短暂停两例均完整；长暂停3例中2例B各1字，另1例输入到原生A的5字之后报 mapping_changed，在X11按键前失败。这种失败在本基线同类3例未出现，但样本很少，不足以推断发生概率或确定具体根因。

正常切换3例，从生成第一增量到 Session 结束的时间，基线约4.01–4.04秒，候选约2.27–2.36秒；B 自身记录的 keymap-changed 次数基线150、151、150，候选86、86、90。计时含模拟增量、会话调度与所有输入，并非逐字显示或纯发送耗时；实际配置、客户端和流式分片可影响结果。长暂停成功结束的基线36/36、35/36等B按键为 keyval=0；候选成功结束的两例各36个 keyval=0、另1个非零。目标恢复后仍无可靠字符，按键派发计数不是接收确认。

基线 case03 缺少“丁”：worker press-before 40.585487、press-after 40.597852；B window-focus-in 40.597589、entry-focus-in 40.599192，A focus-out 40.598943；A/B均未记录对应按下，B在40.607895记录对应释放。时间是各进程事件处理时间，不能精确推定 compositor 内部顺序；现场支持在原生按键跨切焦时丢失，而不是证明原因是 XWayland 后续槽位变化。候选只改变 XWayland 路径，不能修复此现场。

另在 XWayland 新建窗口各做一次部分取消：基线和候选各派发首字并释放，Session 报 cancelled/1，目标两次观察均仅“甲”。这是单次受控样本，不证明所有取消竞态。候选在没有可用相邻双槽时设计为退回原单槽，未知修饰键表则拒绝；仅替身测试覆盖这一退化，客机未专门验证最少槽位。候选相较基线改变映射与发字节奏，有额外竞态和映射所有权风险，受控长暂停与 mapping_changed 已显示不能保证正确，因此未合并。

测试后清理日志记录 overlay-clean、XFCE/X11 用户环境及共享卸载；用户环境不单独证明活动图形会话已恢复。容器和 QEMU 退出0，归档完整流校验通过。生产代码未改，故障和原始数据均保留。
