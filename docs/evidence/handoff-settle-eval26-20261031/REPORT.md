# Ubuntu 26 原生到 XWayland 交接等待对照（本地摘要）

在隔离 Ubuntu 26 GNOME Wayland 客机使用同一 0.15.0 AppImage 运行时和 9ecc378 源码覆盖，复制核对94个常规文件。真实 Session、自有 GTK 窗口、固定40字符和模拟识别/润色；不使用剪贴板、不重放。测试包装在原生 finish 回复后注入约100ms可中断等待，并额外记录槽位和焦点；其并非产品实现，插桩和额外读取会影响时序，不是正式包验收。

采用交替顺序：轻负载基线与等待组各8例，然后各8例的压力组启动两个 yes 进程，但没有逐例独立记录其存活或实际CPU负载。基线两组各1例 mapping_changed，均在X11正文按下前停止；等待组均无此错误。但轻负载基线另1例 Session 报成功、派发40，两个目标最终合计仅10字；压力等待组另1例 Session 报成功、派发40，目标合计39字。其余轻负载基线6/8、等待组8/8，压力基线7/8、等待组7/8按顺序收到40字。每例两个结束后观察点的接收文本相同。已派发计数不是目标接收确认，故无法将等待视为缺字修复；小样本、单次环境和非盲测试不足以推断冲突率或统计显著收益。

实际夹具等待轻负载约94.3–105.9ms（中位94.8ms），压力组约95.0–105.7ms（中位95.9ms）。以生成首个模拟增量至 Session 结束、仅计成功状态（包括未完整接收案例）为口径：轻负载基线中位4.013秒、等待4.169秒；压力基线3.890秒、等待3.943秒。此计时包含模拟生成和整段输出，样本极小，差值不单独代表等待开销。

另2例在等待后由自有X连接覆盖借用槽：均检测 mapping_changed、X11按下0次、产品恢复未覆盖外部值；测试方精确比对自己的读回标记后清零，最终读回全零。另2例在等待期间调用 Session.cancel，分别 reported cancelled/5 和 cancelled/4，X11按下均为0；最终目标收到5和3字，两个观察点稳定，已派发的原生字符不保证都被目标收到，也无法撤回。均不证明所有真实并发与取消时序。

实验不能解决已观察的原生按下跨切焦缺字；候选未合并、生产代码未修改。原始逐案和失败日志仅本地保存。测试压力进程已结束；cleanup/shutdown日志记录overlay清除、XFCE/X11用户环境及共享卸载，用户环境不单独证明活动图形会话恢复。容器与QEMU退出0，归档完整流校验为真。
