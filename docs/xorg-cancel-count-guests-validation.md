# Xorg 取消派发统计：Ubuntu 24/26 实际 Session 复测

2026-10-31 顺序在隔离 Ubuntu 24.04 GNOME Xorg、Ubuntu 26.04 XFCE Xorg 客机测试，logind 均确认 seat0 用户会话 active/x11。使用同一 0.15.0 AppImage（SHA-256 `94a73232871abaca8c91fb5f58e52059be404f10605955562d39bf31ec64354a`）的运行时和依赖，`inkecho` 目录覆盖为提交 `ae2ed413811924ffbea869f8aa88c5bc49827604` 的源码副本。启动器对覆盖目录的 94 个常规文件逐项核对路径集合和哈希（含非 Python 资源，不包含符号链接）；例如 `keyboard.py` SHA-256 `2c049d7503120ab844d14ad44abd9079496afa9625636b732abd53c564be93fd`、`app.py` SHA-256 `13c47834759e79ff075d2aa2499a711287c1932026d4ce0d64034ac217e72a04`。同一探针文件 SHA-256 `122a111593f356f3883b7fd6eeb3b86993a467dcf25d3924f2c0a5164902e13c`；对 driver.send 包装仅观察调用和时间，仍执行原方法。这是旧包依赖加源码覆盖，并非新 AppImage 验收。

通过真实 Session 和自动路由，录音、转写、润色由公开固定文本的本地夹具合成；真实 IBus libpinyin 在自建 GTK3 X11 控件中产生稳定预编辑“你”。两系统均实际选中 KeyboardInput/_XTestDriver。首字按下调用返回后，夹具在 `on_first_sent` 同步调用 Session.cancel：24 和 26 的 finished 分别报告 cancelled、characters=1，而修复前相同类型样本为目标收到“甲”但报告 0。characters 表示已完成按键派发的下界，不是目标接收确认。

两系统取消例各观察到一次真实按下调用返回、一次释放调用返回；finished 信号均发生在释放返回之前，因此不能据 finished 宣称释放已完成。以 finished 单调时间为基准，24 分别约 1.30 与 2.60 秒、26 分别约 1.36 与 2.66 秒两次采样，控件正文均为“甲”、预编辑均为“你”；空格后正文为“甲你”。这只是两个时点的窗口读取，没有观察显示时间，也不证明时点之间或更晚绝无变化。Session 结束后驱动内部 `applied` 为 false、`_pair_applied` 为空，这是内部状态观察，不是对 X 服务器键盘映射的独立读取。自建控件由探针发 SIGTERM，退出码 -15。

正常样本两系统各成功输出 10 字，润色流开始前程序化将焦点切至第二控件后 10 字进入第二控件；原控件拼音在切焦后消失，不能归因于之后的发送。24 首轮为补充时序观察未包装 driver.send，结果作为本地记录保留；最终样本与 26 使用同一探针。未发生驱动异常、释放故障或派发状态未知的真实桌面注入：这些故障边界仅有离线测试，不能由本次正常取消实测推断。

24 临时安装的六个离线拼音包已移除、IBus 引擎及输入源恢复；26 停止自启的真实 IBus 服务并恢复 GNOME Wayland 活动会话。两台 AppImage FUSE、共享目录卸载，QEMU 与容器均退出 0、未 OOM，停止快照完整解压校验通过。原始客机记录、主机身份和快照只保留本地。本次不验证实物麦克风、真实云服务、IBus 桥送达、非 Xorg 路径、真实应用或输出中切焦，也不构成同版本双系统 AppImage 发布验收。
