# 原生 Wayland 每字释放等待调优

本页记录基于 a17 四槽实现的源码实验和本地协议验证。候选包的双 Ubuntu 验收另行记录；本页数字不代表云服务性能，也不替代实际包验收。

## 范围与基线

实验基线为 `aea74171721de6fe5840e38644ef45d66a14d800` 的 44 个产品源文件，依赖来自实际 a17 包 `6d547ecdce671c06f9e153e2f55694a6085de3e473d75a356550dbd97619fbd6`。独立冻结 r30/r20/r10 源码仅改变 `RELEASE_SETTLE_SECONDS`，分别为 30/20/10 ms。首次映射等待 50 ms、后续映射等待 30 ms、四槽上限、每字 ACK、实时状态检查和取消语义均未改变。这是明确的源码加实际包依赖运行，不能称为修改后的 a17 包。

每档有限门为：Chrome textarea 普通混合 BMP 100 字三轮；Chrome cancel5；contenteditable 100/cancel5；GTK 和 VTE 各重复混合 Unicode 100/cancel5；Chrome、GTK、VTE 各 512 字混合中英文、标点、空格与换行。取消请求始终提交完整 100 字，实际发出五字后停止，包含未发出的 hint。每项检查精确读回、真实成功按下/释放数量、守卫零拒绝、500 ms 无尾随、作用域返回前及最终原生/X 映射恢复、原 worker/目标终态与清理。自有窗口自然启动，不控制用户窗口。

实际基线图 SHA 为 `6b19630e18f35206efdf196a5a5a36c9768b1b838e7862ff157610b02216c192`。稳定 a17、旧版本产物及用户配置在每项前后做哈希保全。

## 源码打字性能

下表仅为 Chrome textarea 同一普通 100 字样本的三轮 scope 时间，包含输入事务开始与恢复，未与其它目标夹具的轮询成本混算。

| 释放等待 | 三轮耗时 ms | 平均 ms | 由平均计算的字/秒 |
| --- | --- | ---: | ---: |
| 30 ms | 5440.315 / 5565.533 / 5454.929 | 5486.926 | 18.225 |
| 20 ms | 4329.722 / 4352.091 / 4255.552 | 4312.455 | 23.189 |
| 10 ms | 3261.716 / 3383.848 / 3407.173 | 3350.912 | 29.843 |

10 ms 相比 30 ms 的该样本平均耗时减少约 38.93%。三个样本不是独立应用可靠性统计；有限自有目标通过也不能证明任意应用或机器的最小安全等待。未继续尝试更低等待。

## 保留的 VTE 夹具失败及修正

原 30 ms 组前 12 项通过，第 13 项 VTE512 读回失败，组终态失败；真实 512 次按下/释放平衡、守卫零拒绝、映射恢复和清理正常。原失败路径没有保存长度/首差，不能据此称生产丢字。

一次获审独立诊断保持原 LF expected 断言，因此仍为失败。它记录 received/expected 均 512，读回 25 CR/0 LF、expected 为 0 CR/25 LF，首差位置 12，`actual == expected.replace('\n', '\r')` 精确为真。原因是自有 VTE 的 raw PTY 将 Return 交付为 CR。仅夹具 readback 做一对一 CR→LF，不折叠 CRLF、删除重复或修补正文；保留 wire CR/LF 数值。纯测试证明额外 CR/LF、CRLF 和缺失换行仍被 exact 门检出。GTK 不变。

修正后只新测基线 VTE512，精确 512，scope 28455.447 ms；没有重跑或覆盖原组失败。20/10 ms 使用新固定工具哈希。20 ms 的外层交互工具句柄在上下文恢复后不可恢复，不能补称该外层原 wait0；其 13 项子 owner 均有原 Popen terminal0、完整 progress 与独立复核证据，没有为此重跑。

## 完成结果

30 ms 有效基线 13 项（原组前 12 项加新 VTE512），20 ms 与 10 ms 各 13 项全部通过。10 ms 原外层 runner 句柄 6912 最终 exit0；全部实际 worker 与目标有正常原 wait 终态。采用 10 ms 常量，首次映射和后续映射等待不变；稳定入口在源码阶段不变。

## 可复现入口

源码试验材料位于 `build/release-pace-r1/`：独立 registry/source manifest、固定 preview、每项 raw/owner/terminal/preservation。先审 registry 和工具哈希，再在已解锁的 GNOME 原生会话中按 `run-r30-r1.py`、获审诊断及新 VTE512、`run-r20-r3.py`、`run-r10-r3.py` 的记录顺序执行；这些一次性 runner 拒绝复用现有路径，不可直接重放已占目录。每项使用 preview 固定的 a17 Python/依赖及冻结 source，实际 source audit44/19。旧失败记录不得删除。

相关 worker/parent/Hybrid/keymap 自动测试最终为 189 passed / 5.01 s，Ruff 检查通过。等待测试适配首轮出现三项断言/编辑错误（旧 25 ms 下限、newline 对应映射等待位置、tuple 记录笔误），修正仅测试后复验通过；产品常量外无新增逻辑。异常 release 重试也明确断言 10 ms，未使用更小值。

Root 对同一工作树的完整检查通过：Ruff/format（296 文件）通过，pytest 1605 passed、3 skipped / 39.70 s。这是源码工作树检查，不是 clean HEAD 验证收据或实际包验收。
