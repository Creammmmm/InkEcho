# 可取消的输入链路节流：40 ms 上限隔离对照

2026-10-28 在隔离 Ubuntu 26.04 GNOME Wayland 桌面，使用从 r3 候选
AppImage（SHA-256 `23b1b77e41e4e3a8fdd30a9a6a892d5b5babeaa9e303fdbcc3b37731e5a1e105`）
解包的真实 Fcitx 桥和私有 Fcitx 服务，自建 GTK3 接收窗口；没有访问用户
桌面、剪贴板、真实凭据、麦克风或云服务。每个场景独立创建目标和任务。

这是**测试脚本包装真实 D-Bus 调用的设计实验**，不是产品实现或包验收。
第 7 次提交前短暂停止仅属于本实验的 Fcitx 进程 80 ms，再恢复，以制造
可控的真实输入请求延迟；不能把这种人工压力当成日常负载。返回后的
字符逐个由真实 Fcitx 桥发送，回执以真实服务响应为准。目标窗口没有
被暂停、强制接管或通过剪贴板写入。

实验算法先以实测请求 RTT 建立基线；超出 `max(2×基线, 基线+10ms)`
的部分转为下一请求前的等待预算，等待预算按 0.75 递减、**配置上限
40ms**。每次等待可由取消唤醒，等待后再次检查取消和任务截止时间；
未发送的后续字符按当时焦点正常发送。该值是对输入链路拥塞的可选调度
上限，并非目标窗口帧同步时间，也不是文字已显示的证据。正常路径不
无条件每字等待 40ms。试验观察真实回复和耗时，未伪造目标绘制事件。

| 实验 | 服务延迟 | 观察结果 |
|---|---:|---|
| 基线，无额外节流 | 80.793ms | 100/100 字精确，额外等待 0 |
| 自适应，预算上限 40ms | 83.088ms | 100/100 字精确，前三次额外等待 40.175、30.224、23.241ms，之后衰减 |
| 自适应，等待中取消 | 80.544ms | 约 10.134ms 后取消唤醒，7 字精确前缀，后续 1.2s 无尾字 |
| 自适应，异步切到第二自有窗口 | 80.786ms | A/B 13/87 字，拼接精确；发送协程未因切窗暂停 |

操作系统调度可能令实测墙钟等待略超预算：切窗首个 40ms 预算实际
41.330ms。响应延迟本身及可取消等待不是接收窗口消费或呈现确认；
此前 `../wayland-frame-hint/` 已演示目标暂停时 Fcitx 回执仍快速返回。
仅一轮每种场景，人工暂停服务与测试输入不能证明真实拥塞下更流畅、
任意窗口可无损切换、物理 Esc 行为或 Ubuntu 24 / IBus / 原生 Wayland
键盘的表现。焦点切换过程中 Fcitx 曾返回安全无目标状态，因此切窗例
100 次已接受提交对应 104 次请求；这不是 104 个字符。

服务切换、Wayland 键盘、IBus 和两个 Ubuntu 版本的同一实际包。当前仅
提供有意义的可取消调度原型及证据，不代表用户要求的接收窗口帧同步
已经实现。
