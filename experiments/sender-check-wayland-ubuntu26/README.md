# D-Bus reply-sender checks: Ubuntu 26.04 native Wayland

The base AppImage SHA-256 was `cd510bade9fbb01e4f321fa33785df9c9f4d0627a1336db9e430f2d51073d1a8`, verified inside the guest. This was the extracted candidate with **three source overlays only**: `platform/fcitx5.py` SHA-256 `c8918f6235325036a4bf605edc76579b2813e71d04343ca41e5edec981a7c6b5`, `platform/framework_detection.py` `3c76d50b2a1af82301e82cf727bad9b1f71d5cef3f4e5e4284530cb5416aadf1`, and `platform/ibus.py` `a64cf45e3a22bacbc82e7db61478a15769fb630812c3919c72f48a105998aa3a`. Exact overlay bytes are preserved as `.py.txt` files. The packaged app and native bridge were otherwise unchanged. Logs include the guest hash checks.

Ubuntu 26.04 GNOME native Wayland was confirmed active in an externally network-isolated KVM container; original and backing disks were read-only and QEMU used a temporary snapshot. Host user credentials were not mounted. Tests used private Fcitx configuration, owned GTK text controls, fixed synthetic text and stub audio/transcription. Fcitx test scripts trace one entry for each distinct `(method, destination, reply sender)` combination; recording reply metadata does not capture user text.

`fcitx.log`: auto and explicit Fcitx each delivered 200 exact characters and each cancellation sample ended after one character. All four legacy Fcitx assertions passed. In those samples `GetNameOwner`, `GetConnectionUnixUser`, and `GetConnectionUnixProcessID` replies had sender `org.freedesktop.DBus`; Fcitx `RuntimeVersion`, `Begin`, `Commit`, and `Cancel` destination and sender matched owner `:1.86`.

The guest was then rebooted; packaged IBus test extension was copied into the isolated guest and manually enabled, and `gnome-extensions info` reported ACTIVE. `ibus-prep.log` confirms the base hash and re-extracted three overlay hashes after reboot. `ibus.log` uses explicit IBus selection: full output reached the target as the exact 200-character test string, then the app reported `ibus_delivery_unknown` and failed with a message to check the cursor; the cancel sample retained the first two characters and ended cancelled. The exact time of the second dispatch relative to cancellation is not established. Replies from `GetNameOwner`, `GetConnectionUnixUser`, and `GetConnectionUnixProcessID` had sender `org.freedesktop.DBus`; IBus `Begin`, `Commit`, and `Cancel` destination and sender matched owner `:1.17`. The old target fixture marks `passed=false` for both IBus samples because its assertions expect a Fcitx backend; the actual contents and events must be examined, and the original log is preserved unchanged.

The Fcitx runner uses `run.sh.txt`, `fcitx-sender.py.txt` as `probes/sender.py`, `fcitx-target.py.txt` as `probes/target-focus.py`, and three overlay files under `/tmp/inkecho-r4-test/overlay/`; run `bash probes/run.sh cd510bade9fbb01e4f321fa33785df9c9f4d0627a1336db9e430f2d51073d1a8 wayland`. For IBus, install the package's `platform/ibus_candidate` into a temporary isolated GNOME Shell user extension, reboot, explicitly enable and verify ACTIVE, re-extract and overlay all three files, copy `ibus-sender.py.txt` and `ibus-target.py.txt` to the same sender/target names without `.txt`, and run the latter with `XDG_RUNTIME_DIR=/run/user/1000`, session bus, actual `XAUTHORITY`, `DISPLAY=:0`, `WAYLAND_DISPLAY=wayland-0`, `XDG_SESSION_TYPE=wayland`, `XDG_CURRENT_DESKTOP=ubuntu:GNOME`, `GDK_BACKEND=wayland`, `GTK_IM_MODULE=ibus`, and `XMODIFIERS=@im=ibus` for `full` and `cancel`.

The temporary IBus extension was disabled and removed; `cleanup.log` recorded an empty enabled-extension list and `disable-user-extensions=false`. QMP powerdown was issued, docker wait returned 0, and the temporary container was removed. This is a small set of controlled samples with overlaid code, not full package acceptance or verification of spoofed replies in a real desktop. It does not establish real audio, cloud, shortcut, arbitrary target apps, focus races, or Ubuntu 24 behavior.
