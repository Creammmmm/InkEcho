# Ubuntu 24.04 candidate cd510: targeted package probes

The unmodified candidate AppImage `InkEcho-0.10.2-x86_64.AppImage`, SHA-256 `cd510bade9fbb01e4f321fa33785df9c9f4d0627a1336db9e430f2d51073d1a8`, was verified inside the guest at the start of both runs. Both guest runs extracted and executed the packaged application with no code overlay; the extracted `fcitx5.py` SHA-256 was `1e939e2ee7f884aa8c08e5c664815454ca1b7b877db97421f4b85afebb856286`. These are targeted tests, not complete package acceptance.

An Ubuntu 24.04.5 KVM guest used an independent QEMU temporary snapshot; original guest and backing disks were read-only in an externally network-isolated container. Guest session was active GNOME X11, then active native Wayland after changing GDM settings inside the snapshot and rebooting. Guest used an isolated temporary Fcitx profile, owned GTK controls, synthetic 200-character text, and stubbed audio/transcription. Host credentials were not mounted; a dedicated disposable VM SSH test key was used only on the host. The tests use the same unmodified scripts as the earlier 207b Ubuntu 24 tests; executed bytes are saved with `.txt` suffix.

- `x11.log`: automatic and explicit Fcitx full output and first-character cancellation each passed (200 characters exact, respectively one before cancellation). The zero-prefix fallback full, switch, and cancellation samples passed: full had 200 exact characters, switch A=2 and B=198 with B focus confirmed and concatenation exact, cancellation A=1. An `XGetWindowProperty[_NET_WM_DESKTOP] failed` warning is retained in `x11.stderr`.
- `wayland.log`: automatic and explicit Fcitx full output and first-character cancellation each passed (200 exact, respectively one before cancellation). All three zero-prefix fallback samples failed with zero received characters and `unsupported_target`; the cancel trigger never ran. No native Wayland generic keyboard fallback support is established.
- In both logs the old owner-replacement sample failed its own assertion after one observed character with `delivery_unknown`, and no `owner_replaced` event. It does not establish that replacement acquired the name. No keyboard fallback was observed for this ambiguous delivery. Do not conflate with corrected owner tests on a different package hash.

Reproduce by copying the AppImage and these scripts (remove `.txt` suffix) to `/tmp/inkecho-r4-test/` and `probes/` in an isolated active unlocked guest and running `bash probes/run.sh cd510bade9fbb01e4f321fa33785df9c9f4d0627a1336db9e430f2d51073d1a8 x11` or `wayland` respectively. The runner tests one package and cleans up its private Fcitx installation.

After tests, a separate SSH request for additional package module hashes did not return; a subsequent SSH connection and QMP greeting timed out while the container remained running. Normal QMP powerdown could not be confirmed. The temporary container was stopped, reported exit 0 with `OOMKilled=false`, and was removed; no writable original disks were mounted. The request failure did not invalidate previously captured logs but prevents claiming a clean guest shutdown or additional guest module-hash verification. The candidate's separately recorded build-time extraction compared all packaged application sources to its snapshot.

Not covered on this SHA: corrected owner-replacement validation, IBus auto selection, browser/terminal targets, physical shortcut, real microphone, live cloud, desktop installation, full audio/protocol chains, Ubuntu 26.04, and all release acceptance gates. Failures above must remain visible; this SHA is a candidate, not a release.
