# Real Fcitx preflight abort followed by an immediate new task

2026-10-29: Ubuntu 26.04.1 GNOME Wayland active and unlocked (`inventory.log`), real guest Fcitx 5.1.19 and packaged experimental plugin (RuntimeVersion 5.1.19). Independent QEMU `-snapshot` guest with base and system disk mounted read-only, no host desktop, outside network, user content or real credentials. Baseline AppImage SHA-256 `45a1d170773e4adb3153d4209008b584c8d79e14ac01e4db6cc7e2bfda5dc451`; only `fcitx5.py` and `output_router.py` were copied from the then-current working tree over the guest extraction for this experiment. `run.log` records original and replacement hashes and labels the test-only override. Consequently this is source-override testing, not acceptance of the unmodified 45a package. Private test Fcitx and an isolated XDG data/config directory were used; session-manager input environment restored by trap, and VM container stopped/removed afterward.

The probe performs 30 repeated pairs against the real plugin: `Fcitx5Bridge.connect()` (Begin), `abort_preflight()` (disconnect with no Commit), immediately a fresh `Fcitx5Bridge.connect()` (new Begin), and ordinary close of the second bridge. It emits no Commit or target text. `run.log` is the first probe version: 30/30 pairs succeeded. `run-r2.log` is a second 30/30 run with the included `immediate.py.txt` instrumentation; it checks the old unique owner through `NameHasOwner` only after the second Begin, and checks the old capability token, directory descriptor and lock descriptor immediately after abort. All 30 second Begin calls succeeded; old owner was absent and old capability closed in all 30. Time from first connect to second ready in that run was 2.028–3.532 ms. There was no artificial wait between abort and second connect; actual connection, capability setup and D-Bus calls necessarily take time. This is a small sample, not a guarantee for all event-loop scheduling or simultaneous callers.

A new Begin succeeding indicates that the real plugin accepted the new task in these samples; no direct timestamp for the old server watcher callback or its state is recorded. The owner check occurs after the second Begin and does not establish its exact relationship to watcher processing. It does not test delayed/blocked real daemon handling, Fcitx on 24, real target input, prior/uncertain Commit cleanup, provider interaction, physical shortcut or complete package acceptance. The delayed synthetic private D-Bus service comparison is separate evidence and must not be presented as the real plugin being delayed here.

For reproduction only on a matching disposable guest, copy the exact AppImage to `/tmp/inkecho-r4-test/`, copy files from this evidence to its `probes/` without `.txt`, confirm active/unlocked Wayland and adjust UID/session/display settings, then run `bash probes/run.sh <full-sha> wayland`. This script explicitly overrides two package source modules, starts a private Fcitx and temporarily changes user-manager input environment; never run against the real user desktop. `run.log` used an earlier unpreserved probe version that did not inspect owner/descriptor state; `run-r2.log` used the included probe and begins with an already-overridden extraction. Guest provisioning is a prerequisite, not re-created from scratch here.
