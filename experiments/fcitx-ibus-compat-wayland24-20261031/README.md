# Ubuntu 24.04 Wayland：Fcitx 的 IBus 兼容服务

在隔离 Ubuntu 24.04.5 虚拟机中测试；容器网络模式为 `none`，快照及基础目录为只读挂载，虚拟机磁盘写层位于容器临时内存层。测试使用隔离客机的 SSH 测试密钥，没有使用宿主用户的输入法配置或 API 凭据。容器与 QEMU 启动参数及退出状态的筛选记录见 `container-receipt.json`（不是完整原始 inspect 输出）；该回执不能独立证明完整磁盘后备链或客机内所有网络状态。执行时观察到插件安装与 Fcitx 自启动配置成功，未单独留存其安装操作回执。客机用户管理器报告 GNOME Wayland 环境；身份日志仅记录筛选后的关键字段，不代表全部会话环境。未覆盖会话输入法环境；该登录发布 `XMODIFIERS=@im=ibus`、`QT_IM_MODULE=ibus`、未设置 `GTK_IM_MODULE`。安装的 Fcitx 版本 5.1.7 同时拥有 IBus 和 Fcitx 服务。产品探针从 systemd 用户管理器环境启动，自动检测选择 Fcitx；两个名称共享同一唯一所有者是依据已核对的检测源码与该分支返回结果作出的间接推断，probe 没有分别输出两个名称的唯一所有者，向已获得焦点的自有 GTK3 原生 Wayland 控件输出 `甲乙丙` 完整接收，见 `identity.log` 与 `probe.log`。

`session-normal.log` 与 `session-cancel.log` 使用旧版 AppImage 的 Python/Qt 运行时及复制的源码（其中检测器文件为当前版本，进程内部输出了文件哈希），执行真实 Session 和本地合成录音、识别、流式润色；正常样本收到六字，首字回调取消后等待约 1.3 秒仅观察到首字。运行时与检测器哈希见日志。这不是最终产品 AppImage 的验收；没有测试物理麦克风、快捷键及真实云端服务。

为验证拼音，停止客机 Fcitx 后在隔离配置中启用已安装的拼音引擎，再从用户管理器重启 Fcitx，未修改输入法环境变量。`compat-preedit.py.txt` 聚焦自有 GTK3 控件并选用拼音，通过 QMP 发送 n、i；`preedit-result.json` 记录两字符预编辑，随后自动输出返回 `fcitx_composition_active`、发送次数为 0，半秒后仍为两字符预编辑、正文为空。上下文退出另报告 `output_failed`；此记录不表明所有组词场景均得到保护。对应探针、Session 驱动、模拟任务、测试窗口和 QMP 脚本均随记录保留，脚本仅适用于上述隔离环境与路径。

结果不证明所有应用、跨窗口切换、输入事件在取消前已在途的情况或目标应用接收确认，也不能代替 Ubuntu 24.04 和 26.04 对同一最终 AppImage 的完整验收。
