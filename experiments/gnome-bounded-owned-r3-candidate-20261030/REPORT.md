# Bounded owned-context R3 review candidate

Independent source only; not merged, installed or enabled on the host. Complete frozen source is dist/gnome-bounded-owned-r3-20261030/candidate-src, based on R2 whose actual85-file desktop evidence is separately archived. This patch stores changed integration files, all7 extension assets, executable source tests and generator. It does not activate the shared product. No commit/version/release was made.

R3 hard-denies all legacy entry points: Begin/BeginBatch return false; Commit/CommitBatch return rejected. These handlers do not access the gate, consume a capability, mutate a pending task or abort a boundary. Old clients cannot obtain the legacy unbounded session on the new service. New bounded methods and authenticated current-owner Cancel remain unchanged from R2; all in-flight outcomes remain unconfirmed.

The new Python client accepts only complete exact bounded signatures. A complete known old schema raises upgrade_required; partial/malformed/duplicate signatures remain unavailable. Unique owner verification and closed-transport cleanup remain. The fixed monotonic deadline can only tighten and cannot be replaced by a producer ACK. No replay follows unknown/expired/cancelled requests. Bridge/Router error normalization, logging registration and user upgrade text now preserve ibus_upgrade_required. Text explains manual disable/uninstall/install and GNOME re-login to load code, and that old applications may show authorization failure until updated/restarted. Installation still does not silently overwrite user extensions.

18 actual Python source tests and13 actual JS gate/extracted-handler tests pass, including old entry points never touching current gate, old/current/foreign owner cancellation, pending owner loss, disable during a boundary, partial signatures, wrong owner and cleanup, diagnostic registration/mapping and upgrade text. Ruff checks and formatting of changed Python files pass. The tests use a fake authenticated transport for Python and actual extracted methods for JS; they are not real IPC or target receipt. New R3 real desktop tests on24/26 are still pending and must not inherit R2 qualification. Test import paths currently point to the persistent frozen source above.

The producer path still depends on GNOME-owned context eligibility and public Clutter/stage scheduling; no receiving-application ACK, arbitrary nested-main-loop guarantee, universal frontend support, cross-window ABA completeness or clipboard fallback is claimed. Local cancellation unseen by the peer can still leave a request in flight before the final service check. The displayed installed protocol/source version is distinct from running Shell code until re-login; strict negotiation refuses old code at zero text attempts.
