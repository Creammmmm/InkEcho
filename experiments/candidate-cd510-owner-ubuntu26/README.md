# cd510 Fcitx owner replacement: Ubuntu 26.04 Wayland sample

The unmodified candidate AppImage SHA-256 `cd510bade9fbb01e4f321fa33785df9c9f4d0627a1336db9e430f2d51073d1a8` was checked in the guest and the packaged `fcitx5.py` SHA-256 was `1e939e2ee7f884aa8c08e5c664815454ca1b7b877db97421f4b85afebb856286`. No package source was overlaid. Ubuntu 26.04 used an active GNOME native Wayland session, network-isolated KVM container, original and backing disks mounted read-only, and a temporary QEMU snapshot. A disposable VM SSH key stayed on the host; no host user credential directory was mounted. The probe used its own Fcitx process, temporary profile, owned GTK target, fixed synthetic text and stubbed audio/transcription.

The corrected owner probe, adapted from `../fcitx-owner-replacement-ubuntu24/` by setting `XDG_CURRENT_DESKTOP=ubuntu:GNOME` for this actual desktop, sent SIGTERM to the private Fcitx process immediately after its first successful Commit reply. A separate test D-Bus connection acquired the service name with `RequestNameReply.PRIMARY_OWNER`; logged old owner was `:1.86`, replacement was `:1.109`, current owner was `:1.109`, and `NameHasOwner` for the old owner returned false. The target contained exactly the first character, the bridge recorded `owner_changed` with accepted count 1, and the application reported `partial_input_failed` and ended failed. No keyboard fallback or replay was observed; the probe's `passed` flag was true.

This is one controlled termination-and-replacement sample, not proof of every crash or restart race. The replacement was a dummy D-Bus owner, not a restarted real Fcitx daemon, and the injected change occurs after a Commit reply, not at every point during one. The sample is not complete AppImage package acceptance and does not establish behavior on other sessions or applications. Exact executed scripts are preserved with `.txt` suffix alongside stdout and stderr. In an isolated active GNOME Wayland guest, put scripts without `.txt` suffix under `/tmp/inkecho-r4-test/probes/`, put the AppImage at `/tmp/inkecho-r4-test/`, then run `bash probes/run.sh cd510bade9fbb01e4f321fa33785df9c9f4d0627a1336db9e430f2d51073d1a8 wayland`.

The guest received QMP system_powerdown, docker wait returned 0, and the temporary container was removed.
