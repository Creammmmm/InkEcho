# GNOME 46 native Wayland: zero-prefix fallback diagnostic

Ubuntu 24.04.5 GNOME Wayland was tested in a network-isolated KVM temporary snapshot with original and backing disks mounted read-only. `session.log` records `Type=wayland`, active, `DESKTOP_SESSION=ubuntu`, `WAYLAND_DISPLAY=wayland-0`, and `XDG_CURRENT_DESKTOP=ubuntu:GNOME`. No host credentials were mounted. The base AppImage SHA-256 `602dab02b4837bb8d30c864dbe50d0413d58d53afb53d9695c7f96f50cdfb756` was verified inside the guest; only the packaged `app.py` was overlaid with current source SHA-256 `775de69704161e08c15e3966bab502b73abf0d4750c05c52d79dfa32ea74d333`. The Fcitx, framework detector, IBus, and router module hashes are recorded in `run.log`. This is not final package acceptance.

A private Fcitx process, its task bridge and an owned GTK TextView using the simple input module were used. Recording and transcription were synthetic; no real user data, microphone, cloud or clipboard was used. The packaged router selected Fcitx, whose replies explicitly returned no target for the first character and then `no_target` with `accepted=0`, `unsent_offset=0`, `uncertain=false`. The instrumentation recorded Fcitx Cancel, then bridge close with both bus and capability cleared before hybrid keyboard connection and authorization. GNOME's keyboard authorization returned `unsupported_compositor`; the application emitted one matching diagnostic and the message naming Ubuntu 24.04 / GNOME 46 and the Ubuntu on Xorg login option, and the task finished failed. The target received zero characters and there was no successful text output or retry after that failure. The legacy fixture's `passed=false` reflects that its success assertion expected full text, not that the observed failure path succeeded.

`cleanup.log` records that the isolated test Fcitx process and capability file were absent and the original user-manager hints were restored (`QT_IM_MODULE=ibus`, `XMODIFIERS=@im=ibus`). The advisory `inkecho-fcitx-candidate.lock` file still existed; this sample does not test lock reacquisition, although the bridge connection and capability object were cleared and the isolated process ended.

This differs from the earlier `candidate-cd510-ubuntu24` and `candidate-207b-ubuntu24` native Wayland runner: those scripts did not pass the actual `XDG_CURRENT_DESKTOP` into the sender, so the observed `unsupported_target` cannot be taken as the correct GNOME hybrid-backend diagnosis. Their original failure records remain valid as observed samples under their own test environment. This controlled sample does not prove every native target, concurrent focus race, microphone, real cloud call, or final package behavior.

Exact scripts are saved with `.txt` suffix. To reproduce, copy the AppImage into `/tmp/inkecho-r4-test/`, place `run.sh`, `sender.py`, `target-focus.py`, and `overlay-app.py` without suffixes under its `probes/`, then run `bash probes/run.sh 602dab02b4837bb8d30c864dbe50d0413d58d53afb53d9695c7f96f50cdfb756 wayland` in an isolated, unlocked GNOME Wayland session. The runner verifies the base hash, overlays the single file after extraction and prints hashes. The temporary guest received QMP system_powerdown, docker wait returned 0, and the container was removed.
