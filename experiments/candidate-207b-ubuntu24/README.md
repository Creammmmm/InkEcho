# Ubuntu 24.04 candidate 207b targeted desktop probes

The tested uncommitted development AppImage `InkEcho-0.10.2-x86_64.AppImage` had SHA-256 `207b97eb667e5439137b51963a2aa09515c7ba50a83496d9c10070e989252685`, checked again inside the guest. The package was extracted in the guest, and the probe ran the packaged `app.py` and `fcitx5.py`, with no source overlay. These are targeted desktop experiments, not complete package acceptance.

An Ubuntu 24.04.5 KVM guest used an independent `-snapshot` temporary write layer; both the original guest disk and its base image were mounted read-only in a network-isolated container. It had an active GNOME X11 session, then an active unlocked GNOME native Wayland session after changing GDM configuration inside that temporary layer. The guest was powered off cleanly, container exit 0, and removed. Neither host user credentials nor a credentials directory was mounted. The host used only a dedicated disposable VM SSH test key. The generated input was fixed synthetic text, the target was an owned GTK widget, and recording/transcription were stubbed.

The first `x11.log` was interrupted by a test-proxy socket idle timeout after four passing Fcitx cases. The proxy timeout was corrected, and `x11-r2.log` completed. The automated `passed` fields and content should be inspected, not the runner exit code:

- X11: automatic Fcitx and explicitly selected Fcitx each delivered exactly 200 test characters, and both cancellation samples stopped after one character. Automatic zero-prefix Fcitx-to-keyboard fallback delivered 200 characters in the normal sample and stopped after one on cancellation. The switch sample failed: A received one character, B had confirmed GTK focus, and B received none. The trace shows repeated Fcitx status 3, a certain zero-prefix `no_target`, then `keyboard_insert_started` and `diagnostic=unsupported_target`. The underlying reason was not logged and cannot be attributed solely to focus switching.
- Wayland: automatic and explicitly selected Fcitx each delivered exactly 200 test characters, with each cancellation sample stopping after one. The normal, focus-switch and cancellation keyboard fallback samples failed with zero characters received and `unsupported_target`; the cancellation sample did not reach its trigger. This does not establish 24.04 native Wayland generic fallback support.
- The older owner-replacement probe in both sessions reported `delivery_unknown` after one character and failed its own assertion; it did not prove that the replacement acquired the service name. No automatic replay was observed. This sample must not be conflated with the separate corrected owner-replacement tests on a different package hash.

Scripts are exact guest-run bytes given a `.txt` suffix. In a disposable guest place the AppImage and script files (without `.txt` suffix) under `/tmp/inkecho-r4-test/` and `/tmp/inkecho-r4-test/probes/`; in each correctly configured active desktop session run `bash probes/run.sh <SHA-256> x11` or `wayland`. The scripts configure an isolated Fcitx process and install its bridge inside the disposable guest only; `run.sh` cleans up its own changes when allowed to finish. The first interrupted attempt's Fcitx process was explicitly stopped before the repeat.

Not tested on this SHA: IBus automatic selection, browser/terminal target coverage, physical shortcut, real microphone, real cloud transcription, packaging integration, general source focus races, or Ubuntu 26.04. These experiments therefore do not satisfy the release gate.
