# Ubuntu 24 X11 focus diagnostic: prerequisite failed

This was a follow-up to the `unsupported_target` result in the candidate 207b Ubuntu 24 X11 focus-switch experiment. The packaged `KeyboardInput` can raise this diagnostic when the active-window PID is missing, X input focus is invalid, X input focus is outside the active top-level window, or XQueryPointer fails. Existing test logs do not identify which condition occurred or when the failing read happened relative to the GTK target's later confirmed focus. The result is a real observed failed sample, but its root cause and whether it is a transient focus transition or an unsupported environment are undetermined.

The diagnostic uses the same AppImage SHA-256 `207b97eb667e5439137b51963a2aa09515c7ba50a83496d9c10070e989252685`, a fresh Ubuntu 24.04.5 KVM snapshot with original guest/base disks read-only, and isolated Fcitx/owned GTK fixtures. It instruments the packaged X11 driver's focus method to capture monotonic time and active-window ID, PID, and input-focus ID only if focus fails; it does not modify packaged application files. Three attempts (`run.log`, `run-r2.log`, `run-r3.log`) all failed the initial test-fixture condition: target A never became active, xdotool reported `_NET_ACTIVE_WINDOW` failure, and no sender or text input ran. A separate root X property query returned `_NET_ACTIVE_WINDOW` 0. Accordingly no focus-failure metadata was captured, no candidate behavior was tested, and these failures are not product failures or proof of the earlier failure's cause. Delaying the third attempt 15 seconds did not restore the prerequisite.

The scripts preserve the exact executed bytes using `.txt` suffix. Reproduction uses the same isolated setup as the candidate-207b Ubuntu 24 record, replacing its scripts with these. The guest was powered off; QEMU returned exit 0 and the disposable container was removed. No user credential directory was mounted. No product fix was prepared because the evidence did not discriminate between failure paths.
