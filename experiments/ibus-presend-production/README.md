# Explicit IBus pre-send status experiment

Product patch: /tmp/ibus-presend-production.patch. Test helper extension is strictly experimental and excluded from that patch. Candidate `/tmp/ibus-prod-build/source/dist/InkEcho-0.10.2-x86_64.AppImage` SHA-256 `8196d002379108cda4aaa653bf8c05975a8e5d313f658000a871f8439ea354ec` contains the product protocol change, but predates a subsequent router change preserving the keyboard authorization callback and parent window. It is not the final package and is not release acceptance.

Ubuntu 24 GNOME X11: guest24/run.log. Ubuntu 26 GNOME Wayland: guest26/run.log, retry.log and lost-retry.log. Original setup output and serial logs are in the same guest directories; setup.sh, run.sh and payload/probes are experiment scripts. sender-first.py and sender-second.py preserve earlier probe variants. Fault helper in payload/fault is unauthenticated and must never be shipped. It makes the isolated guest GNOME Shell's panel reference temporarily unavailable and restores it; it is not a real IBus crash. Original disks and seed images were mounted read-only with temporary overlays; no host credentials or user data used. Both guests were shut down and test containers removed, with shutdown logs retained.

Normal product IBus dispatch delivered eight synthetic characters on each desktop. Forced absent panel produced authenticated no_service from pinned Shell owner, zero IBus commits, then keyboard fallback delivered eight characters. The no-replay case deliberately raises a timeout in the probe after receiving the actual first dispatch reply: one character reached the target and no keyboard retry occurred. This simulates an ambiguous client outcome, not packet loss on D-Bus. Real service disappearance, full provider/audio pipeline, other target types and full same-SHA package acceptance remain unverified. Tests do not establish reliable auto IBus target detection.

The patch retains V2 UUID, bus name and interface. New server replies no_service only when the panel is absent before the first dispatch; old clients treat this unexpected result as unknown. Old server never sends no_service and hence new clients do not perform this fallback. The installer verifies extension hashes and refuses overwrite of the old installed UUID; a user must disable/remove that old installation before installing the new one, so automatic upgrade is not implemented. Source-only changes after candidate build require a new build and separate double-system package acceptance.

Independent isolated source tests: 119 passed across tests/test_ibus.py, tests/test_output_router.py, tests/test_ibus_presend.py, tests/test_ibus_extension.py; targeted Ruff with repository pyproject passed. gate.mjs and gate-test.mjs are in /tmp/ibus-prod-tree and their output in gate.log.

For reproduction in a disposable guest only, restore probe `.py.txt` filenames to `.py` under a `probes` directory alongside `fault` and the exact candidate AppImage on the read-only test share. Shell scripts assume a prepared isolated VM and affect that VM's GNOME settings; never run them on a user desktop. Original serial logs remain under `/tmp/ibus-prod-desktop/guest24/serial.log` and `/tmp/ibus-prod-desktop/guest26/serial.log` on the test host; they are not included in this patch. The scripts and helper are archived test evidence, not an installable product extension.
