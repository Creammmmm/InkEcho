# Fcitx 桥重新启用：Ubuntu 客机源码覆盖验证

2026-10-31 顺序使用隔离客机验证：Ubuntu 24.04、Fcitx 5.1.7，以及 Ubuntu 26.04、Fcitx 5.1.19。客机用户服务管理器分别报告 GNOME Wayland 和 XFCE Xorg；本轮没有独立采集 logind 图形会话状态，因此会话类别仅为环境报告。两个系统均以同一原 0.15.0 AppImage（SHA-256 `94a73232871abaca8c91fb5f58e52059be404f10605955562d39bf31ec64354a`）提供 Python、依赖和原生插件；复制包内 Python 目录，仅覆盖 `inkecho/platform/fcitx5_install.py`，其 SHA-256 为主分支提交 `8c026cd` 中的 `407cd00c47fcf277f247827cc86c5a04b75fd7d1074abbdf3d721552de7ddae9`。脚本逐文件比较包内原始 Python 文件，观察到的差异仅为该文件。原生插件 SHA-256 为 `f67c6b5f2cb7ecd7c915c8062efd3b70284c74b97ced4a597d942c4b39594e44`。这是源码覆盖验证，**不是 0.15.26 应用包验收**。

在每台客机的临时数据、配置和缓存目录中，自启真实 Fcitx；开始前确认客机会话总线没有现有 Fcitx owner，随后验证实际 owner PID 是该 Fcitx 进程，不变更用户会话管理器的输入法环境。通过实际安装器调用安装、刷新、停用及重新启用，并读取真实 `GetAddonsV2`：两系统首次安装及重新启用的 enabled 均为 true；测试通过 Fcitx 控制接口将该插件设为 disabled 后，再调用 InkEcho 停用与重新启用，enabled 均保持 false。未发送文字或读取剪贴板。该测试只验证服务状态和配置管理，不证明完整自动路由或桌面窗口输入。

两系统的最后一个样本在本地调用 Refresh 之前注入 `TimeoutExpired`：描述保留，安装器报告刷新未确认、插件状态未知。该故障没有向服务端发出刷新请求，不能证明真实请求超时后远端是否已执行、加载或退出。发布后同步失败和并发重建的覆盖来自此前离线测试，不是本次客机实验。

两客机探针和启动器 SHA-256 分别为 `529b88912b01b9f352f482e77cb832f57b7091db4c1cb612836ecf661fc838b0`、`ac303116abbd31c60a3f29bc5442a76635838e8f4d8dc294353ec142a8589f5e`；24 和 26 本地结果日志哈希分别为 `308184636ec2d82d92346c206443c2f355447343f0dd24c6c2dac9dec917526d`、`102befffac6151fef379f555950f741631ffbdf2065a3d978f1be1fe4377c5af`。测试结束后自启 Fcitx 退出，私有配置与覆盖目录移除、FUSE 卸载；QEMU 和容器均退出 0、未 OOM，停止快照完整解压校验通过。24 客机启动重新生成 SSH 主机密钥，连接时依据隔离客机串口公钥启用严格校验；严格校验连接命令及其独立退出记录未单独保存，因而本地材料不足以独立核验该连接过程。客机快照、原始串口、SSH 主机密钥、云初始化材料和内部地址只留本地，不纳入本摘要。

未覆盖真实 Session 录音、识别、光标输入、实际 Portal 权限、用户应用、真实拼音及完整兼容矩阵；会话类型也并非两系统所有 Xorg/Wayland 组合。本结果不能替代同一正式 AppImage 在两系统的完整验收或用于 release 宣称。
