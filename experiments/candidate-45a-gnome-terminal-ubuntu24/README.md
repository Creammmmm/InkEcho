# Candidate 45a: Ubuntu 24 Wayland GNOME Terminal Fcitx test

2026-10-29, baseline AppImage SHA-256 `45a1d170773e4adb3153d4209008b584c8d79e14ac01e4db6cc7e2bfda5dc451`. Ubuntu 24.04.5 GNOME Shell 46.0, Fcitx 5.1.7, GNOME Terminal 3.52.0-1ubuntu2; actual desktop session Wayland, active and unlocked (`inventory.log`). The terminal server's own native Wayland versus XWayland backend was not established. Independent QEMU container with original guest disk/base/seed mounted read-only and temporary snapshot; initial X11 session was switched to Wayland only in that disposable layer and rebooted. No host desktop, user content, credentials, clipboard or outside network. The package was extracted without source replacement; the container was stopped and removed after testing.

`terminal.log` retains three samples. A real GNOME Terminal launches a self-created Python process that reads input in raw mode, not a shell. The packaged Session uses a substitute recorder and recognizer emitting `风云日月山川河海` repeated 25 times and a private Fcitx bridge. The sender deliberately waits 25 ms after each bridge response so that cancellation and switching can be controlled; this is not a speed measurement.

* Full: 200/200 received exactly, 200 status-1 commits, succeeded.
* Cancel: the driver sends SIGUSR1 after the first `风` is observed. At signal and completion the reader held one character, one commit occurred, cancellation handler ran, outcome cancelled. This does not verify a physical Escape key or retract an in-flight request.
* Controlled switch: after the first character, the sender is paused, a second terminal/reader is started, then it is resumed after a two-second wait. The readers received 1+199 characters, concatenation exact, 200 commits, succeeded. The second window focus was not independently measured; actual receipt shows this sample's routing only, not all unpaused focus races.

Fcitx status 1 signifies attempted bridge submission, not an arbitrary application's consumption or display confirmation; this test's receiver directly records bytes. It does not cover real microphone/cloud ASR, browsers, actual shell or CLI, physical shortcut, IBus, arbitrary target focus races, physical frame presentation, all cancellation timings or all apps. This is targeted candidate evidence, not complete dual-system package acceptance or a release claim.

Reproduce only in an isolated matching guest: put the exact candidate in `/tmp/inkecho-r4-test/`, copy the included `run.sh.txt`, `sender.py.txt`, `terminal_driver.py.txt`, `reader.py.txt` into its `probes/` directory without `.txt` suffix, verify active/unlocked Wayland session, and run `bash probes/run.sh 45a1d170773e4adb3153d4209008b584c8d79e14ac01e4db6cc7e2bfda5dc451 wayland` from the root directory. Scripts assume UID 1000 and desktop session bus/display, start a private Fcitx and temporarily change session environment; do not run on a user desktop. The probe credential is a fixed synthetic string. VM provisioning was not independently recreated.
