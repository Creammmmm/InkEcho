# Chrome / Fcitx 焦点计数诊断准备（尚无运行结果）

此前 Ubuntu 26.04 GNOME Wayland 中 Chrome XWayland 切焦后，测试页报告焦点而 Fcitx 桥持续返回状态 3，见 `experiments/chrome-fcitx-sequenced-ubuntu26/README.md`。产品桥把零个和多个焦点输入上下文均映射为状态 3；网页焦点不等于 Fcitx 焦点，现有证据不能区分这两种情况。

本目录的临时独立 Fcitx 插件在 `/focusprobe` 暴露 `CountFocus`，通过同一输入上下文管理器的 `foreachFocused` 报告数量及各上下文的前端和 `program()`；不会读取输入文字或周边文本。测试 sender 在首个状态 3 后另发诊断请求，因此它观察的是**随后某一瞬间**，不能证明状态 3 被产生时的上下文集合；即便观察到一个上下文，也可能是焦点已变化，不能据此改变路由行为。此插件不能作为产品修复，也没有实现焦点恢复。

2026-10-29 在无外网的 QEMU Ubuntu 26.04 快照中编译成功（`cmake --build` 到 100%）。测试使用原镜像、基础盘和种子只读，Chrome 临时空配置、本地合成网页以及候选包 `f6ceb6311069f85b180bafd446f546247b5e592735ba26035455a571c5eb5164`；没有使用真实用户资料。运行时 SSH 在 banner 阶段超时、QMP 也超时，客机内日志无法取回；不能证实插件确已加载、是否复现状态 3 或输出了任何计数。隔离容器停止后退出码 0、OOMKilled false 并已移除；未确认客机内正常关机。原镜像未写入。以上不是产品验收，不可宣称测试通过。

`probe/` 与 `scripts/` 是实际传入客机的源文件；`.txt` 后缀用于保留字节且避免当成产品源文件。构建命令 `cmake -S probe -B /tmp/focusprobe-build && cmake --build /tmp/focusprobe-build -j2`。运行脚本依赖先将构建产物、同哈希候选包、独立 Chrome 副本和三份脚本布置到脚本指定的客机 `/tmp` 路径，并仅在私有临时桌面会话执行；具体环境准备尚未形成可独立验证的一键流程。

隐私检查：插件不访问文本字段，但 `program()` 是客户端提供的应用标识，不一定无敏感信息，运行必须使用隔离会话。测试网页和日志仅设计使用固定合成文本；若用于其他环境，网页 DOM、日志和进程标识可能包含用户内容，不应采集。测试脚本中的 `probe-key` 是固定合成测试值，非认证凭据。未保存本次客机测试日志，也未复制真实 Chrome 用户目录或密钥到记录。
