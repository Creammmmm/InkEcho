# Ubuntu 26.04 candidate cd510b targeted input tests

AppImage version 0.10.2 SHA-256 `cd510bade9fbb01e4f321fa33785df9c9f4d0627a1336db9e430f2d51073d1a8` was tested in an isolated Ubuntu 26.04.1 QEMU `-snapshot` guest. Original guest and base images and the test input share were read-only; the container had no external networking. The candidate was extracted and its bundled Python executed the bundled application without source overlays. Tests used an isolated Fcitx 5.1.19 service, owned GTK3 controls, fixed synthetic audio and a stub transcription returning 200 synthetic characters; they did not use a real microphone, network API, user credentials, user text, or clipboard.

`wayland.log` records an active, unlocked GNOME Wayland session with `DESKTOP_SESSION=ubuntu` and `XDG_CURRENT_DESKTOP=ubuntu:GNOME`. Auto and explicit Fcitx each delivered all 200 characters exactly and reported `succeeded`. Each corresponding cancellation sample delivered the correct first character, then reported `cancelled`; no later characters were observed in the probe's settling interval. For a simple-module control, Fcitx returned `no_target`, accepted=0, unsent offset=0, uncertain=false; the native hybrid keyboard was connected and authorized and delivered all 200 characters, reporting `succeeded`. That case's old test `passed=false` checks only X11 `keyboard_insert_started`, not Wayland `hybrid_connect`/`hybrid_authorize`; the conclusion comes from the actual event sequence and exact captured content, without changing the log.

`x11.log` records active, unlocked XFCE X11, with `DESKTOP_SESSION=xfce` and `XDG_CURRENT_DESKTOP=XFCE` both verified in the user service environment. Auto and explicit Fcitx each delivered 200 characters exactly and succeeded; each cancellation stopped after the first character. The simple-module zero-prefix sample explicitly returned safe Fcitx `no_target` before `keyboard_insert_started`, then delivered 200 characters and succeeded. All five X11 probe assertions returned true. Session switch and automatic-login configuration changes were confined to the disposable guest snapshot.

`metadata.log` records version and hashes of bundled application files. The scripts retain their exact guest-run bytes with `.txt` suffix. To reproduce in each isolated graphical session, copy the AppImage and the three scripts without `.txt` under `/tmp/inkecho-r4-test/` and its `probes/` directory; execute `bash probes/run.sh cd510bade9fbb01e4f321fa33785df9c9f4d0627a1336db9e430f2d51073d1a8 wayland` or `x11`. The runner temporarily sets the guest user-service input-module environment, installs and enables a private Fcitx bridge, and restores recorded environment after testing. It does not modify package code. The probe logic and output instrumentation are not part of the candidate package.

These are targeted synthetic tests on one owned GTK control per case, not complete package acceptance. They do not establish Ubuntu 24.04 behavior, IBus automatic selection, shell focus races, browser or terminal compatibility, real input devices, cloud service operation, physical shortcuts, first-time authorization or all desktop integrations. Following tests, no Fcitx process was reported in the guest metadata check; the guest shut down normally, Docker wait returned 0, the container and temporary VM test key were removed.
