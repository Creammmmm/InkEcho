# Fcitx 小批量输出阶段 0 对照（2026-10-31）

本目录供独立审查，记录一次**测试专用原型**，不代表产品已实现批量输出、也不构成 AppImage 验收或兼容性承诺。测试脚本在进程内临时替换分批生成器；Fcitx Python 源码、原生插件及其 40 毫秒提交间隔均未修改。输入、网页和凭据均为测试生成；不使用剪贴板或真实云服务。

产品客户端 `fcitx5.py` SHA-256 为 `709331bf404a6a7ae59f0ea0670896ecf2cadb1896e27a7b6eaf2b9e9185f4c8`。产品插件 `libinkecho.so` SHA-256 为 `f67c6b5f2cb7ecd7c915c8062efd3b70284c74b97ced4a597d942c4b39594e44`。两个测试客机使用各自只读基盘、全新隔离写层和关闭外网的容器，未共享其他任务的运行写层。

## 实测范围

两套环境分别为 Ubuntu 26.04 GNOME Wayland + Chrome 原生 Wayland，以及 Ubuntu 24.04 GNOME Xorg + Chrome X11。均使用真实系统 Fcitx 和自有离线网页，发送固定的 200 个汉字。每个批量大小 1、2、4、8 分别测试两次固定焦点、同页面 A→B 切焦、首批发送后取消，共每系统 24 个样本；逐码点及焦点/取消断言均通过。

| 1 | 8.172–8.645 秒 | 8.552–8.617 秒 | 1 字 |

完整统计见 [26 Wayland](evidence/wayland26.json) 和 [24 Xorg](evidence/xorg24.json)。批次是在一次提交时选择焦点的整体；焦点或取消发生在提交后时，已尝试的一整批不能撤回，也不能根据不明确结果重放。固定等待和 D-Bus 返回均不能证明目标应用消费或显示了文字。

26 Wayland 另设置每个页面 input 回调约 15 毫秒忙等待并启动两路 CPU 忙循环，每批次的固定、同页面切焦及取消各一例均通过，[去敏记录](evidence/wayland26_load.json)。未采集实际 CPU 占用，不能量化负载强度。真实虚拟键建立 Fcitx 拼音 `ni` 后，四字批次被 `fcitx_composition_active` 拒绝、尝试数为 0，网页组词状态与事件不变；虚拟空格完成“你”后，后续三字输出成功，[记录](evidence/wayland26_preedit.json)。这不是物理键盘或其他输入法的普遍验证。

## 换行、分段与失败

[朴素按码点切片的失败](evidence/wayland26_naive_newline_failure.json)中，独立换行未进入网页，虽然发送端计数为 11；这说明不能直接将当前生成器替换成简单切片。另一个测试原型先使用现有 `NeighborPlanner` 保留真实换行邻字单元，再合并为受原生协议约束的小批次；换行与后续真实字符放在不同流片段，并包含 é、Ω、😀 及跨片段的 👩‍💻 示例。1、2、4、8 字批次各两次最终文本逐码点一致，[记录](evidence/wayland26_unicode.json)。单例最终结果不保证任意复杂字符簇、跨焦点或中间呈现语义；超过协议边界的字符簇仍需沿用已验证的安全处理。

两个真实窗口测试分别使用 `Page.bringToFront` 和客机虚拟 Alt+Tab，均未能在发送前确认原窗口焦点，因此在输出前停止；[第一次](evidence/wayland26_cross_window_bringtofront.txt)、[第二次](evidence/wayland26_cross_window_alt_tab.txt)。**这些是夹具失败，不证明产品故障，也不证明跨窗口可靠。** 原生 Chrome 的两次 sandbox 启动失败，以及两次取消路由记录夹具错误，也保留在 [evidence](evidence/)；修正仅发生在一次性客机或测试脚本，未禁用 Chrome sandbox。

## 脚本与清理

[scripts](scripts/) 是执行过的测试专用脚本，含隔离客机的绝对路径，不能直接用于用户桌面。它们依赖对应客机镜像、Fcitx 插件、Chrome、D-Bus 和隔离夹具；不是开箱即用的测试套件。归档 JSON 仅保留合成文本、结果、码点计数和必要状态；不含用户配置、真实页面、API 密钥或录音。更完整的非源码级原始日志和同一轮清理回执保留在本地 `build/fcitx-batch-stage0/`、`build/fcitx-batch-stage0-24/`。

实验后两台客机均恢复 profile，移除实验 addon、autostart 和输入法环境配置，卸载测试共享，并正常关机，容器退出码均为 0。需要独立审核：Unicode/协议边界、批内焦点与取消语义、响应丢失及服务重启时不重放、真实跨窗口、GTK/Qt/终端、两系统其余会话、实际物理设备和同一最终 AppImage 的双系统验收。此前通过的两套合成 Chrome 矩阵不能替代上述验证。
