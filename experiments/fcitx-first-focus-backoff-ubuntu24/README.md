# First-focus retry backoff: Ubuntu 24.04 X11 overlay experiment

The base AppImage SHA-256 was `207b97eb667e5439137b51963a2aa09515c7ba50a83496d9c10070e989252685`, verified in the guest. Exactly one packaged file (`inkecho/platform/fcitx5.py`) was overlaid in the extracted app; the overlaid file SHA-256 was `1e939e2ee7f884aa8c08e5c664815454ca1b7b877db97421f4b85afebb856286`, and its exact source is `fcitx5.py.txt`. The guest was Ubuntu 24.04.5 GNOME X11, launched from original/backing disks mounted read-only using a temporary QEMU snapshot inside an externally network-isolated container. Host user credentials were not mounted. The sender uses the actual packaged Session and a synthetic recorder/transcription; the target is owned GTK and all text is synthetic. The shell, sender and target scripts exactly match executed bytes (stored with `.txt` suffix); only Commit timestamps and statuses are instrumented, without recording other user data.

All three assertions in `run.log` passed:

- `recover`: initial Button focus was confirmed, a target TextView was presented after the sender started, and it received the complete ordered 200 characters; three no-target Commit statuses occurred before recovery, with consecutive start intervals 10.8 and 20.9 ms. No keyboard fallback was used.
- `cancel`: Button focus was confirmed; after seven no-target responses cancellation was requested and the session ended cancelled, with zero text in the target. No Commit started after the timestamp of cancellation in this run; no keyboard fallback occurred. Intervals were 11.3, 23.6, 43.6, 43.1, 43.0, 43.2 ms.
- `fallback`: the TextView used the simple GTK input module, and Fcitx returned certain zero-prefix no-target (`accepted=0`, `unsent_offset=0`, `uncertain=false`); only then was keyboard fallback invoked and the target received exactly 200 characters in order. Thirteen no-target Commit attempts had consecutive start intervals 11.4, 22.3, 42.8, 43.2, 45.0, 43.3, 43.5, 42.9, 43.0, 43.7, 44.6, 45.7 ms.

These are single controlled samples; waiting up to 40 ms between retries can add recovery latency and scheduling causes observed intervals to exceed 40 ms. The sample does not prove all target apps, Ubuntu 26.04, other display sessions, or real audio/shortcut/cloud paths. This is an extracted candidate plus source overlay, **not** acceptance of a newly packaged artifact; neither this run nor the old SHA qualifies a later build for release.

To reproduce, copy the same AppImage and scripts (remove `.txt`) to `/tmp/inkecho-r4-test` in an active, unlocked, isolated GNOME X11 guest and run `bash probes/run.sh 207b97eb667e5439137b51963a2aa09515c7ba50a83496d9c10070e989252685 x11`. The runner verifies the base hash before extracting and overlays the single file afterward. It restores its temporary Fcitx environment on completion.
