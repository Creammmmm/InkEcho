# Fcitx repeated-install investigation

In the source snapshot, `FcitxInstaller.install()` reports failure if an identical, already verified installation exists, because staging refuses any existing description. `before.log` is the added regression test failing on its second install. The separate proposed `/tmp/inkecho-fcitx-idempotent.patch` checks the existing exact per-version description and binary hash and returns success without rewriting them; differing or modified descriptions still go through staging's no-overwrite failure. `targeted.log` records 15 passing installation/staging tests, including unchanged inode/mtime and preservation of a modified description. `after.log` is an incomplete broader test run interrupted after 29 progress dots; it is not a pass and its cause is not established.

Isolated Ubuntu 26.04.1 GNOME Wayland, Fcitx 5.1.19; active/unlocked guest with original disk/base/seed read-only and disposable QEMU snapshot, no user credentials, no real microphone or outside network. The baseline candidate SHA-256 is `6d537689d5e30f4611f1e8376025705bf5fcc26c9198c9cda7c51717d434e34a`. The extracted package's installer alone was replaced for this experiment by `installer-patched.py`; `run.log` records original installer SHA `1cf5b7ae2081ad0f915aba94949d85f965446ca29e31116dd7fdc31ff6dbec8d` and patched SHA `f53e8699bafad46e03c60d6e0f82d881be658e65b210cba2e95701a40ffd20a6`, and clearly labels the override. This is a patched-source experiment, not acceptance of the original candidate or a rebuilt package.

`run.log`: private service before install has no `/inkecho` object; two installs succeed with identical inode and mtime; explicit enable yields detected Fcitx and live RuntimeVersion; restart retains auto detection. Disabling removes the published config and detection returns null while the already loaded plugin still answers, as expected until the daemon exits. `run-r2.log` repeats the test with the existing already-overridden extraction, then reinstalls and enables after disable, disables again, restarts, and observes detection null and `UnknownObject` for `/inkecho`. The first-run missing-object errors and the final missing-object error are expected observations, not hidden successes. Both runs alter only a private test XDG data/config directory and restore saved user-manager input method environment on exit; the VM container was stopped and removed. The underlying image was never mounted writable.

For reproduction only in a matching isolated guest, copy baseline package and files `run.sh`, `probe.py`, `installer-patched.py` into `/tmp/inkecho-r4-test/` and its `probes/` directory. Confirm session active Wayland, adapt UID/runtime environment if necessary, and run `bash probes/run.sh <full-baseline-sha> wayland` from `/tmp/inkecho-r4-test`. The script explicitly replaces an extracted package file and starts/restarts a private Fcitx daemon; never use on the real desktop. Provisioning of the VM was not independently recreated, tests do not cover input to targets, real providers or physical hotkeys, Ubuntu 24 runtime, installer races, or complete package acceptance.

The archived Python probe files have a `.py.txt` suffix to preserve their exact executed bytes. When copying them to the isolated guest, remove the final `.txt` suffix so the original shell scripts find their expected `.py` filenames. Do not edit the scripts or historical logs.
