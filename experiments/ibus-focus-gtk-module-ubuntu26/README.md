# GNOME Wayland Shell focus and explicitly selected GTK IBus

Ubuntu 26.04.1, GNOME 50.1, active unlocked native Wayland session ran in a network-isolated QEMU `-snapshot` guest. The original disk, base image and 9p input share were mounted read-only. The pre-existing IBus daemon and engine `xkb:us::eng` were used; input sources remained `[('xkb', 'us')]`. No input method was switched, no user content was queried, and no clipboard or actual microphone was used. The temporary extension and all changes were confined to the discarded snapshot.

The exact probe scripts are included with `.txt` suffixes. Five owned GTK3 windows were created: Wayland with `GTK_IM_MODULE=ibus`, XWayland with `GTK_IM_MODULE=ibus`, native Wayland button, Wayland with `gtk-im-context-simple`, and XWayland with `gtk-im-context-simple`. The extension activated windows by their own test names and returned only the Shell's `currentFocus` boolean, Shell context path, and matching owned window title; then its IBus panel method attempted to send the fixed synthetic character “甲”. Only the owned controls' synthetic contents were read. `probe.log` contains unmodified output, exact source hashes, session type, engine, and extension `ACTIVE` state.

The native Wayland and XWayland IBus entries were each focused twice. Each time `currentFocus=false` while the corresponding owned entry received “甲” (cumulative “甲甲”); the IBus current path at the subsequent observation was `InputContext_3` and `_4`, respectively, while Shell's own path was `_2`. The button and two simple-module controls each had `currentFocus=false`, remained empty, and the subsequently observed IBus current path was `_1`. Path numbers are run-specific and must not be hardcoded. The activation method reported the expected owned window name, and actual delivery to each IBus entry proves those observed samples accepted the synthetic character.

Therefore `currentFocus=false` alone is not a safe reason to reject an IBus panel submission, including for a native Wayland GTK widget that opts into IBus directly. The previous positive result for a default native widget may be a useful restricted signal, but does not generalize across GTK modules. This test does not prove a safe alternative identity test, atomic delivery, behavior under focus races, arbitrary applications, Ubuntu 24.04, or packaged InkEcho. The reported current IBus path was queried after the panel call, not atomically with the focus check. No automatic routing is enabled on this evidence.

To reproduce only inside a disposable Ubuntu 26.04 GNOME guest with IBus installed, copy `extension.js.txt` and `metadata.json.txt` without `.txt` to the user GNOME extension directory named by the metadata UUID; restart the isolated guest so Shell discovers it. Place `actor.py.txt`, `probe.py.txt`, and `run.sh.txt` without `.txt` in a read-only 9p share tagged `inkecho_input`, then run `bash run.sh` in the isolated user's graphical-session environment. The script enables the temporary extension and executes the probe. Normal guest shutdown returned Docker wait 0; the container and temporary SSH test key were deleted, leaving the original images unchanged.
