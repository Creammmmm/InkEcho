# Framework-hint conflict: Ubuntu 26.04 isolated Wayland

Using candidate AppImage SHA-256 `602dab02b4837bb8d30c864dbe50d0413d58d53afb53d9695c7f96f50cdfb756`, verified in guest, this read-only probe calls the packaged framework collector, public detection wrapper and owner-identity probe, without sending or reading any text. Packaged code was not overlaid. The guest was Ubuntu 26.04 GNOME native Wayland in an externally network-isolated KVM container with original and base disks mounted read-only and a temporary QEMU snapshot; no host user credentials were mounted. Test Fcitx and configuration were isolated within the snapshot. Exact probe scripts and logs are preserved with `.txt` script suffixes.

`run.log` used a live private Fcitx process and installed candidate bridge. Both `org.freedesktop.IBus` and `org.fcitx.Fcitx5` names were verified as owned by Fcitx. With all user-manager hints set to Fcitx, both collector and detector returned `fcitx` pinned to `:1.86`. With all hints set to IBus while Fcitx still owned both names, or with a mixed GTK/Qt/XIM environment, both returned null. Restoring the Fcitx hints again selected the same pinned owner.

After the test Fcitx was stopped, the guest's IBus daemon again owned `org.freedesktop.IBus` and Fcitx had no owner. `inverse.log` shows that consistent IBus hints produced an IBus collector hypothesis but the product detector returned null because automatic IBus is intentionally disabled. Stale all-Fcitx hints and mixed IBus/Fcitx hints produced null from both collector and detector. Both scripts restore the prior user-manager environment, recorded in `cleanup.log`; test Fcitx was stopped.

These are controlled service-ownership and **simulated hint changes**, not a complete user-driven switch of desktop input methods or proof that a currently focused widget uses a detected framework. The probe does not establish target receipt, Fcitx-to-IBus transitions during an in-flight commit, or all combinations of two independently active service owners. No product bug was established and no product patch was made.

Reproduce in a disposable active GNOME Wayland guest by placing the exact AppImage and these scripts (remove `.txt`) in `/tmp/inkecho-r4-test` and `probes/`; run `bash probes/run.sh 602dab02b4837bb8d30c864dbe50d0413d58d53afb53d9695c7f96f50cdfb756 wayland`, then `bash probes/inverse.sh`. Both scripts alter only the disposable session's user-manager environment and restore prior values on exit. The guest received QMP system_powerdown, docker wait returned 0, and the temporary container was removed.
