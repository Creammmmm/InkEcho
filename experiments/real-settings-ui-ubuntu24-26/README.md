# Real settings page and ConfigStore: isolated Ubuntu 24 / 26

These samples use the actual current-source `CompatibilityPage`, `ConfigStore`, `Session`, and controller in a temporary source snapshot (full file hashes in `source-sha256sums.txt`) displayed on real isolated Qt desktops. Qt/Python and third-party libraries came from extracted candidate AppImage SHA-256 `602dab02b4837bb8d30c864dbe50d0413d58d53afb53d9695c7f96f50cdfb756`; application source was deliberately loaded from the snapshot instead of the package. Therefore these are source-based GUI tests, not package acceptance. Ubuntu 24.04.5 used GNOME X11 and Qt `xcb`; Ubuntu 26.04 used GNOME native Wayland and Qt `wayland`. The guests were isolated KVM snapshots, original and backing disks mounted read-only, without external network or mounted host credentials. Every ConfigStore root was a fresh temporary guest directory removed afterward.

`probe.py.txt` checks that default values are auto/40/40, operates the visible page to save IBus/75/60, destroys the page and Session, creates a new real ConfigStore/Session/page and verifies those values, then starts a task and changes the controls to keyboard/90. The running task retained the previous settings, and after cancellation a new task observed keyboard/90. `ui24.log` and `ui26-r2.log` both show these checks passed. The first Ubuntu 26 run `ui26.log` also passed its assertions but emitted a misleading `reloaded` log field after the settings had subsequently changed; the probe was corrected to capture the reload at the right time and rerun. Both logs are retained.

`restart_probe.py.txt` tests a stronger process boundary: a first visible Qt process writes Fcitx/82/64 and exits; a second independent process creates a fresh ConfigStore/Session/page from the same temporary root and verifies the persisted values. Both phases passed on Ubuntu 24 (`restart.log`) and Ubuntu 26 (`restart26.log`).

The recorder, credential lookup, and task authorization are controlled substitutes in the task-snapshot probe; no microphone, real key, network, input method, or actual text output is exercised. The process-restart probe does not start a recording. These samples do not prove the platform-specific timing settings affect any native Wayland or input-method backend: their labels and current runtime scope remain X11. They are not comprehensive GUI coverage, packaged application launch validation, or release acceptance.

To reproduce, copy the source snapshot and scripts to a disposable desktop guest, extract the 602 candidate for its Python/Qt runtime, set `PYTHONHOME` to the extracted `usr`, prepend the snapshot root and extracted `packages` to `PYTHONPATH`, set the bundled library and Qt plugin paths, and execute `probe.py`; run `restart_probe.py <same-temp-dir> write` then in a separate Python process `restart_probe.py <same-temp-dir> read`. Use the actual guest session bus, display, and corresponding Qt platform (`xcb` or `wayland`). All three guest instances received QMP system_powerdown, docker wait returned 0, and their temporary containers were removed.
