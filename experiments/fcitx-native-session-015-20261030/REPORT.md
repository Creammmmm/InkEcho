# InkEcho 0.15.0 原生 Wayland Fcitx 完整 Session 补充实测

2026-10-30：三台客机顺序运行同一实际 AppImage，SHA-256 `94a73232871abaca8c91fb5f58e52059be404f10605955562d39bf31ec64354a`，来源提交 `76aeb33`。Ubuntu 24.04.5/GNOME46/Fcitx5.1.7 与 26.04.1/GNOME50.1/Fcitx5.1.19；仅在隔离会话使用包内 Fcitx 插件。测试控件实际 GObject 类型为 `GdkWaylandDisplay`，先检查活动窗口、焦点及自有 PID；不使用剪贴板。包来自 FUSE 挂载，应用模块来自包内，未覆盖生产代码。录音以虚拟音频设备播放合成信号，ASR 与润色使用本地合成 TLS 服务，不代表真实麦克风或供应商云端。

## 完整 Session 与当前焦点

两个系统中，真实 Session 在录音开始后将焦点切到自有第二 GTK3 TextView，auto 实际选择 fcitx；完整语音、模拟转写及润色后，新控件准确接收 22 码点（中文、英文、重音、希腊文、换行），旧控件为空。两系统部分取消样本在收到首字时请求取消，最终均收到前 2 字；第二字可能为取消竞态中已发送或晚到的前缀。进程退出后的 1.3 秒观察窗口收件内容保持不变。此结果是本次受控条件，不能解释为任意取消时刻均只会多收到一字；已发送内容不能撤回。

## 活动拼音期间的完整 Session

独立真实 GTK3 Entry 和官方 Fcitx 前端加载；在核对 PID、原生 Wayland、活动窗口及焦点后，用客机虚拟硬件键盘输入 `n`、`i` 形成长度为 2 的活动拼音预编辑。保持该控件焦点并运行真实完整 Session：两个系统均报告 `fcitx_composition_active`，任务 `failed`、输出字符数 0；Session 完成后等待 1.3 秒，目标已有文字和预编辑长度均保持不变。随后真实空格按键完成预编辑，上屏“你”。该场景是安全阻止语音输出，非在拼音进行时成功输入语音文字。虚拟键盘的保护检查记录在相应 `keys.json`；没有向用户真实桌面发送键。

24 的首轮活动预编辑 Session 已产生正确诊断且文字/预编辑未变，但本地模拟润色连接因提前失败发生 ConnectionResetError，旧 fixture 的成功路径断言未允许它，故 fixture 退出1；第二轮修改该 fixture 后，真实 Session 断言通过，但自有目标状态文件非原子写入导致外层偶发 JSON 读取错误，故仍退出1；第三轮仅将测试状态写改为原子替换后通过。这些失败和日志都保留，未改生产代码。独立 router 的拼音保护样本与完整 Session 样本分别记录。

原始命令、测试脚本、包审计、目标状态、诊断和失败日志保存在 `raw-byte-archive.json`，每项有解码后大小和 SHA-256，可逐项解码复核；未包含虚拟机或浏览器完整分发。各客机按顺序停止，实际包挂载和测试 Fcitx 进程消失，框架环境提示恢复，资源检查通过；Docker 和 QEMU 正常退出0、无 OOM。完整停止快照经全流解码核验，外部保留路径/哈希见 `external-retained-pins.json`。

该结果不覆盖真实设备和云端、其他浏览器/控件、输出中跨窗口或跨后端切换、所有输入引擎、所有取消竞态或全部长文本。原生 IBus 到 XWayland 跨后端中途停止等已知限制没有因此修复，不能将这些样本扩大为全部平台组合已完成。
