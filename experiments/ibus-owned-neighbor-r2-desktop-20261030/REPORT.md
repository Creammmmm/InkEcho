## Cleanup, provenance and limitations

Both guests restored the exact7original asset hashes and all3original GNOME extension settings, released their original FUSE mounts and passed resource checks (capabilities0, free locks, no matching package process/audio, Fcitx ownerfalse). The checker sampled specified XWayland key states;24's list did not include Return,26's included Return. This is not an independent native seat/map snapshot. Both normally powered off, container Exit0/PID0/OOMfalse. The stopped child archives were full-stream hash-verified by the wrapper and independently decompressed/hash-verified again during evidence assembly; identities.json gives exact archive/raw hashes and sizes. Parents, sources, screenshots and complete raw archives remain in persistent `dist/ibus-owned-neighbor-r2-desktop-20261030`.

Final runners and retained intermediate variants are under each reproduction directory. Some test-only runners were edited between failures and corrections, so the final input snapshot is not claimed as a per-run original-source receipt for every intermediate failure. In particular the shared hardlinked GTK helper gained26 discovery/display metadata after24 execution;24 raw result lacks that extra metadata. Candidate application src was immutable and independently matched the same source manifest in both guests throughout final assembly. The initial Ubuntu26 a-not-defined failure was0dispatch before a bounded document-ready check. Private runner parser/copy/dependency failures are preserved. `/tmp` evidence-copy EDQUOT occurred only after both guests stopped; complete originals were already persistent, and review staging moved to projectdist without deleting unique data.

The local R2 source/model regressions (124targeted,344related Python and18Node model cases) precede this desktop run; they do not substitute for a full workflow or actual new package gate. No Xorg, XWayland browser, other application, DeepSeek/Codex page, cloud provider/microphone, oldFcitx3 desktop migration, arbitrary pending-RPC cancel/expiry/replace, physical global shortcut, arbitrary preedit engine, target receipt ACK or lossless cross-window behavior is established. Same-window DOM field switching is not OS-window activation coverage. Unconfirmed input must never be replayed, including the observed missing space. A new packaged candidate still requires the project same-version/same-SHA dual-Ubuntu actual-package gate before stable/deployment/release.

Suggested next action: independently review the concrete24 missing-space race and contenteditable control scope; retain the source candidate as limited qualification only. Do not announce a universal Chrome/IBus fix or silently broaden support from these samples.
