# Candidate 6d: Ubuntu 26.04 X11 Fcitx and fallback observations

2026-10-29, candidate AppImage SHA-256 `6d537689d5e30f4611f1e8376025705bf5fcc26c9198c9cda7c51717d434e34a`; package extracted unchanged and hash checked before each test. Guest Ubuntu 26.04.1, XFCE X11, Fcitx 5.1.19; session active and unlocked. The disk and image files were read-only, QEMU `-snapshot` used a disposable write layer, no user data or keys were mounted, and the isolated container was removed after tests. Switching from default GNOME Wayland to XFCE X11 and reboot affected only the snapshot.

`xfce.log` contains the correct-desktop-environment rerun: automatic and explicitly selected Fcitx each received exactly 200 synthetic characters; cancellations each retained the first character and reported cancelled. A simple input context produced Fcitx `no_target`, accepted=0, offset=0, uncertain=false, then X11 keyboard fallback received all 200 characters and succeeded. The controlled focus-switch sample delivered 1+199 characters to the two controls; the controlled no-target gap delivered 41+159. All seven original `passed` assertions are true.

`input.log` and `focus.log` preserve an earlier run whose scripts incorrectly set `XDG_CURRENT_DESKTOP=ubuntu:GNOME` even though the system's session was XFCE; all five basic and two switch samples passed, but the contradictory environment limits their interpretation. The rerun scripts `run-xfce.sh` and `focus-xfce.sh` differ from the earlier scripts only by setting `XDG_CURRENT_DESKTOP=XFCE`; `programs.log` independently records the actual system session environment. Neither version changes the packaged source. The manual Fcitx configuration and GTK input context environment remain deliberately set by the test harness.

Targets are two self-created GTK3 input controls; recorder and ASR are substitutes and input is a fixed synthetic transcript, not real speech. Cancellation is injected by SIGUSR1, not the physical Esc key. Focus switch is coordinated by pausing the sender and confirming the second control is focused; results do not establish unsynchronized race behavior. The guest did not have a common real terminal or an offline terminal package (`programs.log`, `terminal-inventory.log`); real terminal, browser, IBus, microphone, cloud ASR, physical shortcuts and arbitrary apps were not tested. This is targeted evidence, not complete package or release acceptance.

To reproduce only in an isolated XFCE X11 guest with matching Fcitx and GTK dependencies, put the exact package in `/tmp/inkecho-r4-test/`, copy scripts to `/tmp/inkecho-r4-test/probes/`, confirm active X11 session, and execute `bash probes/run-xfce.sh <full-sha256> x11` followed by `bash probes/focus-xfce.sh <full-sha256> x11`. These scripts assume UID 1000, DISPLAY=:0, and the user session bus, and temporarily start Fcitx and alter session input-method environment; adapt for the guest and do not run on a real user desktop. Provisioning the test system from scratch was not part of this test. Probe `probe-key` is a disposable synthetic constant, not a real credential.

The archived Python probe files have a `.py.txt` suffix to preserve their exact executed bytes. When copying them to the isolated guest, remove the final `.txt` suffix so the original shell scripts find their expected `.py` filenames. Do not edit the scripts or historical logs.
