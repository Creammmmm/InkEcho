# Ubuntu 26.04 GNOME Wayland: candidate 45a explicit IBus

AppImage 0.10.2 SHA-256 `45a1d170773e4adb3153d4209008b584c8d79e14ac01e4db6cc7e2bfda5dc451` was checked in the guest and extracted without source overlays. The Ubuntu 26.04.1 GNOME 50.1 Wayland session was active and unlocked, IBus engine `xkb:us::eng`, extension `ACTIVE`. The package extension and copied guest extension have matching SHA-256s in `setup.log`; application module and package hashes are in `run.log`. The externally network-isolated QEMU snapshot mounted the original disk and base image read-only; no host desktop or input method, real user text, clipboard, microphone, cloud API or real credentials were used. Extension installation and session changes were restricted to the disposable guest.

The real packaged Session and explicit IBus route used a fake recorder and transcription of 200 fixed Chinese characters, in owned GTK3 controls. `run.log` preserves raw results:

- Full: the first TextView received all 200 characters. IBus recorded 200 Commit calls, then reported `ibus_delivery_unknown` and failed. Actual widget contents prove receipt only for this test; panel return is not a general acknowledgement.
- Cancel: a signal issued at first arrival resulted in a correct two-character prefix, two Commit calls, and cancelled outcome. The second character may already have been sent before cancellation. No further text appeared during the 1.3-second settling period. Physical Esc was not tested.
- No-target: an owned non-text button and its window were confirmed focused and active before the transcription returned; both owned TextViews remained empty. 200 Commit calls resulted in the same unknown-delivery error and no fallback. This establishes only the tested non-text control.
- Switch-ready: the sender was deliberately stopped on first arrival, the second TextView was confirmed active and focused, and sender was resumed. First and second controls received 1 and 199 characters, concatenating to the original 200. The result still reported `ibus_delivery_unknown` and failed. This deliberately coordinated switch does not establish behavior for unsynchronized focus races.

The recorded Begin, Commit and Cancel replies came from the matching destination `:1.17` in this particular session; owner-related daemon replies came from `org.freedesktop.DBus`. No keyboard fallback was recorded. `passed` is an old Fcitx-specific probe assertion and is not valid for interpreting these IBus samples; use the raw contents and events. Instrumented `commit_timeout` entries describe timeouts passed to calls, not proof calls timed out.

To reproduce only in an isolated matching guest, place the exact AppImage, `setup.sh`, `run.sh`, and `probes/sender.py`, `probes/target-focus.py` on a read-only 9p share tagged `inkecho_input`. Evidence scripts are archived with `.txt` suffix: remove that suffix when copying. Run setup, allow the isolated guest to reboot, then run the test. The setup explicitly copies and enables the package extension only in that guest; no package source is overlaid. Guest provisioning is a prerequisite. The test does not cover IBus automatic selection, real microphone, cloud providers, browser/terminal, physical shortcuts, real hardware or complete release/package acceptance.

The temporary extension was disabled and removed in the guest, enabled extensions were empty, guest poweroff completed, Docker wait returned 0, and the container was removed (`shutdown.log`). The disposable SSH key stayed on the host and was not mounted into the guest.
