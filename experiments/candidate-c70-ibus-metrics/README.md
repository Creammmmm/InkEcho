Extracted app source matched the build snapshot except removed pycache. These are targeted synthetic tests, not full package or release acceptance. Sessions are active/unlocked per graphical logs. KVM guest overlays used read-only original disk, base and seed, and had no external network. Test target, audio, transcription and credentials were synthetic.

In each system the normal IBus case received 8 characters and the finished event reported 8 acknowledged attempts while still reporting delivery_unknown because the target does not acknowledge receipt. The no-service helper forced an absent panel and authentic real extension replies caused two immediate consecutive tasks in the same Session; keyboard fallback produced 8 characters per task and each finished with count 8. These counts come from keyboard fallback, not IBus. Simulated cleanup exception after a real local disconnect produced zero characters/count 0 and stopped without fallback.

The partial reply loss probe lets two real commits reach the extension and target, then deliberately raises a timeout after receiving the second response but before product code observes it. The target received 2, while the finished event counted only 1 acknowledged attempt and reported delivery_unknown without fallback/replay. It is a client fault simulation, not wire loss or daemon crash. Counts describe confirmed dispatch attempts, not confirmed target receipt; this test does not establish real microphone/provider behavior, other app targets or every failure mode. Generic Fcitx-oriented `passed` booleans in logs are intentionally irrelevant to these IBus samples; inspect the raw receipt and events.
