# Candidate 18d: IBus fast-close cleanup exception

AppImage SHA-256 `18d387d3c515feccbd5a09e322093fc7504824ffbc254e776de5cb67e074eb3c`, same original package in both desktops; unpacked app sources matched the construction snapshot. It contains IBus cleanup exception handling but predates subsequent input diagnostic fixed-code and Fcitx confirmed-attempt accounting fixes. It is not the final package nor complete package acceptance.

Ubuntu 24 GNOME X11 and Ubuntu 26 GNOME Wayland ran as network-isolated KVM overlays with the original guest disk, base and seed read-only. Active unlocked session, original candidate hash and GNOME extension status are recorded in graphical/setup/run logs. Only disposable guest settings were changed. Synthetic audio, transcription, credentials and GTK target were used. No user data or real provider was used.

The guest-only unauthenticated fault helper in `fault/` forces a null GNOME IBus panel and must never be shipped. On each desktop, authenticated real Shell `no_service` replies on two immediate consecutive tasks in the same Session lead to fast local close (no outgoing Cancel) followed by keyboard fallback; the target received exactly 16 synthetic characters. Normal IBus received 8 but reports delivery_unknown because target receipt cannot be confirmed. An injected lost reply after one real attempt resulted in one character, delivery_unknown and no fallback or replay; this is a simulated client fault, not actual D-Bus packet loss.

For the cleanup exception case, the probe first calls the real local Client.close and then deliberately raises OSError. The actual product error handling recorded `input_cleanup_failed` and `ibus_cleanup_failed`, showed its generic keyboard failure text, and delivered zero characters, with no keyboard fallback or replay. This tests an exception propagated after an actual disconnect, not an error that prevents disconnect or a real daemon crash. Generic Fcitx-oriented probe `passed` is not meaningful for these IBus samples; inspect raw event traces and characters instead. Fast-close timestamps are measurements of local synthetic samples, not overall latency.

Reproduce only in an equivalent disposable guest: restore `.py.txt` probe suffixes, mount the exact candidate and fault helper on an isolated read-only 9p share, and run setup/run with actual graphical session. Test scripts, fault helper and synthetic instrumentation must never be deployed to a user desktop. The two guest extensions were disabled and removed before poweroff. Does not validate real microphone, network provider, other target apps, every cleanup failure or full release acceptance.
