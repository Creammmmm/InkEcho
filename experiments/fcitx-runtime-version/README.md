# Fcitx5 运行时版本查询隔离实验

此目录是实验代码，不构成已支持功能，也不替换发布载荷。`RuntimeVersion`
通过 `Instance::version()` 返回插件实际调用到的 Fcitx Core 版本字符串，
无需读取输入内容。客户端应使用已核验的 D-Bus 唯一 owner 查询和握手，
并在输出前重新确认 owner；未知、超时、切换或不匹配均应在发送前回退。

2026-10-28 在 Ubuntu 26.04 隔离虚拟机，用系统 CMake 和 GCC 15.2.0
编译此目录，在独立 D-Bus session 中运行 `probe.sh`，通过独立 Fcitx5
进程返回 `('5.1.19',)`；磁盘 `fcitx5 --version` 亦为 5.1.19。
`objdump -T | c++filt` 显示插件对 `fcitx::Instance::version()` 是动态
未定义符号，意味着其实现来自运行时链接，而不是插件硬编码的构建版本。
实测 `inkecho.cpp`、`probe.sh`、产物的 SHA-256 分别为
`baaaac559e7ada03f6b8f46bb1902178fc64a31c86aa5842cef11c360f18ccfd`、
`91ec678deac88beee49816a91e6100d0f538ac42d931c5ee3fa46544ea70b188`、
`90783814431263b45c9f353463c852ef25f88c93216a94d81de6818a9afcf189`。
实验进程及来宾临时目录清理，虚拟机正常关机。首次实验因客户端过早
查询而触发 D-Bus 自动启动并失败；修订脚本先检查 service owner，重试通过。

这里验证的是常规动态链接下运行时调用的版本声明，未证明磁盘文件与
内存映射一致、所有 Fcitx 辅助库版本一致或用户目标最终收到文字；也未
测试动态符号劫持、安装更新过程中替换、owner 切换与请求完成之间的竞态。
Ubuntu 24.04、实际用户会话、不同发行版本、最终 AppImage 均未验证。
将此接入产品需重新固定原生源代码和编译产物、检查接口返回与 owner，
并对同一 AppImage 在两系统完成项目要求的实际验收。

## Ubuntu 24 和 owner 切换实验

同日在 Ubuntu 24.04 隔离 VM 用 GCC 13.3.0 编译原型成功，独立 D-Bus
会话中的 Fcitx 返回 `5.1.7`。另一独立会话先启动自有 Fcitx 并以唯一
owner 查询版本，正常终止后启动新进程：owner 从 `:1.1` 变为 `:1.9`，
各自返回 `5.1.7`，向旧唯一 owner 的查询失败；未发送输入文字。
原型、修订后 probe、owner probe、Ubuntu 24 编译产物 SHA-256 分别为
`baaaac559e7ada03f6b8f46bb1902178fc64a31c86aa5842cef11c360f18ccfd`、
`7533b2ce968f10978aee1322c350c91dd35c57ebc0a00e75beaab2f063e546d2`、
`f9729a391a0714147e02d7f6a09bcd326640a9d2db266d30ff919062ade38c37`、
`532ef632385bfe9ae3b76312b74874a7cc562c58435bb07f430e704179ebd139`。
首轮脚本的 `-k` 被 24.04 的 Fcitx 拒绝，改为 `--keep` 后通过；它与
26.04 实测脚本哈希不同。初次启动时客机等待网络，SSH 超时，启动完成
后才执行实验。自有进程和来宾临时目录已清除，QMP 正常关机，容器退出 0。

安全接入必须针对 D-Bus 唯一 owner 查询版本，验证系统和已安装插件配置，
将 owner 固定到握手并在发送前复核；owner 改变或无法确认时，只在任何文字
尚未发送时回退。发送后服务消失或调用超时属投递不明，不得重放。此实验
只覆盖两个顺序启动进程，不覆盖同一查询过程中 owner 改变、发送中进程
退出或软件包升级；也不证明所有相关库的版本一致。上述竞态需要产品集成
测试与独立真实桌面测试，不可据此提前发布。
