# First-focus retry backoff: Ubuntu 26.04 Wayland overlay experiment

The base AppImage SHA-256 was `207b97eb667e5439137b51963a2aa09515c7ba50a83496d9c10070e989252685`, verified in the guest. Exactly one packaged file (`inkecho/platform/fcitx5.py`) was overlaid in the extracted app; the overlaid file SHA-256 was `1e939e2ee7f884aa8c08e5c664815454ca1b7b877db97421f4b85afebb856286`, and exact bytes are `fcitx5.py.txt`. Ubuntu 26.04 GNOME native Wayland was confirmed active by loginctl. Original and backing disks were read-only with a temporary QEMU snapshot; the container had no external network, host credentials were not mounted, and SSH used a dedicated disposable test key on the host. The sender uses packaged Session and a synthetic recorder/transcription, targets are owned GTK controls, and all text is synthetic. The shell, sender, and target scripts exactly match executed bytes (stored with `.txt` suffix); Commit timestamps and statuses are instrumented.

All three assertions in `run.log` passed:

- `recover`: initial Button focus was confirmed, a target TextView was presented after sender startup, and it received the complete 200 characters in order; three no-target statuses preceded recovery, with consecutive request-start intervals 10.7 and 20.8 ms. Keyboard fallback was not invoked.
- `cancel`: initial Button focus was confirmed; after seven no-target responses cancellation was requested, and the task finished cancelled with zero text. No observed Commit started after the cancellation timestamp; no keyboard fallback occurred. Intervals were 10.6, 20.8, 41.1, 42.2, 42.1, and 42.7 ms.
- `fallback`: a TextView using the simple GTK input module received all 200 characters, in order, after Fcitx returned certain zero-prefix no-target (`accepted=0`, `unsent_offset=0`, `uncertain=false`) and hybrid keyboard fallback was invoked. Thirteen no-target requests had consecutive start intervals 12.1, 22.5, 43.9, 43.2, 43.4, 42.8, 43.1, 43.3, 44.4, 42.3, 43.0, and 43.7 ms.

These are single controlled samples. A 40 ms retry cap can add recovery latency; scheduling and service time make measured intervals somewhat longer. They do not prove all target apps, other desktop/session combinations, actual audio/shortcut/cloud paths, or a later build. The artifact was extracted and had a source file overlaid, so this is **not final package acceptance** and cannot qualify a newer hash for release. `run.stderr` is preserved as captured.

To reproduce, copy the same AppImage and scripts (remove `.txt`) into `/tmp/inkecho-r4-test` in an active unlocked, isolated GNOME Wayland guest and execute `bash probes/run.sh 207b97eb667e5439137b51963a2aa09515c7ba50a83496d9c10070e989252685 wayland`. The runner verifies the base hash before extracting and overlays the one file afterward, using an isolated Fcitx configuration which it cleans up. QMP `system_powerdown` was issued, `docker wait` returned 0, and the temporary container was removed.
