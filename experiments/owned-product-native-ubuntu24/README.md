The synthetic target process used default GTK input context (GTK_IM_MODULE unset) and a self-owned native GTK3 text control. Actual application Session used synthetic recorder/transcription:

- Full: actual backend ibus, exact 200 synthetic characters in the GTK control, final status unconfirmed. There were no keyboard-connect/authorization events.
- Cancel: backend ibus, programmatic cancel triggered at first observed arrival; a two-character prefix remained after 1.3s, outcome cancelled. The second character may already have been in flight. This does not test physical Esc or pending-RPC cancellation.
- Non-text button active and focused: backend keyboard, no characters appeared in test text fields; GNOME46 keyboard preflight reported unsupported_compositor and task failed. It is not an IBus outcome. The corresponding broad UI message suggesting Xorg describes keyboard fallback and should not be taken to negate the successful specific IBus sample.
- Product settings CompatibilityPage disable reported installed but not running; gnome-extensions separately reported Enabled No and INACTIVE.
