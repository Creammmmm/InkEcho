# Ubuntu 26.04 Wayland candidate 602: targeted package checks

The candidate AppImage `InkEcho-0.10.2-x86_64.AppImage` SHA-256 `602dab02b4837bb8d30c864dbe50d0413d58d53afb53d9695c7f96f50cdfb756` was verified inside the guest before each run. No packaged source was overlaid. Packaged module hashes are in `fcitx.log` and `ibus-prep.log`. The Fcitx and IBus reply-sender checks trace one entry per distinct method/destination/sender tuple.

Ubuntu 26.04 GNOME native Wayland was confirmed active in a network-isolated KVM container with a temporary QEMU snapshot, original and backing disks mounted read-only, and no host user credentials mounted. Tests used private Fcitx configuration, owned GTK text views, fixed synthetic text, and stub audio/transcription. Only a dedicated disposable VM SSH key was used on the host.

`fcitx.log`: automatic and explicit Fcitx each received exactly 200 characters, and each cancellation sample ended after one character. The old Fcitx assertions passed all four. A simple GTK target triggered definite zero-prefix no-target (`accepted=0`, `unsent_offset=0`, `uncertain=false`), hybrid keyboard fallback, and exactly 200 received characters; old fixture reports `passed=false` because it recognizes only X11 keyboard fallback, not hybrid. D-Bus owner queries' sender was `org.freedesktop.DBus`, while Fcitx RuntimeVersion/Begin/Commit/Cancel destinations and sender matched `:1.86`.

After a guest reboot, the packaged IBus candidate extension was installed, manually enabled, and confirmed ACTIVE (`ibus-extension.log`). `ibus-prep.log` verifies the package and module hashes anew. `ibus.log`: explicit IBus full sample delivered exactly 200 characters to the owned target, then the application reported `ibus_delivery_unknown` and failed with a request to check the cursor; cancellation retained a two-character expected prefix and ended cancelled. The time of the second character relative to the cancellation signal is not established. Owner queries had sender `org.freedesktop.DBus`, while IBus Begin/Commit/Cancel destinations and sender matched `:1.17`. The old fixture reports `passed=false` because it expects Fcitx events; logs are preserved unchanged.

Exact scripts are saved with `.txt` suffix. To reproduce Fcitx, copy `run.sh`, `fcitx-sender.py` as `sender.py`, and `fcitx-target.py` as `target-focus.py` (remove `.txt`) into `/tmp/inkecho-r4-test/probes/` and the exact AppImage into `/tmp/inkecho-r4-test/`; execute `bash probes/run.sh 602dab02b4837bb8d30c864dbe50d0413d58d53afb53d9695c7f96f50cdfb756 wayland`. For IBus, install the package's `platform/ibus_candidate` only in an isolated guest, reboot, explicitly enable and verify ACTIVE, re-extract the exact package, copy the IBus sender/target scripts under the same names, and run the target for `full` and `cancel` with `XDG_RUNTIME_DIR=/run/user/1000`, the guest session bus and actual XAUTHORITY, `DISPLAY=:0`, `WAYLAND_DISPLAY=wayland-0`, `XDG_SESSION_TYPE=wayland`, `XDG_CURRENT_DESKTOP=ubuntu:GNOME`, `GDK_BACKEND=wayland`, `GTK_IM_MODULE=ibus`, and `XMODIFIERS=@im=ibus`.

The IBus test extension was disabled and removed; `cleanup.log` records an empty enabled list and `disable-user-extensions=false`. The guest received QMP system_powerdown, docker wait returned 0, and the temporary container was removed. These single controlled samples do not prove spoofing resistance against all races, other applications, physical shortcut, actual audio or cloud, Ubuntu 24, or complete package acceptance. This artifact remains a candidate.
