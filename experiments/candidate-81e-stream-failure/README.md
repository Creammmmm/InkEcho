# Candidate 81e: failure during streaming polish with real bridges

AppImage SHA-256 `81eefc17f810f1a3fd22b911b8109ba1b6921db8bc8adc9abba371371aaa6527`, the same unmodified candidate used on Ubuntu 24 GNOME X11 and Ubuntu 26 GNOME Wayland. Extracted app sources match the build snapshot except pycache. Both active unlocked sessions ran in network-isolated KVM overlays with original guest disk, base, seed and test share read-only. No host data or real API credentials were used.

In each of the four system/backend combinations the real product Session and IBus or Fcitx bridge used a GTK test target and a synthetic recorder, transcriber, and streaming polish provider. The synthetic stream emits exactly two test characters, then waits for the second real bridge response. The test wrapper allows the actual response to reach the probe but holds it before product code sees it; the synthetic stream then raises ProviderError. Thus the receiver contains both characters but the product has acknowledged only the first. Logs show exactly two Commit starts/replies, then injected failure, polishing_failed, a failed finish with characters 1, and no further Commit or original-text replay. For Fcitx the private actual service and installed packaged addon are used; IBus uses the packaged extension. `passed` in the generic target driver is not an assertion for this synthetic failure case, so raw receipt and event traces control interpretation.

The controlled provider failure and held response are deliberately artificial. This does not test real audio, cloud behavior, a real service crash, genuine response loss, every application, or every stage of a stream. It is not a valid performance benchmark: no real speech, model response or network timings are exercised, and deliberate blocking determines the failure. Counts indicate confirmed dispatch attempts, not verified target receipt. These cases are targeted evidence only and do not constitute full two-system package acceptance or release approval.

A fault extension was copied as part of shared setup but never called in this experiment; it is unauthenticated test-only code and must not ship or be installed on a real desktop. Both extensions were disabled and deleted before normal poweroff. For reproduction only in an equivalent isolated guest restore `.py.txt` suffixes and put the exact candidate and probes on a read-only 9p share; scripts change temporary guest input settings and must not run on a user desktop.
