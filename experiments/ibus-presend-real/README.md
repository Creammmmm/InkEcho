# Experimental IBus pre-dispatch protocol, private D-Bus and isolated GNOME

This is a research prototype, not product code or evidence that automatic IBus routing is safe. It distinguishes a locally resolved missing panel before a call (`no_service` with no previous attempted calls; `partial_no_service` after an attempted prefix) from an already attempted call or lost reply (`unknown`). It does not identify a focused client or prove receipt. The gate rejects invalid credentials, other unique senders, duplicate sequence and post-cancel commits. A client may consider keyboard fallback only on an authenticated `no_service` response, if local prior attempts are also zero and the task remains active; timeout, lost reply, owner change, malformed reply, partial prefix and post-call exception must never be replayed. These tests do not implement or test a production OutputRouter fallback.

## Private bus

`private.log` records real D-Bus traffic between a separate GJS service and Python client on a private `dbus-run-session`, temporary 0700 runtime, and fake dispatch function. Modes `none`, `partial`, and `lost` respectively produced `no_service` with zero dispatch, attempted then `partial_no_service` with one dispatch, and timeout after one dispatch without replay. Wrong token, other unique sender and post-cancel requests were rejected. D-Bus owner sender was pinned in the test; the verifier for GNOME Shell process identity was intentionally not applicable to the private GJS service. GJS printed a Gio.UnixInputStream deprecation warning, preserved in raw log. This private test does not use real IBus or a desktop.

## Real isolated GNOME desktop

Ubuntu 26.04.1 GNOME Wayland ran in a network-isolated QEMU snapshot; original guest/base disks and input share were mounted read-only. A uniquely named test-only Shell extension and isolated test protocol were installed only inside the guest, without replacing, restarting or switching its existing IBus service or engine. The extension's `SetMode` test method is **intentionally unauthenticated** and is unacceptable for production: never install this test extension on a real desktop. `setup.log` verifies script/extension hashes. `retry.log` verifies active unlocked Wayland, extension ACTIVE, xkb engine, and b2d AppImage SHA `b2d47dee9295dadbbbff644e0f9553875ef7ac8971a97c56eec7de68d603c5d2` used solely for Python/dependencies and Capability; no application source was overlaid or exercised as the product route.

A real focused owned GTK3 TextView used GTK IBus. GNOME owner was verified by D-Bus sender, UID, PID and `/usr/bin/gnome-shell`. The panel was actually present in all cases; `none` and the second call in `partial` deliberately simulate missing panel using the unauthenticated test-mode switch. `none`: no_service, dispatch count 0 and no received characters; `real`: attempted, one dispatch and one received character; `partial`: attempted then partial_no_service, one dispatch and one received; `lost`: delayed reply caused timeout while one dispatched character was received, and the client did not replay it. Wrong token, a second sender, and post-cancel submissions were rejected. This directly demonstrates the conservative handling for these controlled samples, not that a real panel disappearance or all failure modes behave identically.

`run.log` retains the first failed desktop attempt: the test client reused one D-Bus sender across tasks and the gate rejected a later Begin, as its one-use sender policy requires. `desktop-client-first.py.txt` is the exact first client; `desktop-client.py.txt` creates a new connection per task and is the exact successful retry, whose recorded hashes differ. Both raw logs are retained. No real user data, microphone, clipboard, cloud provider or actual host session was used. No 24 desktop, non-XKB preedit, physical shortcuts, process crash, real panel disappearance, arbitrary app or package acceptance was tested.

All scripts are archived with `.txt` suffix. For private testing, copy them into `/tmp/ibus-presend-real` without suffix and run `private-run.sh` with a compatible host, GJS and project Python; it starts a separate session bus. For desktop testing, use only a disposable guest: copy `extension.js`, `gate.js`, `capability.js`, `metadata.json`, `actor.py`, `desktop-client.py` and the exact b2d candidate to a read-only 9p share tagged `inkecho_input`, run `setup.sh`, reboot and run `run.sh`. Its temporary mode switch is specifically for controlled fault injection; do not use outside isolated testing.

The guest ran disable and removed the extension files before poweroff; the immediate `enabled-extensions` query still listed the experiment UUID, so disable persistence is not confirmed. This was a disposable snapshot: guest poweroff completed, Docker wait returned 0, and the container was removed (`shutdown.log`), leaving the read-only original guest image unchanged.
