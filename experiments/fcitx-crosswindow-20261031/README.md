# Fcitx 批量输出跨窗口候选验证（2026-10-31）

隔离 Ubuntu 24.04 GNOME Xorg 客机，无外网，使用独立临时磁盘写层。运行环境是旧版 0.10.0 AppImage（SHA-256 `ca322f19c6306546698621f4d2301a6a6b03eeb06c6c6be6e9f3d1506f6a5234`），应用源码及原生插件与 [前次候选测试](../fcitx-session-batch-20261031/README.md) 相同，来自 1f3a2c0 的冻结源码。这是源码覆盖测试，不是新版本 AppImage 验收；音频、ASR 和润色均使用合成数据。

自建页面分别位于两扇 Chrome 窗口（不同 X11 窗口与 Chrome target）中。通过 X11 窗口管理器切换窗口，记录浏览器焦点并在首次发送前读取 Fcitx 原生上下文；Chrome 为隔离测试以 `--no-sandbox` 运行，仅加载自建页面。自动和手选 Fcitx 各执行一轮 200 字流式任务：两个窗口分别准确接收前 42 字和后 158 字，拼接与原文完全一致，整个测试分别耗时 3.667 秒和 3.669 秒（含 1.3 秒事后观察）。自动和手选 Fcitx 各执行一轮首字后程序取消：首窗口各收到 1 字，切换后第二窗口收到 0 字，观察期内没有额外输入。逐项结果及实际批次长度见 `ubuntu24/results.json`。

首次启动失败因只读挂载的 Chrome setuid 沙箱助手权限不满足；第二、三轮仅靠 Chrome DevTools `bringToFront` 激活时，网页报告焦点但 Fcitx 所有上下文为无焦点，自动路由退回键盘并报 `cleanup_pending`，没有发送任何文字。以上均为夹具环境或焦点准备不足，不能计为成功，也不足以认定产品缺陷。第四轮通过窗口管理器激活并观测原生焦点后才进入有效测试。测试结束已恢复输入法配置和环境，卸载测试插件并正常关闭客机。

该记录只证明所列受控场景，不能证明其他应用、Unicode 样本或任意切换时机的行为，也不能证明物理 Esc、真实录音或云识别链路。Fcitx 接口应答并不证明所有目标应用均已处理文字。Ubuntu 26.04 的结果和限制见下方。

26.04 原生 Wayland 隔离客机也尝试了双窗口测试，测试浏览器和 Fcitx 均已启动，但通过 QMP 发送 Alt+`、Alt+Tab、Alt+F6 后未确认第一窗口获得焦点，夹具在发送文字前中止。单用 DevTools 激活时两个页面同时报告有焦点，因此不能作为独立窗口的真实焦点证据。没有产品文字提交，不能判断输出是否正确，也不能以此推断产品故障。保存的 `ubuntu26` 夹具为尚未完成校准的实验，不能计为通过。客机结束前已恢复输入法配置、删除测试插件并正常关机。

在全新临时写层重试后，26.04 原生 Wayland 使用独立 GNOME 测试扩展按限定标题激活窗口，并用 Mutter 的 `focus_window` 分别确认切换前后实际焦点；扩展只实现焦点查询和指定标题激活，不实现输入。自动和手选 Fcitx 的 200 字流式任务分别准确接收前 46 字和后 154 字，拼接与原文完全相同，测试耗时分别为 3.573 秒和 3.590 秒（包含 1.3 秒事后观察）。两次首字后程序取消均只在第一窗口收到 1 字，切换后第二窗口无输入。每次发送前 Fcitx 报告活动焦点；`ubuntu26/results.json` 保存逐项记录。测试后已禁用并删除探针、还原输入法配置、正常关闭客机。此前失败的快捷键切换夹具保留作为诊断材料，其失败不计为产品结果。

## 可复核的发送与清理证据

两系统目录下的 `raw-results-redacted.json` 保留了当次逐次调用、批次长度、桥接类型、协议号、时间、取消结果及页面接收事件；仅将临时输入上下文 ID 替换为 `[REDACTED]`。`session_product.py`、`runner.py` 与 `session-browser.py` 是当次使用的测试代码，`session-exit.json` 是测试进程回执。最终 `result.route` 为 `null`，因此它本身不能证明使用了哪条路径；发送期间的 `dispatches` 显示 `route_before` / `route_after` 为 `fcitx`、`backend_type` 为 `Fcitx5Bridge`、协议为 4。它们是夹具从实际路由对象收集的记录，不能代替对目标应用接收的确认；接收结果由自建页面事件单独提供。

`qemu-exit.json` 是运行虚拟机的包装进程退出记录，其返回值均为 0，并记录只读快照摘要。当时的工具输出报告两台客机的输入法退出命令成功、配置恢复、插件文件及测试自启动和环境文件不存在；26 的探针禁用及删除命令也已执行，但这些清理操作没有另存独立的原始回执。因此，仓库中的材料本身不能独立证明清理结果，上述清理状态仅是当时工具输出中的观察。`cleanup-login.py` 保留用于说明检查了哪些项目；它并非已保存的执行结果。
