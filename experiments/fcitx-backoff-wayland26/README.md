# Ubuntu 26 原生 Wayland：Fcitx 退避与恢复

在 Ubuntu 26.04.1 GNOME Wayland 隔离客机，使用只读源盘和 QEMU `-snapshot`、无外网容器、临时私有 Fcitx 服务、自建 GTK3 控件与固定合成转写。候选 AppImage SHA-256 `f6ceb6311069f85b180bafd446f546247b5e592735ba26035455a571c5eb5164`，解包后 **仅覆盖** `fcitx5.py`（SHA-256 `507c15ece743535a3a9d9442665010b43ed721550ee2a7b37b27fb8fdf165f25`）；这不是最终构建包验收。原始 `wayland.log` SHA-256 `df1678ccbcc7b8a57819c1c277236885301817c6c2cce29fbca621bae76c52c4`，同目录 `.txt` 为实际运行脚本字节。

`gap` 样本中首字到达后切至无文本控件，约 1.2 秒后转至第二文本控件；第一窗口收到 120 字，第二窗口收到 80 字，拼接精确匹配固定 200 字，最终 succeeded。期间 15 次明确未发送的状态 3，连续间隔约 11、21、41、81 ms，随后约 103–107 ms；证明此受控样本中请求频率退避且焦点恢复时没有重复。

`gap-cancel` 样本同样切至无文本控件并等待约 1.2 秒后取消：第一窗口保留 34 字，第二窗口为空，第一窗口文本是原文前缀，最终 cancelled；记录中的取消时刻之后未观察到 Commit 返回。不能由回复时间独立证明每次请求的启动时间；结果和取消顺序由 Session、收到的文本及记录共同限定。日志中的 `passed` 是自建探针断言，仅覆盖其预设条件，不证明任意应用或所有焦点切换安全。

实验结束后以客机 `poweroff` 正常关闭并删除临时容器，退出码 0，OOMKilled false；原镜像只读。覆盖文件和旧候选包未提供正式包、双系统或 Chrome 首次切焦失败的根因证明；本轮未访问用户真实输入、麦克风或云端。
