# IBus unconfirmed terminal outcome: source-level Wayland desktop validation

This is a source-level experiment, not validation of a final AppImage. Frozen current `src/inkecho` (source archive SHA-256 `e874ac5bf3658a5c1b0d8db4f19901c2739c0a466090d2850432b599122ded5a`) was overlaid on an older 0.10.2 AppImage SHA-256 `42118031876729529974e6c20d746638d5d09611f4bb34b4ae189fb4717ada7b` solely to provide its runtime. The actual package was therefore modified for this test and is not a release candidate. Both guest-run logs show `app.py`, `core.py`, and `platform/output_router.py` hashes matching `source-hashes.log`; this establishes the tested terminal code for these samples, not a whole-package integrity gate.

Ubuntu 26.04.1 GNOME Wayland ran in an isolated, network-disabled QEMU `-snapshot` container, with the original disk, base image, and input share mounted read-only. A separate temporary output share captured synthetic test logs. No SSH access, key mount, key transfer, user credentials, user text, clipboard, real microphone or cloud service was used. QMP controlled only the isolated guest's GNOME run dialog; the setup script installed the extension from the frozen source into the disposable guest, rebooted, and the test verified its `ACTIVE` state. The guest reported an active, unlocked Wayland session and `xkb:us::eng`. The container exited 0 and was removed.

The real GNOME IBus panel and owned GTK3 controls were exercised through the application `Session` with a stub recorder and synthetic transcription. The test did not show the actual application window or inspect rendered UI; it recorded Session state/status/diagnostic/finished signals and actual owned-widget content. `run.log` contains the following results:

- `full`: the TextView received all 200 fixed synthetic characters; states included `injecting`, `unconfirmed`, and `idle`, with `ibus_delivery_unknown` and finished outcome `unconfirmed`.
- `cancel`: the first received character triggered a programmatic cancellation signal; the TextView contained the correct two-character prefix, and the task reported `cancelled` then `idle`. The second may have been in flight before cancellation. No physical Esc key was tested.
- `fault`: the instrumented sender raises a synthetic timeout **before** forwarding the second IBus Commit. The first character was received, the second was not sent in this probe, and the task reported `failed` with `ibus_delivery_unknown`, then `idle`; no fallback or replay occurred. This does not simulate a timeout after a real in-flight submission.
- `no-target`: the non-text button window and button were confirmed active and focused; both owned TextViews stayed empty. The task reported `unconfirmed` and the explicit status saying receipt could not be confirmed and no retry occurred. This is one controlled non-text target, not proof of every IBus context.

The test target retains an older Fcitx-only `passed` assertion, so IBus results must be assessed from actual contents and event fields rather than that flag. This does not test native application UI rendering, live audio/ASR/polishing, physical hotkeys, other applications, Ubuntu 24, or dual-system package acceptance. Timings and target receipts are not presentation acknowledgements.

The exact test and QMP scripts are saved with `.txt` suffixes. Reproduction requires an independently frozen source tree, the stated old runtime package, a disposable Ubuntu 26.04 GNOME Wayland guest, a read-only 9p input share tagged `inkinput`, and a writable temporary output share tagged `inkoutput`. Rename scripts without `.txt`, arrange files as indicated by `setup.sh`, then use the guest's desktop to mount the input and run setup; after reboot repeat the mount and run `run.sh`. The QMP helper used only that isolated guest. Do not use a personal desktop or credentials for this experiment.
