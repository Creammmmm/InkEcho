# Independent IBus context coexistence: Ubuntu 24.04

On Ubuntu 24.04.5 with IBus `1.5.29-rc2`, a private session bus, IBus daemon, temporary home and private panel were created in an externally network-isolated KVM guest. Original and backing disks were mounted read-only using a temporary QEMU snapshot. No host credentials, existing user engine, clipboard or user text were accessed. Two synthetic input-context proxies received fixed synthetic commits; handlers counted only receiver identity rather than logging text.

`run.log` shows that creating the second context without focusing it left the first synthetic target current; a private panel commit reached the target. Calling `FocusIn` on the second context changed current focus, and the next panel commit reached the bridge context itself. Both assertions passed; exact scripts and stdout/stderr are retained. The private session bus activated its own IBus portal as shown in stderr. Guest QMP system_powerdown completed, docker wait returned 0 and the temporary container was removed.

These signal observations confirm the prior 26.04 private-bus result for this 24.04 version, but are not actual GUI widget insertion or delivery acknowledgements. An independent context cannot be assumed to transparently submit to the prior target simply by taking focus; remaining unfocused also does not grant it authority to submit as that target. Installing a competing primary panel would affect the existing panel, contrary to project constraints. Existing panel signals can target virtual contexts and have unresolved asynchronous focus/receipt races, so the experiment does not justify automatically selecting IBus or replaying ambiguous commits.

To reproduce in a disposable environment copy `run.sh.txt` and `probe.py.txt` without `.txt` suffixes into one directory, then execute `bash run.sh`; the script constructs and cleans its own private bus and directories. This is not an AppImage or desktop acceptance test and does not prove all future IBus APIs impossible.
