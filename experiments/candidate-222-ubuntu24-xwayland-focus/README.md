# Ubuntu 24 Wayland: bounded XWayland focus observation

Original candidate SHA `222c017a4f9e10bf4d6422cf402a2b7ea57245adb267a4409cce87ca74551694`, unchanged. A network-isolated KVM overlay backed by read-only original disk/base/seed ran Ubuntu 24 GNOME Wayland. The actual session was active/unlocked; only disposable guest settings were changed. Product source was not edited; no text was sent or user content read. The observer uses the candidate package's `_XDriver.focus()` and reads only synthetic owned-window X IDs. A guest-only GNOME Shell extension provides activation and bounded title observation for windows with the fixed test prefix; its unrelated Test method is not invoked. This extension is unauthenticated test code and must never ship or be installed on a user desktop.

Two repeats alternately activated owned GTK3 XWayland simple and native Wayland windows. GNOME Shell reported the intended owned active title each time. With the XWayland window active, `_XDriver.focus()` returned `ok` and the corresponding X11 input focus. With native Wayland active, `_NET_ACTIVE_WINDOW` was 0 and `_XDriver.focus()` returned unsupported_target, despite the raw X focus retaining a different X window. Exact values and source hashes are in `guest/run.log`. This is two sequential settled-window samples, not proof against asynchronous focus races, no-target conditions, nested X input focus, arbitrary applications, XWayland client acceptance or actual output. It is not package/release acceptance.

Existing hybrid output currently authorizes native Wayland before selecting XWayland. A possible direction is avoiding the native capability requirement only after safely establishing a current XWayland target, and failing on transition to unsupported native output. These observations alone are insufficient to implement that change without risk of sending to a stale X window or replay; no product change or compatibility claim was made. The helper extension was disabled/deleted and guest normal poweroff requested. Restore `.py.txt` scripts only in equivalent disposable guests; never execute the fixture on a user desktop.
