# Candidate 0eb0: Ubuntu 24/26 isolated Fcitx checks

The 0.10.2 candidate `InkEcho-0.10.2-x86_64.AppImage` SHA-256 is `0eb0c745fb66fc045c1c32efd268fff27fb95e1dfaf6e08493058af9d9351152`. `snapshot-time.txt` records the UTC snapshot time. The image was built independently in `/tmp`; no stable package was overwritten. `build.log` records the build. `extract.log` was empty when selective extraction returned success. Empty `package.diff` compares the actual extracted `packages/inkecho` with the source snapshot, excluding bytecode; empty `worktree.diff` compares that snapshot to working-tree `src/inkecho` immediately after the build. These checks do not establish bundled dependency or asset integrity and do not cover later source changes.

Two independent, externally network-isolated KVM/QEMU `-snapshot` guests mounted state, base and seed read-only. Only disposable guest configuration and synthetic data were used; no real API keys, audio, clipboard, personal text, user desktop or input method were accessed. The 24 guest changed GDM and account settings only in its temporary overlay to switch from X11 to Wayland; both containers were stopped and removed. SSH test private keys remained on the host and were not mounted in the guests or included here.

Ubuntu 24 log includes active unlocked session and system/Fcitx 5.1.7, and the Wayland log separately confirms session type after the switch. Ubuntu 26 inventory was read before execution: Type=wayland, Active=yes, LockedHint=no, Fcitx 5.1.19, GNOME Shell 50.1. The probe confirms exact package SHA before extracting and invokes the unmodified package code; packaged app and router hashes are in each log. The status check after installation reports a verified staged bridge, and repeated install reports identical inode/mtime. Test receiver is a GTK fixture and audio/transcription are synthetic.

On Ubuntu 26 the old probe labels its successful native keyboard fallback `passed=false` because it only recognizes the X11 keyboard path; the raw event list shows Fcitx `no_target` with accepted=0, hybrid connection and authorization, then `finished=succeeded`, and the target reports 200 received characters. Keep that raw false flag; it is not a passed probe assertion. Ubuntu 24 Wayland fallback is an observed real failure: Fcitx no-target with zero prefix followed by `unsupported_compositor`, zero characters and `failed`.

The cancellations are initiated by the synthetic test signal after a first receipt, not physical Escape; an already queued event may still arrive. These observations do not establish actual microphone, shortcut, overlay, provider/cloud, browser/terminal behavior, all focus races, IBus, all characters, or full dual-system AppImage acceptance. The candidate remains unreleased. Serial logs include the Ubuntu 24 networkd wait; the 26 stop was container stop after the probe, not a documented guest poweroff.

Reproduce only in equivalent disposable, active and unlocked test guests. Copy this exact candidate and `probes/run.sh` to `/tmp/inkecho-r4-test/` and its `probes/` folder. Copy `probes/sender.py.txt` and `probes/target-focus.py.txt` into that folder as `sender.py` and `target-focus.py` respectively; do not change their contents. Then run `bash probes/run.sh <full candidate SHA> x11` or `wayland` with the matching real guest session. The harness starts a private Fcitx and temporarily changes the disposable guest session's input environment; never run it on the user's desktop. `run.sh` restores environment and cleans its private test directory. It does not verify complete UI or package acceptance.
