# Candidate 81e: Ubuntu 26 Chrome offline sample

Unmodified AppImage SHA `81eefc17f810f1a3fd22b911b8109ba1b6921db8bc8adc9abba371371aaa6527` on an active unlocked GNOME Wayland disposable KVM overlay. Original disk, base, seed, app share and host-installed Chrome program directory were mounted read-only, with no external network; no browser profile, host data, API key or user webpage was accessed. A temporary empty Chrome profile and synthetic localhost page were used. Chrome's program version and package source hashes are in `guest/fcitx.log`. The test Chrome uses XWayland with GTK3 and `--no-sandbox` solely inside the isolated guest; this is not validation of native Wayland or a normal secured browser install.

The page reports value via localhost HTTP events; there was no independent final DOM read, so this is only the observed sample. The test probe deliberately delays Fcitx replies 25 ms and cannot measure real performance. No browser cancellation, focus switch, actual speech or cloud provider was tested.

Explicit IBus test failed in its browser fixture before the sender began: `initial_focus_missing`; there is no IBus input result and it must not be treated as product failure or success. The setup/run output and failure are retained. Both tests used the same candidate; isolated app data was deleted on guest poweroff. Test scripts and raw `.py.txt` probes are for equivalent disposable guests only. The host Chrome program directory must be provided read-only as a separate guest 9p mount; never mount a real user profile or run these scripts on a user desktop. This does not claim full browser compatibility or release acceptance.
